WordPress

Pilns iesācēja ceļvedis: katrai tēmai — skaidrojums, kāpēc tas vajadzīgs, un pilnībā patstāvīgs koda piemērs, ko var iekopēt un uzreiz redzēt strādājam.

Kur likt PHP kodu: ja vien nav norādīts citādi, visi šīs lapas PHP piemēri jāievieto aktīvās tēmas functions.php failā (Izskats → Tēmas redaktors, vai tieši failā serverī) un jāsaglabā — izmaiņas parasti redzamas uzreiz pēc lapas atsvaidzināšanas. Meklē ātru sintakses uzziņu? Skaties WordPress Cheatsheet. Vēlies gatavas, kopējamas integrācijas (valodas, kontaktforma)? Tās dzīvo Integrācijas kategorijā. Kaut kas salūzis? Skaties WordPress kļūdas un problēmu risinājumi.

Tēmu izveide

Lai WordPress atpazītu mapi wp-content/themes/ iekšpusē kā tēmu, obligāti nepieciešami tikai divi faili: style.css (ar galvenes komentāru) un index.php. Bez index.php tēma administrācijā parādās kā "Broken Theme" un to nevar aktivizēt.

1. solis — izveido mapi wp-content/themes/mana-tema/ un tajā šo failu:

css/* style.css */
/*
Theme Name: Mana Tēma
Version: 1.0
*/

body { font-family: sans-serif; }

2. solis — tajā pašā mapē izveido index.php:

php<?php get_header(); ?>

<main>
  <?php if (have_posts()) : while (have_posts()) : the_post(); ?>
    <article>
      <h2><?php the_title(); ?></h2>
      <?php the_content(); ?>
    </article>
  <?php endwhile; endif; ?>
</main>

<?php get_footer(); ?>

3. solis — WordPress admin panelī ej uz Izskats → Tēmas → aktivizē "Mana Tēma". Tas ir viss — tēma jau strādā, kaut arī izskatīsies "kaila", jo trūkst header.php/footer.php.

Ja index.php izmanto get_header()/get_footer(), tad header.php/footer.php failiem jau jāeksistē tajā pašā mapē (kaut tukšiem: <html><body> un attiecīgi </body></html>), citādi radīsies kļūda.

Bērnu tēmas (Child Themes)

Viens no biežākajiem un dārgākajiem iesācēju kļūdām: rediģēt lejupielādētu vai iegādātu tēmu tieši (piem., mainīt style.css vai functions.php failā, kas nāca kopā ar tēmu). Kad tēmas autors izlaidīs atjauninājumu un to uzstādīsi, visas tavas izmaiņas tiks pilnībā pārrakstītas un pazudīs — WordPress vienkārši aizvieto veco tēmas mapi ar jauno.

Bērnu tēma atrisina šo problēmu: tā ir atsevišķa, maza tēma, kas "manto" visu no vecāktēmas (parent theme), bet ļauj droši pārrakstīt tikai to, ko vēlies mainīt. Vecāktēmu var brīvi atjaunināt — bērnu tēma un tavas izmaiņas paliek neskartas.

1. solis — izveido jaunu mapi, piem. wp-content/themes/mana-tema-child/, ar šo style.css:

css/*
Theme Name: Mana Tēma Child
Template: mana-tema
Version: 1.0
*/

Template rindā jānorāda tieši vecāktēmas mapes nosaukums (nevis "Theme Name") — šī ir vienīgā obligātā saite starp abām tēmām.

2. solis — tajā pašā mapē izveido functions.php, kas ielādē gan vecāktēmas, gan bērnu tēmas stilus:

php<?php
add_action('wp_enqueue_scripts', function() {
    // Vispirms ielādē vecāktēmas stilus
    wp_enqueue_style(
        'parent-style',
        get_template_directory_uri() . '/style.css'
    );

    // Tad bērnu tēmas stilus — "vecāks" no parent-style,
    // lai tas ielādētos PĒC un varētu pārrakstīt tā noteikumus
    wp_enqueue_style(
        'child-style',
        get_stylesheet_uri(),
        ['parent-style']
    );
});

3. solis — Izskats → Tēmas → aktivizē "Mana Tēma Child". Vietne izskatīsies tieši tāpat kā ar vecāktēmu, bet tagad droši vari pievienot savu CSS style.css beigās vai pārrakstīt atsevišķus .php failus (piem., footer.php), tos nokopējot no vecāktēmas uz bērnu tēmas mapi un tur rediģējot — WordPress vienmēr vispirms meklē failu bērnu tēmā, un tikai tad vecāktēmā.

Ja plāno izmantot lejupielādētu vai iegādātu tēmu (ne pašrakstītu), vienmēr izveido tai bērnu tēmu uzreiz sākumā, pirms sāc jebko rediģēt — daudz vieglāk to izdarīt no paša sākuma, nekā mēģināt "izvilkt" izmaiņas no galvenās tēmas failiem vēlāk.

wp-config.php

Galvenais konfigurācijas fails, kas atrodas WordPress saknes mapē (blakus wp-admin, wp-content) — satur datubāzes pieejas datus un svarīgākos globālos iestatījumus. Šo failu neveido pats — to automātiski izveido WordPress instalācijas laikā, bet vēlāk to var rediģēt.

php<?php
// --- Datubāze ---
define('DB_NAME', 'mana_datubaze');
define('DB_USER', 'root');
define('DB_PASSWORD', 'secret');
define('DB_HOST', 'localhost');
define('DB_CHARSET', 'utf8mb4');
define('DB_COLLATE', '');

// Tabulu prefikss — maini no noklusējuma "wp_" drošības apsvērumu dēļ
$table_prefix = 'wp_';

// --- Autentifikācijas atslēgas un "sāls" (salts) ---
// Ģenerē unikālas katrai instalācijai: https://api.wordpress.org/secret-key/1.1/salt/
// Maiņa šeit uzreiz atslēdz visus esošos pieteikšanās sesiju "cookies"
define('AUTH_KEY',         'ievieto-unikālu-virkni-šeit');
define('SECURE_AUTH_KEY',  'ievieto-unikālu-virkni-šeit');
// ... un tā tālāk visām 8 atslēgām

// --- Vides tips (WordPress 5.5+) — ietekmē, kā daži spraudņi/tēmas uzvedas ---
define('WP_ENVIRONMENT_TYPE', 'production'); // local | development | staging | production

// --- Atkļūdošana (izstrādes vidē) ---
define('WP_DEBUG', true);          // ieslēdz kļūdu apstrādi kopumā
define('WP_DEBUG_LOG', true);      // raksta kļūdas failā wp-content/debug.log
define('WP_DEBUG_DISPLAY', false); // bet neizvada tās ekrānā apmeklētājiem
define('SCRIPT_DEBUG', true);      // ielādē nesaspiestās (.js/.css) kodola versijas

// --- Drošība (ražošanas vidē) ---
define('DISALLOW_FILE_EDIT', true);   // izslēdz tēmas/spraudņu redaktoru admin panelī
define('DISALLOW_FILE_MODS', true);   // bloķē spraudņu/tēmu instalēšanu un atjaunināšanu no admin paneļa
define('FORCE_SSL_ADMIN', true);      // piespiedu HTTPS admin panelim un pieteikšanās lapai

// --- Veiktspēja ---
define('WP_MEMORY_LIMIT', '256M');  // PHP atmiņas limits, ko WordPress drīkst izmantot
define('WP_POST_REVISIONS', 5);   // ierobežo revīziju skaitu (noklusējumā neierobežots)
define('AUTOSAVE_INTERVAL', 120); // automātiskās saglabāšanas intervāls sekundēs

// --- Automātiskie atjauninājumi ---
define('WP_AUTO_UPDATE_CORE', 'minor'); // true | false | 'minor' (tikai drošības ielāpi)

if ( ! defined( 'ABSPATH' ) ) {
    define( 'ABSPATH', __DIR__ . '/' );
}
require_once ABSPATH . 'wp-settings.php';

WP_ENVIRONMENT_TYPE

Kopš WP 5.5 ļauj kodam/spraudņiem uzvesties atšķirīgi lokālajā, staging un production vidē (wp_get_environment_type()).

Autentifikācijas atslēgas

8 nejaušas virknes, kas šifrē pieteikšanās "cookies" — ģenerē ar WordPress.org rīku, nevis izdomā pašrocīgi.

DISALLOW_FILE_EDIT

Ražošanas vietnē vienmēr izslēdz iebūvēto koda redaktoru — bieži izmantots uzbrukuma vektors, ja admin konts tiek kompromitēts.

Tabulu prefikss

Maiņa no noklusējuma wp_ uz kaut ko unikālu apgrūtina automatizētus SQL injection uzbrukumus, kas pieņem noklusējuma nosaukumu.

Pirms vietnes publicēšanas obligāti iestati WP_DEBUG_DISPLAY uz false (vai vienkārši WP_DEBUG uz false) — kļūdu izvade ražošanas vietnē var atklāt failu ceļus un citu jutīgu informāciju apmeklētājiem. Izmanto WP_DEBUG_LOG, lai kļūdas tik un tā redzētu failā, neparādot tās apmeklētājiem.

Spraudņa pamatstruktūra

Ja funkcionalitātei jāpaliek neatkarīgai no tēmas (nemainās, kad nomaina dizainu — piem., kontaktforma, ziņu abonēšana), to noformē kā spraudni, nevis functions.php. Minimāls spraudnis ir viens PHP fails ar galvenes komentāru — WordPress to atpazīst pēc šī komentāra formāta, nevis pēc faila nosaukuma.

Izveido wp-content/plugins/mans-spraudnis/mans-spraudnis.php:

php<?php
/**
 * Plugin Name: Mans Spraudnis
 * Description: Īss apraksts, ko tas dara
 * Version: 1.0
 * Author: Tavs vārds
 */

// Pasargā failu no tiešas piekļuves ārpus WordPress
defined('ABSPATH') || exit;

// No šejienes tālāk — tieši tāda pati sintakse kā functions.php
add_action('wp_footer', function() {
    echo '<!-- Mans spraudnis strādā -->';
});

Pēc faila saglabāšanas admin panelī Spraudņi → Uzstādītie spraudņi parādīsies "Mans Spraudnis" ar pogu "Aktivizēt".

Template Hierarchy

Kad apmeklētājs atver lapu, WordPress automātiski izvēlas, kuru veidnes failu izmantot, sekojot noteiktai prioritāšu secībai — pirmo atrasto failu tēmas mapē tas arī izmanto. Ja specifiskāka veidne neeksistē, WordPress "krīt atpakaļ" uz vispārīgāku, un galu galā vienmēr uz index.php (vienīgo patiešām obligāto failu).

textSākumlapa:        front-page.php → home.php → index.php
Viens ieraksts:    single-{post-type}.php → single.php → index.php
Statiska lapa:     page-{slug}.php → page.php → index.php
Ierakstu arhīvs:   archive-{post-type}.php → archive.php → index.php
Kategorija:        category-{slug}.php → category.php → archive.php → index.php
Birka:             tag-{slug}.php → tag.php → archive.php → index.php
Meklēšana:         search.php → index.php
Kļūda 404:         404.php → index.php

Piemērs: ja tēmā izveido single-produkts.php, tas automātiski parādīsies visiem "produkts" CPT ierakstiem, nevajag neko papildus reģistrēt — WordPress pats atrod šo failu pēc nosaukuma.

The Loop

WordPress ierakstus lapā izvada ar "The Loop" — standarta ciklu, ko izmanto gandrīz katrā veidnes failā (index.php, archive.php, single.php). have_posts() pārbauda, vai vēl ir ieraksti; the_post() "sagatavo" nākamo ierakstu, lai funkcijas kā the_title() zinātu, par kuru ierakstu runāt.

php<?php if (have_posts()) : ?>

  <?php while (have_posts()) : the_post(); ?>

    <article>
      <h2><a href="<?php the_permalink(); ?>"><?php the_title(); ?></a></h2>
      <p>Ieraksta ID: <?php echo get_the_ID(); ?></p>
      <?php the_content(); ?>
    </article>

  <?php endwhile; ?>

<?php else : ?>
  <p>Ieraksti nav atrasti.</p>
<?php endif; ?>

Šo bloku ievieto jebkurā veidnes failā, kur jāparāda ierakstu saraksts vai saturs — visbiežāk index.php, archive.php vai single.php.

Template Tags

Template tags ir funkcijas, ko izsauc The Loop iekšienē (starp have_posts() un endwhile), lai izvadītu konkrētā ieraksta datus — nosaukumu, saturu, datumu, izcēlattēlu.

the_title()

Izvada ieraksta virsrakstu tieši (echo).

the_content()

Izvada pilnu ieraksta saturu (ar formatējumu).

the_excerpt()

Izvada īsu izvilkumu — noder sarakstu skatiem.

the_permalink()

Izvada pilnu URL uz ierakstu.

the_date()

Izvada publicēšanas datumu.

the_post_thumbnail()

Izvada izcēlattēlu kā <img> tagu.

Katrai the_*() funkcijai ir arī get_the_*() versija (piem. get_the_title()), kas atgriež vērtību, nevis izvada uzreiz — noderīga, ja vērtība jāapstrādā pirms izvades:

php$virsraksts = get_the_title();
echo strtoupper($virsraksts); // virsraksts LIELAJIEM BURTIEM

// Izcēlattēls prasa aktivizēt atbalstu functions.php failā:
add_theme_support('post-thumbnails');

Conditional Tags

Funkcijas, kas atgriež true/false, lai noteiktu, kāda veida lapa pašlaik tiek rādīta — īpaši noderīgas koplietotos failos (header.php, footer.php), kur jāizvada dažāds saturs atkarībā no lapas.

Lapas veids:

textis_front_page()       → vai šī ir sākumlapa
is_home()              → vai šī ir ierakstu plūsmas lapa
is_single()            → vai šis ir viens ieraksts (post vai CPT ar atbalstu)
is_singular()          → tas pats, bet plašāk — ietver arī lapas un pielikumus
is_page()              → vai šī ir statiska lapa
is_page_template()     → vai lapa izmanto konkrētu lapas veidni
is_archive()           → vai šī ir jebkāds arhīvs
is_category() / is_tag() → vai konkrēta kategorija/birka
is_tax()               → vai pielāgotas taksonomijas arhīva lapa
is_author()            → vai autora arhīva lapa
is_date() / is_year() / is_month() / is_day() → vai datuma arhīvs (un cik precīzs)
is_search()            → vai šī ir meklēšanas rezultātu lapa
is_404()               → vai šī ir "nav atrasts" lapa
is_paged()             → vai tā ir 2. vai tālāka arhīva/saraksta lapa
is_attachment()        → vai atsevišķa pielikuma (attēla/faila) lapa

Lietotājs & vide:

textis_user_logged_in()   → vai apmeklētājs ir pieteicies
is_admin()            → vai atrodamies admin panelī (nevis publiskajā daļā)
is_super_admin()      → vai lietotājam ir tīkla superadmina tiesības (multisite)
is_multisite()        → vai instalācija ir WordPress Multisite tīkls
is_main_site()        → vai šī ir Multisite tīkla galvenā vietne
is_ssl()              → vai pašreizējais pieprasījums notiek pa HTTPS
wp_is_mobile()        → rupjš mobilās ierīces "guess" pēc User-Agent (ne 100% precīzs)
is_customize_preview() → vai skats tiek rādīts Customizer priekšskatījumā

Ieraksta stāvoklis (izsauc The Loop iekšpusē, konkrētam ierakstam):

texthas_excerpt()         → vai ierakstam ir manuāli uzrakstīts izvilkums
has_post_thumbnail()  → vai ierakstam ir iestatīts izcēlattēls
comments_open()       → vai komentāri šim ierakstam ir atvērti
pings_open()          → vai pingback/trackback ir atvērti šim ierakstam
phpif (is_front_page()) {
    echo 'Laipni lūdzam sākumlapā!';
} elseif (is_singular('produkts')) {
    echo 'Skaties vienu produktu.';
} elseif (!is_user_logged_in()) {
    echo 'Lūdzu, piesakies, lai redzētu vairāk.';
}

is_single() pēc noklusējuma aptver arī pielāgotos ierakstu tipus (CPT), bet ne lapas — ja nepieciešams pārbaudīt "vai šis ir viens ieraksts, jebkāds tips, ieskaitot lapas", izmanto plašāko is_singular() tā vietā.

WP_Query (pielāgoti vaicājumi)

Kad jāizgūst ieraksti ārpus galvenā The Loop (piem., "Populārākie raksti" bloks sānjoslā), izmanto WP_Query klasi. Pēc pielāgotā cikla vienmēr jāizsauc wp_reset_postdata(), lai atjaunotu globālo $post mainīgo — citādi galvenais Loop tālāk lapā var sākt rādīt nepareizus datus.

php$vaicajums = new WP_Query([
    'post_type'      => 'post',
    'posts_per_page' => 5,
    'orderby'        => 'date',
    'order'          => 'DESC',
]);

if ($vaicajums->have_posts()) :
    while ($vaicajums->have_posts()) : $vaicajums->the_post(); ?>
        <h3><?php the_title(); ?></h3>
    <?php endwhile;
endif;

wp_reset_postdata(); // obligāti pēc pielāgota vaicājuma!

Lai galvenajā arhīva vaicājumā mainītu iestatījumus (piem., cik ierakstu rādīt vienā lapā), labāk izmanto āķi pre_get_posts, nevis jaunu WP_Query:

phpadd_action('pre_get_posts', function($query) {
    if (!is_admin() && $query->is_main_query() && $query->is_category('jaunumi')) {
        $query->set('posts_per_page', 12);
    }
});

Taksonomijas

Taksonomija ir veids, kā grupēt saturu — WordPress jau nāk ar divām iebūvētām: kategorijas (hierarhiskas, ar apakškategorijām) un birkas (plakanas, bez hierarhijas). Savu taksonomiju izveido ar register_taxonomy(), un to var piesaistīt gan parastiem ierakstiem, gan CPT.

phpadd_action('init', function() {
    register_taxonomy('zime', 'post', [
        'label'              => 'Zīmes',
        'hierarchical'       => true,  // true = kā kategorijas, false = kā birkas
        'show_in_rest'       => true,  // vajadzīgs Gutenberg redaktoram
        'show_admin_column'  => true,  // parāda kolonnu ierakstu sarakstā
    ]);
});

Rādīšana veidnē — ierakstam piesaistīto terminu saraksts:

php<?php echo get_the_term_list(get_the_ID(), 'zime', '', ', '); ?>

Custom Post Types (CPT)

Papildus ierakstiem un lapām WordPress ļauj izveidot savus, strukturētus satura tipus — piemēram, "Produkti" vai "Atsauksmes", katru ar savu administrācijas sadaļu. Reģistrē tos ar register_post_type(), izsauktu caur init āķi.

php// functions.php
add_action('init', function() {
    register_post_type('produkts', [
        'labels'       => [
            'name'          => 'Produkti',
            'singular_name' => 'Produkts',
        ],
        'public'       => true,
        'has_archive'  => true,
        'show_in_rest' => true, // vajadzīgs Gutenberg redaktoram
        'menu_icon'    => 'dashicons-cart',
        'supports'     => ['title', 'editor', 'thumbnail'],
    ]);
});

Pēc šī koda pievienošanas un lapas atsvaidzināšanas admin panelī sānizvēlnē parādīsies jauna sadaļa "Produkti" ar savu grozāmo ikonu — tur var pievienot jaunus ierakstus tāpat kā parastus WordPress ierakstus.

Pēc pievienošanas ejot uz jaunā CPT publisko lapu (piem., /produkts/kaut-kas/) var rādīties 404 — jāatjauno pastāvīgās saites: Iestatījumi → Pastāvīgās saites → Saglabāt (nekas nav jāmaina, pats saglabāšanas klikšķis atjauno noteikumus).

Pielāgoti lauki

Bez ACF spraudņa pielāgotus datus jebkuram ierakstam (arī parastam, ne tikai CPT) var pievienot un vēlāk nolasīt tieši ar update_post_meta()/get_post_meta() — noder, kad pietiek ar dažiem papildu laukiem un negribi papildu atkarību.

php// Saglabā vērtību konkrētam ierakstam (piem., admin darbībā vai formā)
update_post_meta($post_id, 'cena', 49.99);

// Nolasa veidnē (single.php vai archive-produkts.php), The Loop iekšpusē
<?php while (have_posts()) : the_post(); ?>

  <h2><?php the_title(); ?></h2>

  <?php
  $cena = get_post_meta(get_the_ID(), 'cena', true);
  if ($cena) {
      echo '<p>Cena: ' . esc_html($cena) . ' €</p>';
  }
  ?>

<?php endwhile; ?>

Trešais parametrs get_post_meta() (true) nozīmē "atgriez vienu vērtību, ne masīvu" — bez tā funkcija vienmēr atgriež masīvu, pat ja lauks ir tikai viens.

Izvēlnes

Izvēlnes izveide notiek divos soļos: pirmkārt, functions.php failā reģistrē vietu izvēlnei (piešķir tai iekšēju nosaukumu), otrkārt, veidnē (parasti header.php) izvada to ar wp_nav_menu(). Pašu izvēlnes saturu (kādas saites tajā ir) pēc tam pārvalda administrācijā, nevis kodā.

php// functions.php — reģistrē izvēlnes vietu
add_action('after_setup_theme', function() {
    register_nav_menus([
        'galvena' => 'Galvenā izvēlne',
    ]);
});
php// header.php — izvada izvēlni šajā vietā
<?php
wp_nav_menu([
    'theme_location' => 'galvena',
    'container'      => 'nav',
]);
?>

Pēc šī koda pievienošanas admin panelī parādīsies jauna sadaļa: Izskats → Izvēlnes, kur var izveidot izvēlni, pievienot tai lapas/saites un piešķirt to pozīcijai "Galvenā izvēlne".

Skriptu/stilu pieslēgšana

CSS un JS failus tēmā nekad nepievieno tieši ar <link>/<script> tagiem veidnē — tā vietā izmanto wp_enqueue_scripts āķi. Tas ļauj WordPress pašam pārvaldīt failu ielādes secību un izvairīties no konfliktiem, ja vēlāk spraudnis mēģina pievienot to pašu bibliotēku.

php// functions.php
add_action('wp_enqueue_scripts', function() {
    // Tēmas galvenais CSS fails (style.css)
    wp_enqueue_style('mana-tema-style', get_stylesheet_uri());

    // Pielāgots JS fails no tēmas /js/ mapes
    wp_enqueue_script(
        'mana-tema-main',
        get_template_directory_uri() . '/js/main.js',
        [],       // atkarības (piem., ['jquery'])
        '1.0',     // versija (kešošanas atjaunošanai)
        true       // ielādēt lapas beigās, ne <head>
    );
});

Lai šis piemērs strādātu, jāizveido reāls fails js/main.js tēmas mapē — pretējā gadījumā pārlūka konsolē redzēsi 404 kļūdu tam vienam failam (pati vietne turpinās strādāt).

Hooks & Filters

Hooks ir WordPress galvenais mehānisms, kā mainīt vai papildināt uzvedību, neaiztiekot kodola failus. Actions ļauj izpildīt savu kodu noteiktā brīdī (piem., lapas ielādes laikā), filters ļauj pārtvert un mainīt vērtību pirms tā tiek izmantota tālāk.

php// Action — pievieno kaut ko pirms </body> tagā (piem., analītikas skriptu)
add_action('wp_footer', function() {
    echo '<!-- Šis teksts parādās katras lapas HTML kodā pirms </body> -->';
});

// Filter — maina ieraksta virsrakstu pirms tas tiek attēlots
add_filter('the_title', function($title) {
    return '★ ' . $title;
});

Pēc šī koda pievienošanas functions.php failā un lapas atsvaidzināšanas — katra ieraksta virsraksts sāksies ar "★ ", un pārlūka izejas kodā (View Source) redzēsi jauno komentāru pirms </body>.

Biežākie āķi, ar kuriem sāksi: init (WordPress ielādēts), wp_enqueue_scripts (CSS/JS), wp_head/wp_footer (lapas sākums/beigas).

Shortcodes

Shortcode ļauj ievietot dinamisku PHP saturu tieši Gutenberg/klasiskā redaktora tekstā, rakstot vienkāršu iekavu tagu, piem. [gads]. Reģistrē ar add_shortcode() — funkcijai jāatgriež (return) rezultāts, nekad nedrīkst to izvadīt ar echo.

php// Vienkāršs shortcode bez parametriem: [gads]
add_shortcode('gads', function() {
    return date('Y');
});

// Shortcode ar parametru (atribūtu): [sveiciens vards="Anna"]
add_shortcode('sveiciens', function($atts) {
    $atts = shortcode_atts(['vards' => 'Viesi'], $atts);
    return 'Sveiki, ' . esc_html($atts['vards']) . '!';
});

shortcode_atts() ir svarīgs, nevis tikai ērtība — tas nodrošina noklusējuma vērtības un pasargā no PHP kļūdas, ja lietotājs shortcode uzraksta bez atribūta.

Widgets & Sidebars

Sidebar (WordPress terminoloģijā) ir jebkura widžetiem paredzēta zona — bieži sānjosla, bet var būt arī kājene. Vispirms reģistrē zonu ar register_sidebar(), tad veidnē izvada to ar dynamic_sidebar() — pēc tam admin lietotājs pats no Izskats → Widžeti var ievilkt tur jebkādus blokus, negrozot kodu.

php// functions.php — reģistrē widžetu zonu
add_action('widgets_init', function() {
    register_sidebar([
        'name'          => 'Galvenā sānjosla',
        'id'            => 'galvena-sanjosla',
        'before_widget' => '<div class="widget">',
        'after_widget'  => '</div>',
    ]);
});
php// sidebar.php — izvada šīs zonas saturu
<?php if (is_active_sidebar('galvena-sanjosla')) : ?>
    <aside><?php dynamic_sidebar('galvena-sanjosla'); ?></aside>
<?php endif; ?>

AJAX pamati

AJAX ļauj lapai apmainīties ar datiem ar serveri bez pilnas pārlādēšanas (piem., "Ielādēt vairāk" poga). WordPress visiem AJAX pieprasījumiem izmanto vienu kopīgu galapunktu — admin-ajax.php. PHP pusē reģistrē divus āķus ar vienādu vārdu: wp_ajax_{action} ielogotiem lietotājiem, wp_ajax_nopriv_{action} — pārējiem.

php// 1) Nododam JS pusei ajax_url un nonce
add_action('wp_enqueue_scripts', function() {
    wp_enqueue_script('mana-tema-main', get_template_directory_uri() . '/js/main.js', [], '1.0', true);
    wp_localize_script('mana-tema-main', 'MyAjax', [
        'ajax_url' => admin_url('admin-ajax.php'),
        'nonce'    => wp_create_nonce('my_ajax_nonce'),
    ]);
});

// 2) Apstrādājam pieprasījumu servera pusē
add_action('wp_ajax_paskaitit',        'mana_tema_paskaitit');
add_action('wp_ajax_nopriv_paskaitit', 'mana_tema_paskaitit');

function mana_tema_paskaitit(): void {
    if (!wp_verify_nonce($_POST['nonce'] ?? '', 'my_ajax_nonce')) {
        wp_send_json_error(['message' => 'Drošības kļūda']);
    }
    $a = (int) ($_POST['a'] ?? 0);
    $b = (int) ($_POST['b'] ?? 0);
    wp_send_json_success(['summa' => $a + $b]);
}
js// js/main.js — pieprasījums no pārlūka puses
fetch(MyAjax.ajax_url, {
  method: 'POST',
  body: new URLSearchParams({ action: 'paskaitit', nonce: MyAjax.nonce, a: 2, b: 3 }),
})
  .then(res => res.json())
  .then(data => console.log(data.data.summa)); // 5

fetch()

Pārlūkā iebūvēta funkcija tīkla pieprasījumu sūtīšanai — WordPress kontekstā ar to nosūta datus uz admin-ajax.php bez lapas pārlādēšanas. Atgriež Promise (solījumu par vēlāku atbildi), tāpēc lieto ar .then().

new URLSearchParams(objekts)

Pārlūka iebūvēta klase, kas parastu JS objektu pārvērš formā, ko servera $_POST spēj nolasīt tieši (tas pats formāts, ko sūta parasta HTML forma). Bez tās fetch() nosūtītu JSON tekstu, ko $_POST nesaprastu.

res.json()

res ir servera atbilde no fetch(). .json() pārvērš to no jēla teksta par lietojamu JS objektu — arī tas atgriež Promise, tāpēc seko vēl viens .then(), lai piekļūtu jau pārveidotajiem datiem.

Gutenberg bloki

Kopš WordPress 5.0 satura redaktors (Gutenberg) sastāv no blokiem — katrs rindkopas, attēla vai pielāgota elementa gabals ir savs bloks. Savu bloku veido divi faili: block.json (bloka metadati) un JS fails, kas nosaka, kā bloks izskatās redaktorā (edit) un ko tas saglabā datubāzē (save).

1. solis — izveido blocks/sveiciens/block.json:

json{
  "apiVersion": 3,
  "name": "mana-tema/sveiciens",
  "title": "Sveiciena bloks",
  "category": "widgets",
  "icon": "smiley",
  "editorScript": "file:./index.js"
}

2. solis — reģistrē bloku PHP pusē (nolasa block.json automātiski):

php// functions.php
add_action('init', function() {
    register_block_type(get_template_directory() . '/blocks/sveiciens');
});

3. solis — blocks/sveiciens/index.js nosaka bloka uzvedību redaktorā:

jsimport { registerBlockType } from '@wordpress/blocks';

registerBlockType('mana-tema/sveiciens', {
  edit: () => 'Sveiciens (redaktora skats)',
  save: () => 'Sveiciens (saglabātais HTML)',
});

import sintakse pārlūkā tieši nestrādā — reāls bloka JS jāsalaiž (build) ar @wordpress/scripts (komanda wp-scripts build), kas import pārvērš parastā, pārlūkam saprotamā JS failā. Tas ir vienīgais piemērs šajā lapā, kam nepieciešams papildu būvēšanas solis.

Tulkošana (i18n)

Ja tēma vai spraudnis paredzēts izplatīšanai (arī citiem lietotājiem, ne tikai vienai vietnei), visi lietotājam redzamie teksti jāietver tulkošanas funkcijās — tas ļauj vēlāk pievienot jebkuru valodu bez koda maiņas.

1. solis — reģistrē "text domain" (unikālu identifikatoru tulkojumiem):

phpadd_action('after_setup_theme', function() {
    load_theme_textdomain('mana-tema', get_template_directory() . '/languages');
});

2. solis — ietver katru redzamo tekstu attiecīgajā funkcijā (otrais parametrs vienmēr ir text domain no 1. soļa):

php// Atgriež tulkoto tekstu (jāizmanto echo/turpmākai apstrādei)
$teksts = __('Sveiki, pasaule!', 'mana-tema');

// Uzreiz izvada tulkoto tekstu (saīsinājums echo __(...))
_e('Sveiki, pasaule!', 'mana-tema');

// Apvieno tulkošanu ar drošu HTML izvadi — visbiežāk lietotā kombinācija veidnēs
echo esc_html__('Sveiki, pasaule!', 'mana-tema');

Pašus tulkojumus glabā .po/.mo failos languages mapē — tos ģenerē un rediģē ar rīkiem kā Poedit, kas nolasa kodā izmantotos __()/_e() izsaukumus un veido no tiem tulkojamo tekstu sarakstu.

Drošība: nonce & escaping

Divi drošības jēdzieni, kas jāzina no paša sākuma. Escaping — izvadot jebkādus datus HTML, izmanto esc_html()/esc_attr(), lai novērstu XSS (kāds ievieto ļaunprātīgu <script> tagu, kas izpildās citu apmeklētāju pārlūkos). Nonce — formas, kas maina datus, aizsargā ar vienreizēju "biļeti", kas apliecina, ka pieprasījums patiešām nāk no tavas lapas.

php// Veidnē — droša izvade
echo esc_html($lietotaja_teksts);

// Formā — pievieno slēptu, unikālu lauku
<form method="post">
    <?php wp_nonce_field('mana_darbiba', 'mans_nonce'); ?>
    <input type="text" name="komentars">
    <button type="submit">Sūtīt</button>
</form>

// Apstrādājot formu — vispirms pārbauda nonce
<?php
if (!wp_verify_nonce($_POST['mans_nonce'] ?? '', 'mana_darbiba')) {
    die('Drošības pārbaude neizdevās');
}
// ... šeit droši apstrādā $_POST['komentars']

Sanitizācija: ievades attīrīšana

Escaping (iepriekš) padara datus drošus izvadei. Sanitizācija ir cits solis — padara lietotāja ievadītos datus drošus saglabāšanai, noņemot vai pārveidojot nevēlamu saturu, pirms tas nonāk datubāzē.

php// Atļauj tikai konkrētus HTML tagus/atribūtus, pārējo izfiltrē — noder,
// kad lietotājam jāļauj neliels formatējums (piem., komentāros)
$atlautie_tagi = [
    'a'      => ['href' => true, 'title' => true],
    'strong' => [],
    'em'     => [],
];
echo wp_kses($lietotaja_html, $atlautie_tagi);

// Citas bieži lietotas sanitizācijas funkcijas pēc datu veida
sanitize_email($_POST['epasts']);
sanitize_key($_POST['id']);            // tikai mazie burti, cipari, "-", "_"
absint($_POST['skaits']);           // piespiedu kārtā pozitīvs vesels skaitlis
sanitize_textarea_field($_POST['zinojums']);

Vienkāršs likums: sanitizē pie ievades (pirms saglabā datubāzē), escapē pie izvades (tieši pirms echo). Dari abus — nepaļaujies, ka viens aizstāj otru.

Lietotāju lomas & tiesības

WordPress lietotājiem piešķir lomu (role), kas satur konkrētu tiesību (capability) kopumu — nekad nepārbaudi tiešo lomu kodā, vienmēr pārbaudi konkrētu tiesību, jo tas paliek pareizs pat tad, ja lomu struktūra vēlāk mainās.

Administrator

Visas tiesības, ieskaitot spraudņu/tēmu pārvaldību.

Editor

Var rediģēt un publicēt visu lietotāju ierakstus.

Author

Var publicēt un pārvaldīt tikai savus ierakstus.

Contributor

Var rakstīt ierakstus, bet nevar tos pats publicēt.

Subscriber

Var tikai rediģēt savu profilu.

phpif (current_user_can('publish_posts')) {
    echo 'Vari publicēt ierakstus.';
}

// Pielāgotas lomas izveide (parasti izsauc vienreiz, aktivizējot spraudni)
add_role('redaktors_lite', 'Redaktors (ierobežots)', [
    'read'         => true,
    'edit_posts'   => true,
    'publish_posts' => false,
]);

$wpdb vaicājumi

Kad WP_Query nesniedz vajadzīgo elastību (piem., savai, pielāgotai datubāzes tabulai), globālais $wpdb objekts ļauj rakstīt SQL tieši. Lietotāja ievadi nekad nesalīmē tieši vaicājuma tekstā — vienmēr izmanto $wpdb->prepare().

phpglobal $wpdb;

// Droši — vērtība tiek automātiski attīrīta
$rezultati = $wpdb->get_results(
    $wpdb->prepare("SELECT * FROM {$wpdb->prefix}atsauksmes WHERE vertejums >= %d", 4)
);

foreach ($rezultati as $rinda) {
    echo esc_html($rinda->teksts);
}

{$wpdb->prefix} automātiski ievieto pareizo tabulu prefiksu (parasti wp_, bet var atšķirties) — nekad nehardkodē wp_ tieši.

Options API

Vienkāršākais un biežāk lietotais veids, kā saglabāt vietnes iestatījumus — WordPress tos glabā wp_options tabulā kā atslēga-vērtība pārus. Ideāli piemērots tēmas/spraudņa iestatījumiem, kur nav vajadzīga sarežģīta datu struktūra.

php// Saglabā vai pārraksta vērtību
update_option('mana_tema_krasa', '#ff0000');

// Nolasa vērtību — otrais parametrs ir noklusējums, ja opcija vēl neeksistē
$krasa = get_option('mana_tema_krasa', '#000000');

// Pievieno tikai tad, ja opcija vēl neeksistē (update_option pārraksta vienmēr)
add_option('mana_tema_versija', '1.0');

// Izdzēš opciju pilnībā
delete_option('mana_tema_versija');

update_option() un add_option() pieņem arī trešo parametru $autoload (true/false). Ar true (noklusējums) opcija tiek ielādēta katrā lapas pieprasījumā — der biežai lietošanai. Retāk vajadzīgām, lielām vērtībām iestati false, lai nepalēninātu katru lapas ielādi.

Transients (kešošana)

Transients ir pagaidu vērtība ar derīguma termiņu — glabājas datubāzē (vai kešošanas sistēmā, ja tāda uzstādīta). Noder, lai izvairītos no smaga darba (ārējs API pieprasījums, sarežģīts vaicājums) atkārtošanas katrā lapas ielādē.

phpfunction iegut_valutas_kursu(): float {
    $saglabats = get_transient('valutas_kurss');
    if ($saglabats !== false) {
        return (float) $saglabats;
    }

    // Šis "smagais" darbs izpildīsies tikai reizi stundā
    $kurss = 1.08; // šeit reāli būtu ārējs API izsaukums
    set_transient('valutas_kurss', $kurss, HOUR_IN_SECONDS);

    return $kurss;
}

Cron uzdevumi

WordPress Cron nav īsts servera cron — tas ieplānoto uzdevumu pārbauda un izpilda tikai tad, kad kāds apmeklē vietni. Vienmēr vispirms pārbaudi ar wp_next_scheduled(), vai uzdevums jau nav ieplānots, citādi katrā aktivizācijā izveidosi dublikātus.

php// Ieplāno uzdevumu, ja tas vēl nav ieplānots
if (!wp_next_scheduled('mana_tema_dienas_uzdevums')) {
    wp_schedule_event(time(), 'daily', 'mana_tema_dienas_uzdevums');
}

// Pieslēdz reālo funkciju šim āķim
add_action('mana_tema_dienas_uzdevums', function() {
    // piem., iztīra vecus pagaidu ierakstus
});

Zemapmeklētai vietnei WP-Cron var kavēties (nav apmeklētāju = nav trigera). Ražošanas vietnēm bieži atspējo iebūvēto sistēmu (define('DISABLE_WP_CRON', true) failā wp-config.php) un aizstāj ar īstu servera cron, kas ik minūti izsauc wp-cron.php.

HTTP API (wp_remote_*)

Kad PHP kodam jāizsauc ārējs API (maksājumu serviss, laika ziņas, cita vietne), WordPress iesaka izmantot iebūvēto HTTP API, nevis tiešu cURL — tas automātiski ievēro servera starpniekservera (proxy) iestatījumus un WordPress filtrus, un vienādi strādā visos hostingos.

php// GET pieprasījums
$atbilde = wp_remote_get('https://api.piemers.lv/dati', [
    'timeout' => 10, // sekundes — noklusējums (5s) bieži par īsu lēnākiem API
]);

// VIENMĒR vispirms pārbauda, vai pats pieprasījums neizdevās (tīkla kļūda u.c.)
if (is_wp_error($atbilde)) {
    error_log($atbilde->get_error_message());
    return;
}

$body = wp_remote_retrieve_body($atbilde);
$dati = json_decode($body, true);

POST pieprasījumam ar datiem un galvenēm:

php$atbilde = wp_remote_post('https://api.piemers.lv/pasutijumi', [
    'headers' => ['Content-Type' => 'application/json'],
    'body'    => json_encode(['summa' => 49.99]),
]);

is_wp_error() pārbauda tikai to, vai pieprasījums tehniski izdevās (sasniedza serveri). Pat veiksmīga savienojuma gadījumā serveris var atbildēt ar kļūdas statusa kodu (404, 500) — to pārbauda atsevišķi ar wp_remote_retrieve_response_code($atbilde).

REST API pamati

WordPress jau nāk ar iebūvētu REST API — bez papildu koda ieraksti pieejami kā JSON adresē /wp-json/wp/v2/posts. Savus, pielāgotus galapunktus izveido ar register_rest_route().

textGET /wp-json/wp/v2/posts        → visi publicētie ieraksti kā JSON
GET /wp-json/wp/v2/posts/5      → viens ieraksts (ID=5)
GET /wp-json/wp/v2/produkts     → CPT ieraksti (ja show_in_rest: true)
phpadd_action('rest_api_init', function() {
    register_rest_route('mana-tema/v1', '/sveiciens', [
        'methods'  => 'GET',
        'callback' => function() {
            return ['teksts' => 'Sveiki no pielāgota REST galapunkta!'];
        },
        'permission_callback' => '__return_true', // publiski pieejams
    ]);
});
// Pieejams: /wp-json/mana-tema/v1/sveiciens
