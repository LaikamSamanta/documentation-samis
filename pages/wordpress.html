Sākums WordPress

WordPress

Pilns iesācēja ceļvedis: katrai tēmai — skaidrojums, kāpēc tas vajadzīgs, un pilnībā patstāvīgs koda piemērs, ko var iekopēt un uzreiz redzēt strādājam.

Kur likt PHP kodu: ja vien nav norādīts citādi, visi šīs lapas PHP piemēri jāievieto aktīvās tēmas functions.php failā (Izskats → Tēmas redaktors, vai tieši failā serverī) un jāsaglabā — izmaiņas parasti redzamas uzreiz pēc lapas atsvaidzināšanas.

Tēmas vs spraudņi

WordPress funkcionalitāti paplašina divos veidos, un iesācējiem tos bieži sajauc: Tēma nosaka vietnes izskatu un izkārtojumu — krāsas, fontus, to, kā izskatās lapa un ieraksts. Spraudnis pievieno jaunu funkcionalitāti (kontaktformu, veikalu, SEO rīkus), kas turpina darboties arī pēc tēmas nomaiņas.

Praktisks jautājums, ko sev uzdot: "Ja rīt nomainīšu vietnes dizainu, vai šai funkcijai jāpazūd?" Ja atbilde ir "nē" (piem., ziņu abonēšana, kalkulators), tā pieder spraudnī, nevis tēmā.

Tēmu izveide

Lai WordPress atpazītu mapi wp-content/themes/ iekšpusē kā tēmu, obligāti nepieciešami tikai divi faili: style.css (ar galvenes komentāru) un index.php. Bez index.php tēma administrācijā parādās kā "Broken Theme" un to nevar aktivizēt.

1. solis — izveido mapi wp-content/themes/mana-tema/ un tajā šo failu:

css/* style.css */
/*
Theme Name: Mana Tēma
Version: 1.0
*/

body { font-family: sans-serif; }

2. solis — tajā pašā mapē izveido index.php:

php<?php get_header(); ?>

<main>
  <?php if (have_posts()) : while (have_posts()) : the_post(); ?>
    <article>
      <h2><?php the_title(); ?></h2>
      <?php the_content(); ?>
    </article>
  <?php endwhile; endif; ?>
</main>

<?php get_footer(); ?>

3. solis — WordPress admin panelī ej uz Izskats → Tēmas → aktivizē "Mana Tēma". Tas ir viss — tēma jau strādā, kaut arī izskatīsies "kaila", jo trūkst header.php/footer.php.

Ja index.php izmanto get_header()/get_footer(), tad header.php/footer.php failiem jau jāeksistē tajā pašā mapē (kaut tukšiem: <html><body> un attiecīgi </body></html>), citādi radīsies kļūda.

Bērnu tēmas (Child Themes)

Viens no biežākajiem un dārgākajiem iesācēju kļūdām: rediģēt lejupielādētu vai iegādātu tēmu tieši (piem., mainīt style.css vai functions.php failā, kas nāca kopā ar tēmu). Kad tēmas autors izlaidīs atjauninājumu un to uzstādīsi, visas tavas izmaiņas tiks pilnībā pārrakstītas un pazudīs — WordPress vienkārši aizvieto veco tēmas mapi ar jauno.

Bērnu tēma atrisina šo problēmu: tā ir atsevišķa, maza tēma, kas "manto" visu no vecāktēmas (parent theme), bet ļauj droši pārrakstīt tikai to, ko vēlies mainīt. Vecāktēmu var brīvi atjaunināt — bērnu tēma un tavas izmaiņas paliek neskartas.

1. solis — izveido jaunu mapi, piem. wp-content/themes/mana-tema-child/, ar šo style.css:

css/*
Theme Name: Mana Tēma Child
Template: mana-tema
Version: 1.0
*/

Template rindā jānorāda tieši vecāktēmas mapes nosaukums (nevis "Theme Name") — šī ir vienīgā obligātā saite starp abām tēmām.

2. solis — tajā pašā mapē izveido functions.php, kas ielādē gan vecāktēmas, gan bērnu tēmas stilus:

php<?php
add_action('wp_enqueue_scripts', function() {
    // Vispirms ielādē vecāktēmas stilus
    wp_enqueue_style(
        'parent-style',
        get_template_directory_uri() . '/style.css'
    );

    // Tad bērnu tēmas stilus — "vecāks" no parent-style,
    // lai tas ielādētos PĒC un varētu pārrakstīt tā noteikumus
    wp_enqueue_style(
        'child-style',
        get_stylesheet_uri(),
        ['parent-style']
    );
});

3. solis — Izskats → Tēmas → aktivizē "Mana Tēma Child". Vietne izskatīsies tieši tāpat kā ar vecāktēmu, bet tagad droši vari pievienot savu CSS style.css beigās vai pārrakstīt atsevišķus .php failus (piem., footer.php), tos nokopējot no vecāktēmas uz bērnu tēmas mapi un tur rediģējot — WordPress vienmēr vispirms meklē failu bērnu tēmā, un tikai tad vecāktēmā.

Ja plāno izmantot lejupielādētu vai iegādātu tēmu (ne pašrakstītu), vienmēr izveido tai bērnu tēmu uzreiz sākumā, pirms sāc jebko rediģēt — daudz vieglāk to izdarīt no paša sākuma, nekā mēģināt "izvilkt" izmaiņas no galvenās tēmas failiem vēlāk.

wp-config.php

Galvenais konfigurācijas fails, kas atrodas WordPress saknes mapē (blakus wp-admin, wp-content) — satur datubāzes pieejas datus un svarīgākos globālos iestatījumus. Šo failu neveido pats — to automātiski izveido WordPress instalācijas laikā, bet vēlāk to var rediģēt.

php<?php
define('DB_NAME', 'mana_datubaze');
define('DB_USER', 'root');
define('DB_PASSWORD', 'secret');
define('DB_HOST', 'localhost');

// Rāda kļūdas ekrānā — noder izstrādes laikā
define('WP_DEBUG', true);

Pirms vietnes publicēšanas obligāti iestati WP_DEBUG uz false — kļūdu izvade ražošanas vietnē var atklāt failu ceļus un citu jutīgu informāciju apmeklētājiem.

The Loop

WordPress ierakstus lapā izvada ar "The Loop" — standarta ciklu, ko izmanto gandrīz katrā veidnes failā (index.php, archive.php, single.php). have_posts() pārbauda, vai vēl ir ieraksti; the_post() "sagatavo" nākamo ierakstu, lai funkcijas kā the_title() zinātu, par kuru ierakstu runāt.

php<?php if (have_posts()) : ?>

  <?php while (have_posts()) : the_post(); ?>

    <article>
      <h2><a href="<?php the_permalink(); ?>"><?php the_title(); ?></a></h2>
      <p>Ieraksta ID: <?php echo get_the_ID(); ?></p>
      <?php the_content(); ?>
    </article>

  <?php endwhile; ?>

<?php else : ?>
  <p>Ieraksti nav atrasti.</p>
<?php endif; ?>

Šo bloku ievieto jebkurā veidnes failā, kur jāparāda ierakstu saraksts vai saturs — visbiežāk index.php, archive.php vai single.php.

Izvēlnes

Izvēlnes izveide notiek divos soļos: pirmkārt, functions.php failā reģistrē vietu izvēlnei (piešķir tai iekšēju nosaukumu), otrkārt, veidnē (parasti header.php) izvada to ar wp_nav_menu(). Pašu izvēlnes saturu (kādas saites tajā ir) pēc tam pārvalda administrācijā, nevis kodā.

php// functions.php — reģistrē izvēlnes vietu
add_action('after_setup_theme', function() {
    register_nav_menus([
        'galvena' => 'Galvenā izvēlne',
    ]);
});
php// header.php — izvada izvēlni šajā vietā
<?php
wp_nav_menu([
    'theme_location' => 'galvena',
    'container'      => 'nav',
]);
?>

Pēc šī koda pievienošanas admin panelī parādīsies jauna sadaļa: Izskats → Izvēlnes, kur var izveidot izvēlni, pievienot tai lapas/saites un piešķirt to pozīcijai "Galvenā izvēlne".

Skriptu/stilu pieslēgšana

CSS un JS failus tēmā nekad nepievieno tieši ar <link>/<script> tagiem veidnē — tā vietā izmanto wp_enqueue_scripts āķi. Tas ļauj WordPress pašam pārvaldīt failu ielādes secību un izvairīties no konfliktiem, ja vēlāk spraudnis mēģina pievienot to pašu bibliotēku.

php// functions.php
add_action('wp_enqueue_scripts', function() {
    // Tēmas galvenais CSS fails (style.css)
    wp_enqueue_style('mana-tema-style', get_stylesheet_uri());

    // Pielāgots JS fails no tēmas /js/ mapes
    wp_enqueue_script(
        'mana-tema-main',
        get_template_directory_uri() . '/js/main.js',
        [],       // atkarības (piem., ['jquery'])
        '1.0',     // versija (kešošanas atjaunošanai)
        true       // ielādēt lapas beigās, ne <head>
    );
});

Lai šis piemērs strādātu, jāizveido reāls fails js/main.js tēmas mapē — pretējā gadījumā pārlūka konsolē redzēsi 404 kļūdu tam vienam failam (pati vietne turpinās strādāt).

Hooks & Filters

Hooks ir WordPress galvenais mehānisms, kā mainīt vai papildināt uzvedību, neaiztiekot kodola failus. Actions ļauj izpildīt savu kodu noteiktā brīdī (piem., lapas ielādes laikā), filters ļauj pārtvert un mainīt vērtību pirms tā tiek izmantota tālāk.

php// Action — pievieno kaut ko pirms </body> tagā (piem., analītikas skriptu)
add_action('wp_footer', function() {
    echo '<!-- Šis teksts parādās katras lapas HTML kodā pirms </body> -->';
});

// Filter — maina ieraksta virsrakstu pirms tas tiek attēlots
add_filter('the_title', function($title) {
    return '★ ' . $title;
});

Pēc šī koda pievienošanas functions.php failā un lapas atsvaidzināšanas — katra ieraksta virsraksts sāksies ar "★ ", un pārlūka izejas kodā (View Source) redzēsi jauno komentāru pirms </body>.

Biežākie āķi, ar kuriem sāksi: init (WordPress ielādēts), wp_enqueue_scripts (CSS/JS), wp_head/wp_footer (lapas sākums/beigas).

Drošība: nonce & escaping

Divi drošības jēdzieni, kas jāzina no paša sākuma. Escaping — izvadot jebkādus datus HTML, izmanto esc_html()/esc_attr(), lai novērstu XSS (kāds ievieto ļaunprātīgu <script> tagu, kas izpildās citu apmeklētāju pārlūkos). Nonce — formas, kas maina datus, aizsargā ar vienreizēju "biļeti", kas apliecina, ka pieprasījums patiešām nāk no tavas lapas.

php// Veidnē — droša izvade
echo esc_html($lietotaja_teksts);

// Formā — pievieno slēptu, unikālu lauku
<form method="post">
    <?php wp_nonce_field('mana_darbiba', 'mans_nonce'); ?>
    <input type="text" name="komentars">
    <button type="submit">Sūtīt</button>
</form>

// Apstrādājot formu — vispirms pārbauda nonce
<?php
if (!wp_verify_nonce($_POST['mans_nonce'] ?? '', 'mana_darbiba')) {
    die('Drošības pārbaude neizdevās');
}
// ... šeit droši apstrādā $_POST['komentars']

Custom Post Types (CPT)

Papildus ierakstiem un lapām WordPress ļauj izveidot savus, strukturētus satura tipus — piemēram, "Produkti" vai "Atsauksmes", katru ar savu administrācijas sadaļu. Reģistrē tos ar register_post_type(), izsauktu caur init āķi.

php// functions.php
add_action('init', function() {
    register_post_type('produkts', [
        'labels'       => [
            'name'          => 'Produkti',
            'singular_name' => 'Produkts',
        ],
        'public'       => true,
        'has_archive'  => true,
        'show_in_rest' => true, // vajadzīgs Gutenberg redaktoram
        'menu_icon'    => 'dashicons-cart',
        'supports'     => ['title', 'editor', 'thumbnail'],
    ]);
});

Pēc šī koda pievienošanas un lapas atsvaidzināšanas admin panelī sānizvēlnē parādīsies jauna sadaļa "Produkti" ar savu grozāmo ikonu — tur var pievienot jaunus ierakstus tāpat kā parastus WordPress ierakstus.

Pēc pievienošanas ejot uz jaunā CPT publisko lapu (piem., /produkts/kaut-kas/) var rādīties 404 — jāatjauno pastāvīgās saites: Iestatījumi → Pastāvīgās saites → Saglabāt (nekas nav jāmaina, pats saglabāšanas klikšķis atjauno noteikumus).

Pielāgoti lauki

Bez ACF spraudņa pielāgotus datus jebkuram ierakstam (arī parastam, ne tikai CPT) var pievienot un vēlāk nolasīt tieši ar update_post_meta()/get_post_meta() — noder, kad pietiek ar dažiem papildu laukiem un negribi papildu atkarību.

php// Saglabā vērtību konkrētam ierakstam (piem., admin darbībā vai formā)
update_post_meta($post_id, 'cena', 49.99);

// Nolasa veidnē (single.php vai archive-produkts.php), The Loop iekšpusē
<?php while (have_posts()) : the_post(); ?>

  <h2><?php the_title(); ?></h2>

  <?php
  $cena = get_post_meta(get_the_ID(), 'cena', true);
  if ($cena) {
      echo '<p>Cena: ' . esc_html($cena) . ' €</p>';
  }
  ?>

<?php endwhile; ?>

Trešais parametrs get_post_meta() (true) nozīmē "atgriez vienu vērtību, ne masīvu" — bez tā funkcija vienmēr atgriež masīvu, pat ja lauks ir tikai viens.

Valodu sistēma (multi-language) — pārskats

Šī ir pilna, patstāvīga daudzvalodu sistēma — tavs paša "mini WPML", bet vienkāršāks, bez maksas un pilnībā tavā kontrolē. To var iekopēt gandrīz jebkurā WordPress projektā un tā uzreiz strādā. Sistēma sastāv no astoņām daļām, kuras zemāk izskaidrotas pa vienai:

1️⃣ Valodu saraksts

JSON fails ar aktīvajām valodām (kods + nosaukums).

2️⃣ Valodas noteikšana

No URL, sīkdatnes vai noklusējuma — automātiski.

3️⃣ Pretty URL

/en/lapa/ vietā neglīta ?lang=en.

4️⃣ Statiskā teksta tulkojumi

Pogas, izvēlnes, virsraksti — visās valodās.

5️⃣ Daudzvalodu lauki

Ieraksta lauki (piem., apakšvirsraksts) katrā valodā atsevišķi.

6️⃣ Admin lapa

Valodu pievienošana/dzēšana bez koda rediģēšanas.

7️⃣ Google Translate

Viena poga aizpilda tulkojumu automātiski.

8️⃣ Pārslēdzējs & SEO

Frontend valodu izvēlne + hreflang tagi.

Visas 8 daļas kopā veido vienu failu — inc/multilingual.php. Katra sadaļa zemāk paskaidro savu gabalu un rāda tā kodu; pēdējā sadaļā ("Kā ielikt citā projektā") ir precīzi soļi, kā tās salikt kopā jaunā WordPress projektā.

1. Pamata fails & valodu saraksts

Valodu saraksts netiek glabāts datubāzē, bet vienkāršā JSON failā wp-content/uploads/ml-lang/languages.json — tas ir ātrāk nekā datubāzes vaicājums un failu var apskatīt/rediģēt tieši, ja kādreiz vajag. Fails ar .htaccess tiek pasargāts, lai neviens to nevarētu atvērt tieši pārlūkā.

php/**
 * inc/multilingual.php
 * Daudzvalodu sistēma — daļa 1: pamata valodu saraksts
 */
defined('ABSPATH') || exit;

// Atgriež mapes ceļu, kur glabājam valodu datus (izveido, ja neeksistē)
function ml_lang_dir(): string {
    $dir = wp_upload_dir()['basedir'] . '/ml-lang';
    if (!file_exists($dir)) {
        wp_mkdir_p($dir);
        file_put_contents($dir . '/.htaccess', 'deny from all');
    }
    return $dir;
}

// Nolasa aktīvo valodu sarakstu — piem. [['code'=>'lv','label'=>'Latviešu'], ...]
function ml_get_languages(): array {
    $file = ml_lang_dir() . '/languages.json';

    if (!file_exists($file)) {
        return [['code' => 'lv', 'label' => 'Latviešu']];
    }

    $data = json_decode(file_get_contents($file), true);
    return (is_array($data) && !empty($data))
        ? $data
        : [['code' => 'lv', 'label' => 'Latviešu']];
}

// Saglabā valodu sarakstu atpakaļ JSON failā
function ml_save_languages(array $langs): bool {
    $file = ml_lang_dir() . '/languages.json';
    $json = wp_json_encode($langs, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
    return (bool) file_put_contents($file, $json);
}

// Pirmā valoda sarakstā vienmēr ir noklusējuma (galvenā) valoda
function ml_default_lang(): string {
    $langs = ml_get_languages();
    return $langs[0]['code'] ?? 'lv';
}

Ja fails vēl neeksistē, sistēma automātiski strādā ar vienu noklusējuma valodu (lv) — tā nekad "nesalūzt" pat pirms pirmās konfigurēšanas.

2. Aktīvās valodas noteikšana

Katrā lapas ielādē sistēmai jāzina, kurā valodā rādīt saturu. Prioritāšu secība: vispirms skatās URL (/en/...), tad sīkdatni (atceras iepriekšējo izvēli), visbeidzot — noklusējumu.

php// Nosaka un atceras aktīvo valodu vienas lapas ielādes ietvaros (static — skaitļo tikai vienreiz)
function ml_detect_lang(): string {
    static $detected = null;
    if ($detected !== null) return $detected;

    $allowed = array_column(ml_get_languages(), 'code');
    $default = ml_default_lang();

    // 1) URL segments, piem. "/en/kontakti/" -> "en"
    $path  = parse_url($_SERVER['REQUEST_URI'] ?? '/', PHP_URL_PATH) ?? '/';
    $parts = explode('/', trim($path, '/'));

    if (!empty($parts[0]) && in_array($parts[0], $allowed, true)) {
        return $detected = $parts[0];
    }

    // 2) Sīkdatne no iepriekšējā apmeklējuma
    $cookie = sanitize_key($_COOKIE['ml_lang'] ?? '');
    if ($cookie && in_array($cookie, $allowed, true)) {
        return $detected = $cookie;
    }

    // 3) Noklusējums
    return $detected = $default;
}

// Īsāks, ērtāks alias — šo sauc visur pārējā kodā un veidnēs
function ml_current_lang(): string {
    return ml_detect_lang();
}

// Katru reizi, kad valoda mainās, atjaunojam sīkdatni uz gadu
add_action('init', function () {
    $lang = ml_detect_lang();
    if (($_COOKIE['ml_lang'] ?? '') !== $lang) {
        setcookie('ml_lang', $lang, time() + YEAR_IN_SECONDS, COOKIEPATH, COOKIE_DOMAIN, is_ssl(), true);
    }
});

3. Pretty URL maršrutēšana

Bez šī soļa vienīgais veids, kā norādīt valodu, būtu neglīts ?lang=en parametrs. add_rewrite_rule() māca WordPress saprast, ka /en/kontakti/ ir tas pats, kas parastā "kontakti" lapa, tikai citā valodā.

php// Reģistrē URL noteikumus katrai valodai: /en/, /en/jebkas/, u.t.t.
add_action('init', function () {
    foreach (ml_get_languages() as $l) {
        $code = preg_quote($l['code'], '#');

        add_rewrite_rule('^' . $code . '/?$', 'index.php?ml_lang=' . $l['code'], 'top');
        add_rewrite_rule('^' . $code . '/(.+?)/?$', 'index.php?ml_lang=' . $l['code'] . '&ml_path=$matches[1]', 'top');
    }
});

// Māca WordPress atpazīt jaunos URL parametrus
add_filter('query_vars', function (array $vars): array {
    $vars[] = 'ml_lang';
    $vars[] = 'ml_path';
    return $vars;
});

// Pārvērš "ml_path" (piem. "kontakti") par īstu WordPress lapu
add_action('parse_request', function (WP $wp): void {
    if (empty($wp->query_vars['ml_lang'] ?? '')) return;

    $path = trim($wp->query_vars['ml_path'] ?? '', '/');
    unset($wp->query_vars['ml_path']);

    // Tukšs ceļš ("/en/") -> sākumlapa
    if ($path === '') {
        $front_id = (int) get_option('page_on_front');
        if ($front_id) $wp->query_vars['page_id'] = $front_id;
        return;
    }

    // Meklē lapu pēc slug, piem. "kontakti"
    $page = get_page_by_path($path);
    if ($page) {
        $wp->query_vars['page_id'] = $page->ID;
        return;
    }

    // Ja nekas neatrodas, ļauj WordPress mēģināt pašam (arī raksti/CPT)
    $wp->query_vars['pagename'] = $path;
});

// Ģenerē saiti uz pašreizējo lapu, bet citā valodā (izmanto pārslēdzējā)
function ml_url(string $target_lang): string {
    $home    = untrailingslashit(home_url());
    $default = ml_default_lang();
    $allowed = array_column(ml_get_languages(), 'code');

    if (!in_array($target_lang, $allowed, true)) return $home . '/';

    $path     = parse_url($_SERVER['REQUEST_URI'] ?? '/', PHP_URL_PATH) ?? '/';
    $relative = '/' . ltrim($path, '/');

    // Noņem esošo valodas prefiksu, ja tāds jau ir ceļā
    foreach ($allowed as $code) {
        $prefix = '/' . $code;
        if ($relative === $prefix || str_starts_with($relative, $prefix . '/')) {
            $relative = substr($relative, strlen($prefix));
            break;
        }
    }
    $relative = '/' . ltrim($relative ?: '/', '/');

    return $target_lang === $default
        ? $home . $relative
        : $home . '/' . $target_lang . $relative;
}

// Katru reizi, kad maini valodas vai atjauno tēmu, jāatsvaidzina URL noteikumi
add_action('after_switch_theme', 'flush_rewrite_rules');

Pēc šī koda pievienošanas dodies uz Iestatījumi → Pastāvīgās saites → Saglabāt — tas piespiedu kārtā atsvaidzina URL noteikumus. Bez šī soļa /en/... adreses rādīs 404.

4. Statiskā teksta tulkojumi

Šis nodrošina tulkojumus fiksētiem tekstiem, kas nav piesaistīti konkrētam ierakstam — pogas, izvēlnes vārdi, virsraksti. Tie tiek glabāti JSON failos, sagrupēti pa "grupām" (piem., menu.json, kontakti.json), lai katra lapa/sadaļa turētu savu nelielo tulkojumu failu.

php// Nolasa/raksta konkrētas grupas tulkojumu failu, piem. "menu" -> ml-lang/menu.json
function ml_dict_file(string $group): string {
    return ml_lang_dir() . '/' . sanitize_file_name($group) . '.json';
}

function ml_dict_read(string $group): array {
    $file = ml_dict_file($group);
    if (!file_exists($file)) return [];
    $data = json_decode(file_get_contents($file), true);
    return is_array($data) ? $data : [];
}

function ml_dict_write(string $group, array $data): bool {
    return (bool) file_put_contents(ml_dict_file($group), wp_json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE));
}

// ŠO IZSAUC VEIDNĒS: ml_t('menu', 'home') -> "Sākums" / "Home" / "Главная"
function ml_t(string $group, string $key, string $lang = ''): string {
    $lang = $lang ?: ml_current_lang();
    $data = ml_dict_read($group);

    return $data[$lang][$key]
        ?? $data[ml_default_lang()][$key]
        ?? '';
}

Lietošana veidnē (piem. header.php):

php<a href="/"><?= esc_html(ml_t('menu', 'home')) ?></a>

Atbilstošais menu.json fails izskatītos šādi (šo faila saturu vēlāk rediģēs caur admin lapu, skat. 6. soli, nevis ar roku):

json{
    "lv": { "home": "Sākums", "contact": "Kontakti" },
    "en": { "home": "Home",   "contact": "Contact" }
}

5. Daudzvalodu pielāgotie lauki

Šī daļa atšķiras no 4. soļa — tā ir domāta laukiem, kas pieder konkrētam ierakstam (piem., raksta apakšvirsraksts), nevis fiksētiem UI tekstiem. Vērtība katrai valodai tiek saglabāta vienā post meta laukā kā JSON masīvs — piem. {"lv": "...", "en": "..."}.

php// ŠO IZSAUC VEIDNĒS: ml_field(get_the_ID(), 'ml_subtitle')
function ml_field(int $post_id, string $field, string $lang = ''): string {
    $raw = get_post_meta($post_id, $field, true);
    if (empty($raw)) return '';

    $data = is_array($raw) ? $raw : json_decode($raw, true);
    if (!is_array($data)) return '';

    $lang = $lang ?: ml_current_lang();

    return $data[$lang]
        ?? $data[ml_default_lang()]
        ?? reset($data)
        ?: '';
}

Un pilns meta box piemērs — pievieno vienu ievades lauku katrai valodai jebkura ieraksta rediģēšanas ekrānā, ar drošu saglabāšanu (nonce pārbaude):

phpadd_action('add_meta_boxes', function () {

});

        <input type="text" style="width:100%"
               id="ml_subtitle_<?= esc_attr($code) ?>"
               name="ml_subtitle[<?= esc_attr($code) ?>]"
               value="<?= esc_attr($val) ?>">
        <?php if ($code !== $default): ?>
            <button type="button" class="button ml-translate-btn"
                data-from="<?= esc_attr($default) ?>" data-to="<?= esc_attr($code) ?>"
                data-source="#ml_subtitle_<?= esc_attr($default) ?>"

add_action('save_post', function (int $post_id) {
    if (!isset($_POST['ml_subtitle_nonce']) || !wp_verify_nonce($_POST['ml_subtitle_nonce'], 'ml_save_subtitle')) return;
    if (!current_user_can('edit_post', $post_id)) return;

    $values = array_map('sanitize_text_field', $_POST['ml_subtitle'] ?? []);

Un rādīšana veidnē (piem. single.php):

php<?php $apaksvirsraksts = ml_field(get_the_ID(), 'ml_subtitle'); ?>

Vēlies daudzvalodu lauku citam CPT vai citam laukam? Nokopē šo pašu meta box piemēru, nomaini 'post' uz savu satura tipu un 'ml_subtitle' uz savu lauka nosaukumu — pārējais paliek identisks.

6. Admin lapa valodām

Lai valodas varētu pievienot/dzēst bez koda rediģēšanas, pievieno vienkāršu admin lapu. Tā parādās WordPress sānizvēlnē un ļauj rediģēt valodu tabulu (kods + nosaukums), kas tieši atbilst 1. solī izveidotajam languages.json.

phpadd_action('admin_menu', function () {
    add_menu_page('Valodas', 'Valodas', 'manage_options', 'ml-languages', 'ml_languages_page', 'dashicons-translation', 80);

function ml_languages_page(): void {

7. Google Translate automātiskā tulkošana

Šī daļa pievieno pogu "🌍 Tulkot", kas automātiski aizpilda tulkojuma lauku, izmantojot Google Translate bezmaksas, neoficiālo galapunktu (to pašu, ko izmanto translate.google.com pārlūkā). Nav vajadzīga API atslēga vai maksas konts.

phpadd_action('admin_footer', function () {
    ?>
    <script>
    (function () {
        // Tulko tekstu no vienas valodas uz otru caur Google Translate
        async function mlTranslate(text, from, to) {
            if (!text.trim()) return text;
            const url = 'https://translate.googleapis.com/translate_a/single'
                + '?client=gtx&sl=' + from + '&tl=' + to + '&dt=t&q=' + encodeURIComponent(text);
            const res  = await fetch(url);
            const json = await res.json();
            // Google atgriež ligzdotu masīvu — saliekam gabalus vienā tekstā
            return json[0].map(part => part[0]).join('');
        }

        document.addEventListener('click', async function (e) {
            const btn = e.target.closest('.ml-translate-btn');
            if (!btn) return;

            const from = btn.dataset.from || 'lv';
            const to   = btn.dataset.to;
            const src  = document.querySelector(btn.dataset.source);
            const dest = document.querySelector(btn.dataset.target);
            if (!src || !dest) return;

            btn.disabled = true;
            const original = btn.textContent;
            btn.textContent = '⏳ Tulko...';

            dest.value = await mlTranslate(src.value, from, to);

            btn.textContent = '✅ Gatavs';
            setTimeout(() => { btn.textContent = original; btn.disabled = false; }, 1500);
        });
    })();
    </script>
    <?php
});

Šī poga jau strādā ar 5. solī izveidoto meta box piemēru (tur tai jau ir pareizie data-* atribūti) — ne pati funkcija, ne pogas HTML nekas papildus nav jāraksta.

Šis ir neoficiāls Google galapunkts (nav Google Cloud Translation API) — tas ir bez maksas un ideāls admin ērtībai, bet nav garantijas, ka Google to nemainīs nākotnē. Lieliem apjomiem vai kritiskiem projektiem ilgtermiņā apsver oficiālo, maksas Google Cloud Translation API.

8. Valodu pārslēdzējs & SEO

Pēdējā daļa — apmeklētājam redzamā valodu izvēlne un hreflang SEO tagi, kas palīdz Google saprast, ka lapas dažādās valodās ir viena un tā pati satura versija, nevis dublēts saturs.

php// ŠO IZSAUC VEIDNĒ (piem. header.php): <?php ml_language_switcher(); ?>
function ml_language_switcher(): void {
    $langs = ml_get_languages();
    if (count($langs) < 2) return; // nav jēgas rādīt pārslēdzēju vienai valodai

    $current = ml_current_lang();
    ?>
    <div class="ml-switcher">
        <?php foreach ($langs as $l): ?>
            <a href="<?= esc_url(ml_url($l['code'])) ?>"
               class="ml-switcher-item <?= $l['code'] === $current ? 'active' : '' ?>">
                <?= esc_html(strtoupper($l['code'])) ?>
            </a>
        <?php endforeach; ?>
    </div>
    <?php
}

// hreflang tagi <head> sadaļā — palīdz SEO, novērš "dublēta satura" problēmu
add_action('wp_head', function () {
    $langs = ml_get_languages();
    if (count($langs) < 2) return;

    foreach ($langs as $l) {
        printf(
            '<link rel="alternate" hreflang="%s" href="%s">' . "\n",
            esc_attr($l['code']),
            esc_url(ml_url($l['code']))
        );
    }
}, 1);

Minimāls CSS pārslēdzējam (pielāgo pēc savas vietnes stila):

css.ml-switcher { display: flex; gap: 8px; }
.ml-switcher-item { opacity: .5; text-decoration: none; font-weight: 600; }
.ml-switcher-item.active { opacity: 1; }

4. WordPress admin: Iestatījumi → Pastāvīgās saites → Saglabāt
   (tas aktivizē /en/, /ru/ u.c. URL noteikumus)
5. Ej uz jauno "🌍 Valodas" izvēlni admin sānjoslā un pievieno valodas
6. header.php failā ielikt: 
7. Veidnēs izmanto ml_t('grupa', 'atslēga') statiskajam tekstam
   un ml_field($post_id, 'lauka_vards') ieraksta laukiem

Sistēma darbojas ar jebkuru valodu skaitu un jebkuriem kodiem (lv, en, ru, de, ...) — nekas kodā nav "hardkodēts" uz konkrētām valodām. Pievienojot jaunu valodu admin lapā, viss (URL, pārslēdzējs, hreflang) sāk strādāt automātiski.

Ja projektā jau ir cita daudzvalodu sistēma vai spraudnis (WPML, Polylang), neinstalē abas vienlaikus — tās konfliktēs (piem., abas mēģinās reģistrēt savus add_rewrite_rule() noteikumus un URL sajuks).
