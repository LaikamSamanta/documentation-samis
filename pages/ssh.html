SSH

Pilns iesācēja ceļvedis: kā pieslēgties serverim un pārvaldīt WordPress vietni caur termināli - ar WP-CLI komandām, failu/datubāzes darbībām un reāliem, darbojošos piemēriem.

Kas ir SSH un kāpēc tas WordPress izstrādātājam

SSH (Secure Shell) ir šifrēts protokols attālinātai pieslēgšanās serverim caur termināli - tā vietā, lai serverim piekļūtu fiziski vai tikai caur FTP failu pārlūku, nosūti komandas pa tīklu, un tās izpildās tieši tur, ar pilnu šifrēšanu starp tavu datoru un serveri. Strādā pāri portam 22.

Lielākajai daļai WordPress darba (tēmas rediģēšana, spraudņu uzstādīšana) FTP/failu pārvaldnieks pietiek. Bet SSH kļūst nepieciešams, tiklīdz:

⚡ Ātrums

WP-CLI komanda izpilda spraudņa atjaunināšanu vai datubāzes migrāciju sekundēs - administrācijas panelī tas var aizņemt minūtes vai pat neizdoties timeout dēļ.

🔍 Kļūdu logi

Kad vietne parāda balto ekrānu (WSOD) bez paskaidrojuma, reālais iemesls parasti redzams tikai servera error logā.

💾 Datubāzes darbi

Domēna maiņa, backup, lielu tabulu tīrīšana - administrācijas panelī bieži pārsniedz servera laika/atmiņas limitus.

🤖 Automatizācija

Skripti, kas dara vairākas darbības pēc kārtas (deploy, backup, cache tīrīšana) bez manuālas klikšķināšanas katru reizi.

Pieslēgšanās serverim

bashssh lietotajvards@servera-ip-vai-domens.lv

# Ja serveris klausās nestandarta portā (ne 22)
ssh -p 2222 lietotajvards@servera-ip-vai-domens.lv

Pieslēgšanās datus (lietotājvārdu, adresi, portu) atrodi sava WordPress hostinga panelī - parasti sadaļā "SSH pieeja" vai "Advanced". Dažiem koplietošanas (shared) hostingiem SSH pieeja jāieslēdz atsevišķi vai jāpieprasa no atbalsta.

Pirmajā reizē pieslēdzoties konkrētam serverim, terminālis parādīs servera "pirkstu nospiedumu" (fingerprint) un jautās, vai uzticies tam - apstiprini tikai tad, ja esi pārliecināts, ka adrese ir pareiza.

Pēc pieslēgšanās parasti nonāc mājas mapē, ne uzreiz WordPress instalācijas vietā. Atrodi to ar find / -name wp-config.php 2>/dev/null (meklē visā serverī, ignorējot "atteikts" kļūdas) vai jautā hostingam, kur tā atrodas - tipiski /var/www/html/, /home/lietotajs/public_html/ vai līdzīgi.

SSH atslēgas

Parole strādā, bet katru reizi jāievada no jauna un ir jutīgāka pret uzminēšanu. Praksē izmanto SSH atslēgu pāri: privātā atslēga paliek tavā datorā, publiskā - serverī.

bash# Izveido jaunu atslēgu pāri
ssh-keygen -t ed25519 -C "tavs@epasts.lv"

# Nokopē publisko atslēgu uz serveri (viena komanda, dara visu automātiski)
ssh-copy-id lietotajvards@servera-ip-vai-domens.lv

Ja regulāri pieslēdzies vairākiem WordPress serveriem, ērtāk izveidot saīsinājumus failā ~/.ssh/config:

text# ~/.ssh/config
Host klienta-vietne
    HostName servera-ip-vai-domens.lv
    User lietotajvards
    IdentityFile ~/.ssh/id_ed25519

Pēc tam pieslēgšanās saīsinās līdz ssh klienta-vietne.

Visbiežākā kļūda - Permission denied (publickey) - nozīmē, ka serveris nesaņēma vai neatpazina tavu publisko atslēgu. Nekad neglabā un nesūti privāto atslēgu (id_ed25519 bez .pub) nekur citur, tikai savā datorā - tā ir līdzvērtīga parolei. (Ja tev vajag SSH atslēgu Git/GitHub autentifikācijai, nevis servera pieejai - tas ir atsevišķs process, skat. Git dokumentācijā.)

Kas ir WP-CLI

WP-CLI (WordPress Command Line Interface) ir oficiāls WordPress komandrindas rīks - praktiski visu, ko dari administrācijas panelī (uzstādi spraudni, atjaunini tēmu, izveido lietotāju), var izdarīt ar vienu komandu, bez pārlūka un bez klikšķināšanas.

bash# Pārbauda, vai WP-CLI jau instalēts serverī (daudzos WP hostingos ir pēc noklusējuma)
wp --info

# Ja nav - instalē (vienreiz, serverim jābūt PHP CLI pieejai)
curl -O https://raw.githubusercontent.com/wp-cli/builds/gh-pages/phar/wp-cli.phar
chmod +x wp-cli.phar
sudo mv wp-cli.phar /usr/local/bin/wp

Visas wp komandas jāpalaiž, atrodoties WordPress instalācijas mapē (kur ir wp-config.php) - WP-CLI pats to atrod, izmantojot pašreizējo termināļa atrašanās vietu. Ja saņem kļūdu "This does not seem to be a WordPress installation", pārbaudi ar pwd, vai esi pareizajā mapē.

Core, spraudņi & tēmas

bash# WordPress kodola atjaunināšana
wp core update
wp core version

# Spraudņi - saraksts, uzstādīšana, aktivizēšana, atjaunināšana
wp plugin list
wp plugin install contact-form-7 --activate
wp plugin update --all
wp plugin deactivate spraudna-nosaukums

# Tēmas - tas pats princips
wp theme list
wp theme activate mana-tema
wp theme update --all

wp plugin update --all vienā komandā atjaunina VISUS spraudņus uzreiz - noderīgi, bet vienmēr vispirms izveido dublējumu (skat. MySQL & dublējumi), jo atjauninājums var salauzt saderību ar tēmu vai citu spraudni.

Datubāze & search-replace

bash# Eksportē visu datubāzi vienā .sql failā
wp db export dublejums.sql

# Importē atpakaļ (piem., pēc atjaunošanas no dublējuma)
wp db import dublejums.sql

Visbiežākais WP-CLI datubāzes uzdevums - domēna maiņa (piem., pārceļot vietni no vecais-domens.lv uz jauns-domens.lv, vai no staging uz production). WordPress saglabā pilnu domēna adresi tieši datubāzē (tabulās, iestatījumos), tāpēc vienkārša failu kopēšana to nemaina:

bash# --dry-run vispirms parāda, CIK reižu vārds tiktu aizvietots, bez reālas maiņas
wp search-replace 'vecais-domens.lv' 'jauns-domens.lv' --dry-run

# Kad pārliecināts - palaid bez --dry-run, lai tiešām aizvieto
wp search-replace 'vecais-domens.lv' 'jauns-domens.lv'

search-replace ir daudz drošāks par manuālu SQL UPDATE vaicājumu, jo WP-CLI automātiski pareizi apstrādā WordPress serializētos datus (piem., masīvus, kas saglabāti kā teksts ar precīzu garuma skaitīšanu) - manuāla teksta aizvietošana šos serializētos laukus salauztu. Vienmēr vispirms izveido dublējumu (wp db export) pirms search-replace bez --dry-run.

Lietotāji, opcijas & cache

bash# Izveido jaunu administratora lietotāju (noder, ja esošais aizmirsis paroli)
wp user create adminis admin@epasts.lv --role=administrator --user_pass=DrosaParole123

# Maina lietotāja paroli
wp user update adminis --user_pass=JaunaDrosaParole456

# Nolasa/maina jebkuru WordPress opciju (piem., vietnes nosaukumu)
wp option get blogname
wp option update blogname "Jauns Vietnes Nosaukums"

# Notīra WordPress objektu kešu (ne vienmēr to pašu, ko hostinga/CDN kešs)
wp cache flush

Tikai administratori - noder drošības auditam, lai pārbaudītu, vai nav parādījies svešs/neatpazīts admin konts:

bashwp user list --role=administrator --fields=ID,user_login,user_email,user_registered

Info par konkrētu lietotāju - visi tā dati un atsevišķie meta lauki:

bashwp user get lietotajvards --fields=all
wp user meta list lietotajvards

wp user create ar administratora lomu ir ātrākais veids atgūt piekļuvi vietnei, ja pazaudēta gan admin parole, gan e-pasta piekļuve atiestatīšanai - tiešā datubāzes/failu piekļuve caur SSH šo situāciju atrisina pāris sekundēs. wp user list --role=administrator der arī otrādi - regulāri pārbaudīt, vai vietnē nav parādījies admin konts, ko tu neizveidoji (bieža pazīme, ka vietne uzlauzta).

Failu pārvaldība & tiesības

bash# Pārvietošanās un satura skatīšana
cd wp-content/themes/mana-tema
ls -la

# Rediģē failu tieši terminālī (nano ir vienkāršākais teksta redaktors)
nano wp-config.php
# Ctrl+O = saglabāt, Ctrl+X = iziet

Failu tiesības (permissions) WordPress serverī parasti jābūt: mapes 755, faili 644, izņemot wp-config.php, kam ieteicams 600 (lasa/raksta tikai īpašnieks):

bash# Visām mapēm rekursīvi - 755
find . -type d -exec chmod 755 {} \;

# Visiem failiem rekursīvi - 644
find . -type f -exec chmod 644 {} \;

# wp-config.php stingrāk - tikai īpašniekam
chmod 600 wp-config.php

Nekad neuzstādi chmod 777 "lai vienkārši strādātu" - tas dod RAKSTĪŠANAS tiesības ikvienam serverī, ieskaitot potenciāli ļaunprātīgus skriptus, ja serveris koplietots. Ja fails/mape nesaglabājas, reālais iemesls parasti ir nepareizs failu īpašnieks (owner), nevis tiesības - pārbaudi ar ls -la un salīdzini ar to, kā PHP process darbojas (bieži www-data).

Faila datumi - kad izveidots, mainīts vai pēdējoreiz atvērts:

bashstat fails.php

stat izvadā trīs laikus - Access (pēdējoreiz nolasīts), Modify (pēdējoreiz mainīts saturs - svarīgākais, meklējot ļaunprātīgi ievietotus failus) un Change (pēdējoreiz mainīti faila metadati, piem., tiesības). Lielākā daļa Linux failsistēmu nesaglabā reālu "izveidošanas" datumu - Modify ir tuvākais praktiskais aizstājējs.

Servera resursi (RAM, CPU, disks)

bash# RAM izmantojums cilvēkam lasāmā formātā (-h = human-readable)
free -h

# Dzīvs, reāllaika procesu saraksts (q = iziet); htop ir skaistāka alternatīva, ja instalēts
top

# TOP 10 procesi pēc RAM patēriņa, bez interaktīva režīma
ps aux --sort=-%mem | head -10

# TOP 10 procesi pēc CPU patēriņa
ps aux --sort=-%cpu | head -10

# Diska vietas izmantojums pa nodalījumiem
df -h

# Kuras mapes pašreizējā vietā aizņem visvairāk vietas, sakārtots dilstoši
du -sh */ | sort -rh | head -10

Ja WordPress vietne kļūst lēna vai serveris "karājas", ps aux --sort=-%mem parasti uzreiz parāda vainīgo - bieži tas ir neierobežots PHP process, aizmirsts backup skripts vai spraudnis ar atmiņas noplūdi. du -sh */ | sort -rh palīdz atrast, kas piepildījis disku (bieži - logi vai veci dublējumi, kas nekad netika izdzēsti).

Tīkla diagnostika (IP, DNS, MX, telnet)

bash# Servera IEKŠĒJĀ/piešķirtā IP adrese
hostname -I

# Servera PUBLISKĀ IP adrese, tā, kā to redz internets (var atšķirties no augšējās)
curl ifconfig.me

# Domēna MX ieraksti (kur nonāk e-pasts) un vispārīgs DNS
dig domena.lv MX
dig domena.lv +short

# Pārbauda, vai konkrēts ports ir atvērts/sasniedzams no servera puses
telnet domena.lv 80
telnet domena.lv 25
# Ctrl+] tad "quit", lai izietu no telnet sesijas

telnet domena.lv 25 ir klasisks veids pārbaudīt, kāpēc WordPress e-pasti (paroles atiestatīšana, kontaktformas) nenonāk galā - ja savienojums uz 25. portu neizdodas, problēma ir servera/hostinga pusē (bloķēts izejošais SMTP), nevis WordPress kodā. Plašāk par DNS/MX ierakstiem - Tīkla dokumentācijā.

Kļūdu logi

Kad WordPress rāda balto ekrānu (White Screen of Death) vai vispārīgu "There has been a critical error" ziņojumu bez paskaidrojuma, reālais iemesls ir servera error logā, ne pašā ekrānā:

bash# WordPress paša debug log (jāieslēdz vispirms wp-config.php)
tail -f wp-content/debug.log

# PHP servera error log (atrašanās vieta atkarīga no hostinga)
tail -f /var/log/php-errors.log
tail -f /var/log/apache2/error.log

Lai ieslēgtu WordPress debug logu, wp-config.php pievieno (pirms rindas /* That's all, stop editing! */):

phpdefine('WP_DEBUG', true);
define('WP_DEBUG_LOG', true);
define('WP_DEBUG_DISPLAY', false); // nerāda kļūdas apmeklētājiem, tikai logā

tail -f (nevis vienkārši cat) turpina rādīt jaunas rindas reāllaikā, kamēr komanda darbojas - atver to, tad izpildi darbību, kas izraisa kļūdu (piem., atsvaidzini lapu), un skaties, kas parādās uzreiz. Beidz ar Ctrl+C. Vienmēr izslēdz WP_DEBUG_DISPLAY produkcijas vietnē - redzamas PHP kļūdas apmeklētājiem var atklāt servera failu ceļus un citu tehnisku info uzbrucējiem.

Sintakses pārbaude (php -l)

Pirms rediģēta faila (piem., functions.php) augšupielādes vai aizvietošanas uz dzīvas vietnes vienmēr der pārbaudīt, vai tajā nav sintakses kļūdu - pat viena trūkstoša iekava vai semikols nozīmē tūlītēju "critical error" / balto ekrānu visai vietnei. php -l ("lint") pārbauda faila sintaksi, nepalaižot to:

bash# Pārbauda vienu konkrētu failu
php -l wp-content/themes/mana-tema/functions.php

Ja viss kārtībā, redzēsi:

bashNo syntax errors detected in wp-content/themes/mana-tema/functions.php

Ja failā ir kļūda, komanda parāda precīzu rindas numuru, kur PHP parsētājs "aizķērās" (bieži tas ir viena rinda pēc tās, kur reālā problēma ir, piem., trūkstoša aizverošā iekava iepriekšējā rindā):

bashPHP Parse error:  syntax error, unexpected token "}", expecting end of file in wp-content/themes/mana-tema/functions.php on line 142
Errors parsing wp-content/themes/mana-tema/functions.php

Lai pārbaudītu visus PHP failus tēmā vai spraudnī uzreiz (un redzētu tikai tos, kuros patiešām ir kļūda, nevis garu sarakstu ar "No syntax errors" katram failam):

bash# find atrod visus .php failus, php -l pārbauda katru; grep -v izfiltrē "tīros" rezultātus
find . -name "*.php" -exec php -l {} \; | grep -v "No syntax errors"

Šis paradums glābj no visbiežāk sastopamā "izsalabotā vietne" scenārija: rediģē functions.php tieši serverī (piem., ar nano), aizmirsti aizvērt iekavu, saglabā - un vietne uzreiz krīt visiem apmeklētājiem. Palaižot php -l pirms saglabāšanas ietekmes (vai kā daļu no deploy skripta), kļūdu noķer pirms tā nonāk dzīvajā vietnē.

php -l noķer tikai sintakses (parsēšanas laika) kļūdas - trūkstošas iekavas, semikolus, neaizvērtas pēdiņas. Tas neatklāj loģikas vai izpildlaika kļūdas (piem., izsaukumu neesošai funkcijai, nepareizu mainīgo), jo kods faktiski netiek palaists. Tādām kļūdām vajag WP_DEBUG un kļūdu logu (skat. augstāk).

MySQL & dublējumi

Alternatīva wp db export/import (skat. augstāk) - tiešs mysqldump, ja WP-CLI nav pieejams vai vajag precīzāku kontroli:

bash# Datubāzes datus (lietotājvārds, parole, nosaukums) atrodi wp-config.php
mysqldump -u db_lietotajs -p db_nosaukums > dublejums.sql

# Atjaunošana no dublējuma
mysql -u db_lietotajs -p db_nosaukums < dublejums.sql

# Ienākšana tieši MySQL komandrindā (interaktīvi vaicājumi)
mysql -u db_lietotajs -p db_nosaukums

Pirms JEBKURAS datubāzes darbības (search-replace, spraudņu masveida atjaunināšana, manuāli SQL vaicājumi) vienmēr vispirms izveido svaigu dublējumu. WordPress datubāzes izmaiņas parasti nav atsaucamas ar "Undo" - dublējums ir vienīgais drošības tīkls.

WP-Cron vs īstais cron

WordPress ieplānotos uzdevumus (publicēšana nākotnē, e-pasta paziņojumi, spraudņu grafiki) pēc noklusējuma pārbauda WP-Cron - bet tas nav īsts, vienmēr strādājošs fona process, tas palaižas tikai tad, kad kāds apmeklētājs atver lapu. Zemas apmeklētības vietnēm ieplānotie uzdevumi var kavēties vai vispār neizpildīties.

Risinājums - izslēdz WordPress "pseido-cron" un aizstāj ar īstu servera cron uzdevumu:

php// wp-config.php
define('DISABLE_WP_CRON', true);
bash# crontab -e atver servera cron sarakstu rediģēšanai; šī rinda palaiž
# WordPress cron pārbaudi ik pēc 5 minūtēm, neatkarīgi no apmeklētājiem
*/5 * * * * wp cron event run --due-now --path=/celjs/uz/wordpress > /dev/null 2>&1

Cron rindas piecas zvaigznītes/skaitļi apzīmē: minūte, stunda, mēneša diena, mēnesis, nedēļas diena. */5 * * * * nozīmē "katras 5 minūtes, vienmēr" - * katrā pozīcijā nozīmē "jebkurš". --due-now nozīmē - WP-CLI palaiž tikai tos uzdevumus, kam pienācis laiks, ne visus uzreiz.

Vīrusu & aizdomīgu failu meklēšana

Core failu integritāte - WordPress salīdzina tavus kodola failus ar oficiālajiem, nemainītajiem failiem un uzreiz parāda, kuri atšķiras:

bashwp core verify-checksums

Nesen mainīti faili - bieži pirmā pazīme, ka vietne uzlauzta, ir faili, kas mainīti brīdī, kad tu pats neko nedarīji:

bash# Visi .php faili, kas mainīti pēdējo 7 dienu laikā
find . -name "*.php" -mtime -7

# Tas pats, bet ar precīzu datumu/laiku katram failam, sakārtots pēc laika
find . -name "*.php" -mtime -7 -printf "%T@ %p\n" | sort -n

Aizdomīgi koda paraugi - ļaunprātīgs WordPress kods bieži izmanto konkrētas, atpazīstamas PHP funkcijas, lai paslēptu/izpildītu injicētu kodu:

bash# Meklē failus ar bieži ļaunprātīgi izmantotiem paraugiem visā wp-content
grep -rl "eval(base64_decode" wp-content/ --include="*.php"
grep -rl "eval(gzinflate" wp-content/ --include="*.php"
grep -rl "eval(\$_POST" wp-content/ --include="*.php"

Šīs komandas norāda uz aizdomām, ne pierāda vīrusu - daži leģitīmi spraudņi arī izmanto eval() vai base64 nešķīstiem mērķiem (piem., licenču pārbaudei). Katru atrasto sakritību pārbaudi manuāli, salīdzinot ar to, kas failā bija PIRMS aizdomīgā perioda (skat. Git vēsturi, ja tēma/spraudnis versionēts). Nopietnākai, automatizētai skenēšanai der specializēts rīks - clamscan (ClamAV) vai hostinga/WordPress drošības spraudnis (Wordfence, Sucuri).

Failu pārsūtīšana (scp/rsync)

bash# scp - vienkārša kopēšana caur SSH, bez papildu FTP servera
scp mana-tema.zip lietotajvards@serveris.lv:/mapes/celjs/
scp -r wp-content/themes/mana-tema/ lietotajvards@serveris.lv:/mapes/celjs/

# rsync - gudrāks: kopē TIKAI mainītos failus, ne visu katru reizi
rsync -avz --progress ./mana-mape/ lietotajvards@serveris.lv:/mapes/celjs/

rsync ir daudz ātrāks lielu projektu regulārai izvietošanai (deploy), jo pārsūta tikai izmaiņas - pirmā reize kopē visu, bet katra nākamā tikai to, kas mainījies kopš pēdējās reizes. -a saglabā tiesības/laika zīmogus, -v parāda progresu, -z saspiež pārsūtīšanas laikā.

Noderīgas komandas

Kopsavilkums - visas komandas, kas parādījās šajā lapā, vienuviet ātrai uzziņai:

bash# Pieslēgšanās

# WP-CLI ikdienas darbi

# Kļūdu logs reāllaikā

# Failu tiesības
find . -type d -exec chmod 755 {} \;
find . -type f -exec chmod 644 {} \;

# Datubāze bez WP-CLI
mysqldump -u lietotajs -p db_nosaukums > dublejums.sql

# Servera resursi

# Tīkla diagnostika

# Drošība
