Sākums WordPress Ātrie risinājumi

Ātrie risinājumi

Populāri, patstāvīgi functions.php trikizi - katru var iekopēt tieši tādu, kāds tas ir, tēmas functions.php failā (vai izceltā failā, ko no turienes ielādē ar require_once). Meklē pilnas dziļās sadaļas? Skaties pilnajā WordPress dokumentācijā.

SVG augšupielāžu atbalsts

WordPress pēc noklusējuma bloķē SVG augšupielādi - SVG faili ir teksta (XML) faili, kas var saturēt JavaScript kodu, tāpēc tie ir potenciāls XSS drošības risks. Šis kods atļauj SVG, bet tikai uzticamiem lietotājiem (administratoriem).

phpadd_filter('upload_mimes', function($mimes) {
    if (current_user_can('manage_options')) {
        $mimes['svg'] = 'image/svg+xml';
    }
    return $mimes;
});

Nekad neatļauj SVG augšupielādi visiem lietotājiem (piem., edit_posts vietā manage_options) - jebkurš, kas var augšupielādēt SVG, teorētiski var ievietot ļaunprātīgu JavaScript kodu. Ražošanas vietnēm, kur SVG jāaugšupielādē arī parastiem redaktoriem, apsver specializētu spraudni (piem., "Safe SVG"), kas SVG failu attīra pirms saglabāšanas.

Noņemt WordPress versijas numuru

WordPress pēc noklusējuma lapas HTML kodā atklāj savu versijas numuru - tas atvieglo uzbrucējiem atrast vietnes, kam vēl nav uzstādīts jaunākais drošības labojums.

phpremove_action('wp_head', 'wp_generator');

Izslēgt XML-RPC

XML-RPC ir vecāks WordPress interfeiss ārējiem savienojumiem (piem., senākām mobilajām lietotnēm) - tas ir arī izplatīts brute-force uzbrukumu mērķis. Ja to nelieto (lielākā daļa vietņu nelieto), droši izslēdz.

phpadd_filter('xmlrpc_enabled', '__return_false');

Izslēgt komentārus pilnībā

Aizver komentārus visos esošajos ierakstos, noņem komentāru atbalstu no ierakstu/lapu tipiem un paslēpj "Komentāri" izvēlni admin panelī - der vietnēm, kur komentāri nemaz nav vajadzīgi.

php// 1) Aizver komentārus/trackback visiem esošajiem ierakstiem un lapām
function wpds_disable_comments_status() {
    return false;
}
add_filter('comments_open', 'wpds_disable_comments_status', 20, 2);
add_filter('pings_open', 'wpds_disable_comments_status', 20, 2);

// 2) Noņem komentāru atbalstu no ierakstu/lapu tipiem
add_action('init', function() {
    remove_post_type_support('post', 'comments');
    remove_post_type_support('page', 'comments');
});

// 3) Paslēpj "Komentāri" admin izvēlnē
add_action('admin_menu', function() {
    remove_menu_page('edit-comments.php');
});

Paslēpt admin izvēlnes punktus

Vienkāršo admin paneli parastiem redaktoriem, paslēpjot izvēlnes punktus, kas viņiem nav vajadzīgi.

phpadd_action('admin_menu', function() {
    if (current_user_can('manage_options')) return; // administratori redz visu

    remove_menu_page('tools.php');       // Rīki
    remove_menu_page('edit-comments.php'); // Komentāri
    remove_menu_page('plugins.php');     // Spraudņi
}, 999); // liels skaitlis - izpildās PĒC visiem, kas izveido izvēlnes

Standarta izvēlnes punktu identifikatorus (kā tools.php, edit-comments.php) atrodi WordPress oficiālajā remove_menu_page() dokumentācijā. Pielāgota spraudņa izveidoto izvēlni (piem., no kāda uzstādīta spraudņa) paslēpj tāpat, izmantojot tā reģistrēto slug.

Pieteikšanās logo, saite & fons

Nomaina noklusējuma WordPress logo /wp-login.php lapā pret savas vietnes logo. Zemāk arī tas, kā tai pašā lapai ļaut pielāgot fona krāsu.

phpadd_action('login_enqueue_scripts', function() {
    $logo = get_template_directory_uri() . '/assets/logo.png';
    ?>
    <style>
        #login h1 a {
            background-image: url(<?= esc_url($logo) ?>);
            background-size: contain;
            width: 100%;
            height: 80px;
        }
    </style>
    <?php
});

// Neobligāti - logo klikšķis ved uz tavu vietni, ne wordpress.org
add_filter('login_headerurl', 'home_url');

Piemērs augstāk izmanto fiksētu failu no tēmas mapes - labi der, ja logo maina reti, pats izstrādātājs. Ja logo un logo saite jāļauj mainīt klientam pašam (bez koda rediģēšanas), izmanto WordPress Customizer - WP_Customize_Image_Control uzreiz dod gatavu attēla augšupielādes lauku ar priekšskatījumu no Media Library, bez papildu JS rakstīšanas:

php// 1) Reģistrē attēla LAUKU un URL LAUKU - abi Izskats → Pielāgot → Vietnes identitāte
add_action('customize_register', function($wp_customize) {
    $wp_customize->add_setting('wpds_login_logo', [
        'type'    => 'option', // saglabā wp_options tabulā, nevis theme mod
        'default' => '',
    ]);
    $wp_customize->add_control(new WP_Customize_Image_Control($wp_customize, 'wpds_login_logo_control', [
        'label'    => 'Pieteikšanās lapas logo',
        'section'  => 'title_tagline', // jau esoša "Vietnes identitāte" sadaļa
        'settings' => 'wpds_login_logo',
    ]));

    // Otrs, pavisam atsevišķs lauks - kur ved klikšķis uz logo
    $wp_customize->add_setting('wpds_login_logo_url', [
        'type'              => 'option',
        'default'           => '',
        'sanitize_callback' => 'esc_url_raw', // obligāti - lauks ir brīvs teksts, ne attēla ID
    ]);
    $wp_customize->add_control('wpds_login_logo_url', [
        'label'       => 'Logo saite (atstāj tukšu, lai vestu uz sākumlapu)',
        'section'     => 'title_tagline',
        'type'        => 'url',
    ]);

    // Trešais lauks - fona krāsa. WP_Customize_Color_Control pats pievieno
    // krāsu izvēlētāju (color picker), bez papildu JS
    $wp_customize->add_setting('wpds_login_bg_color', [
        'type'              => 'option',
        'default'           => '',
        'sanitize_callback' => 'sanitize_hex_color', // pieņem tikai derīgu #rrggbb vai tukšu
    ]);
    $wp_customize->add_control(new WP_Customize_Color_Control($wp_customize, 'wpds_login_bg_color_control', [
        'label'    => 'Pieteikšanās lapas fona krāsa',
        'section'  => 'title_tagline',
        'settings' => 'wpds_login_bg_color',
    ]));
});

// 2) Nolasa saglabāto attēlu un fona krāsu, izmanto tos - WP_Customize_Image_Control
// jau pats saglabā GATAVU attēla URL (nevis tikai ID), tāpēc get_option() pietiek
add_action('login_enqueue_scripts', function() {
    $logo = get_option('wpds_login_logo');
    $bg_krasa = get_option('wpds_login_bg_color');
    if (!$logo && !$bg_krasa) return; // nekas nav iestatīts - paliek WordPress noklusējums
    ?>
    <style>
        <?php if ($logo): ?>
        #login h1 a {
            background-image: url(<?= esc_url($logo) ?>);
            background-size: contain;
            width: 100%;
            height: 80px;
        }
        <?php endif; ?>
        <?php if ($bg_krasa): ?>
        body.login {
            background: <?= esc_attr($bg_krasa) ?>;
        }
        <?php endif; ?>
    </style>
    <?php
});

// 3) Nolasa saglabāto URL - ja lauks tukšs, atgriežas pie WordPress noklusējuma (home_url)
add_filter('login_headerurl', function($noklusejuma_url) {
    $custom_url = get_option('wpds_login_logo_url');
    return $custom_url ? esc_url($custom_url) : $noklusejuma_url;
});

Šis piemērs ir pilnībā pašpietiekams - pēc iekopēšanas klients uzreiz redz jaunus "Pieteikšanās lapas logo", "Logo saite" un "Pieteikšanās lapas fona krāsa" laukus Izskats → Pielāgot → Vietnes identitāte, ar attēla augšupielādes pogu un krāsu izvēlētāju. Nekas papildus (admin lapa, JS) nav jāraksta - visi trīs ievades tipi to visu jau dara paši.

Novirzīšana pēc pieteikšanās (pēc lomas)

Pēc pieteikšanās administratorus nosūta uz admin paneli, bet parastos lietotājus (piem., abonentus) - uz konta lapu, nevis noklusējuma admin dashboard.

phpadd_filter('login_redirect', function($parasta_adrese, $pieprasita_adrese, $user) {
    if ($user instanceof WP_User && in_array('administrator', $user->roles, true)) {
        return admin_url();
    }
    return home_url('/mans-konts/');
}, 10, 3);

Piespiedu admin valoda (latviski)

Uzspiež WordPress administrācijas paneli vienmēr rādīt latviešu valodā, neatkarīgi no katra lietotāja profilā izvēlētās personīgās valodas (Lietotāji → Tavs profils → Valoda) - noder, ja vēlies, lai visi komandas locekļi redz vienu un to pašu admin saskarni. Vietnes publiskā daļa (front-end) šo filtru neskar, jo is_admin() pārbauda tikai admin paneli.

phpadd_filter('locale', 'wpds_uzspiest_admin_valodu');
add_filter('user_locale', 'wpds_uzspiest_admin_valodu'); // obligāti - bez šī katra lietotāja profila valoda (Lietotāji → Tavs profils) uzvarētu virs šī iestatījuma

function wpds_uzspiest_admin_valodu($valoda) {
    if (is_admin()) {
        return 'lv_LV';
    }
    return $valoda;
}

Šis filtrs tikai norāda, kuru valodu WordPress mēģina lietot - tas nedarbosies, ja latviešu valodas pakotne serverī nav uzstādīta. Ja pēc šī koda admin panelis joprojām rādās angliski, dodies uz Iestatījumi → Vispārīgi → Vietnes valoda un izvēlies "Latviešu", lai WordPress lejupielādētu lv_LV tulkojuma failus (vai uzstādi ar WP-CLI: wp language core install lv_LV). Pēc tam šis filtrs turpinās strādāt automātiski visiem lietotājiem, arī tiem, kam profilā izvēlēta cita valoda.

Admin paneļa & pieteikšanās lapas krāsas

Šeit bieži iesācējs sajauc divas pavisam atšķirīgas lapas: wp-admin panelis (dashboard, redzams pēc pieteikšanās) un wp-login.php (pati pieteikšanās forma, pirms pieteikšanās). Katrai ir sava CSS un savs hooks - piemērs, kas maina vienu, otru vispār neietekmē.

1) Admin paneļa (dashboard) pamata krāsa

Kopš WordPress 5.7 admin panelis linkiem, fokusa iezīmējumiem un primārajām pogām izmanto CSS mainīgos - tos pārrakstot, maina krāsu visur uzreiz, neatkarīgi no lietotāja izvēlētās "Admin Color Scheme".

phpadd_action('admin_head', function() {
    ?>
    <style>
        :root {
            --wp-admin-theme-color: #d94f70;
            --wp-admin-theme-color-darker-10: #c23f5e;
            --wp-admin-theme-color-darker-20: #a8324e;
        }
    </style>
    <?php
});

2) Pieteikšanās lapas (wp-login.php) krāsa

wp-login.php šos CSS mainīgos nemaz nelasa - tai jāizmanto cits hooks (login_enqueue_scripts) un jāmērķē tieši uz lapā esošos selektorus (#nav - "Reģistrēties" / "Aizmirsāt paroli?", #backtoblog - "Atpakaļ uz vietni").

phpadd_action('login_enqueue_scripts', function() {
    ?>
    <style>
        #login #nav a,
        #login #backtoblog a {
            color: #d94f70;
        }
        #login #nav a:hover,
        #login #backtoblog a:hover {
            color: #a8324e;
        }

        /* Neobligāti - arī "Pieteikties" pogas krāsa */
        .wp-core-ui .button-primary {
            background: #d94f70;
            border-color: #a8324e;
        }
        .wp-core-ui .button-primary:hover,
        .wp-core-ui .button-primary:focus {
            background: #c23f5e;
            border-color: #8f2b45;
        }
    </style>
    <?php
});

admin_head neizsaucas vispār wp-login.php lapā - tā ir sava, atsevišķa lapa ārpus admin paneļa, ne tā daļa. Ja liec pirmo piemēru un gaidi, ka mainīsies pieteikšanās lapas krāsa, kods vienkārši nekad neizpildīsies tur, kur skaties - bieži izskatās, it kā "nekas nemainās", lai gan kods faktiski strādā pareizi (dashboard krāsa gan mainījusies).

3) Sekundārās (necaurspīdīgi apvilktās) pogas

WordPress atšķir divus pogu veidus: .button-primary - pilnībā iekrāsota "galvenā" darbība (piem., "Pieteikties"), un parasta .button - bez fona, tikai ar apmali (piem., "Mainīt", "Atcelt"). Tās ir divi atšķirīgi selektori - otrās pogas krāsu --wp-admin-theme-color mainīgais neietekmē, tāpēc tai jāpieraksta sava CSS, neatkarīgi no tā, vai poga atrodas admin panelī vai pieteikšanās lapā.

php// Der gan admin_head (dashboard), gan login_enqueue_scripts (wp-login.php) -
// izvēlies hooku atkarībā no tā, kurā lapā poga atrodas
add_action('admin_head', function() {
    ?>
    <style>
        .wp-core-ui .button:not(.button-primary) {
            color: #d94f70;
            border-color: #d94f70;
        }
        .wp-core-ui .button:not(.button-primary):hover,
        .wp-core-ui .button:not(.button-primary):focus {
            color: #a8324e;
            border-color: #a8324e;
        }
    </style>
    <?php
});

:not(.button-primary) pasargā no tā, lai šis noteikums netīšām nepārrakstītu pirmās apakšsadaļas primāro pogu stilu - abi noteikumi var droši dzīvot vienā un tajā pašā <style> blokā.

4) Pilnāks piemērs - vairāk elementu & pacēluma efekts pogai

Reālā projektā pieteikšanās lapā parasti jāstilizē vairāk nekā tikai divi-trīs elementi - arī privātuma politikas saite (redzama, ja iestatīta Privātuma politikas lapa) un valodas pārslēdzēja poga lapas apakšā (redzama, ja uzstādītas vairākas valodas). Šis piemērs apvieno visu iepriekšējo un pievieno arī nelielu "pacēluma" animāciju pogai, uzbraucot ar peli:

phpadd_action('login_enqueue_scripts', function() {
    ?>
    <style>
        #login #nav a,
        #login #backtoblog a {
            color: #c8b3d0; /* saišu krāsa */
        }
        #login #nav a:hover,
        #login #backtoblog a:hover {
            color: #997ca2; /* saišu krāsa, uzbraucot ar peli */
        }

        /* "Pieteikties" pogas krāsa, forma un pacēluma efekts */
        .wp-core-ui .button-primary {
            background: #1e1b4b !important;
            border-radius: 6px !important;
            border-color: transparent !important;
            color: #ffffff !important;
            transition: transform 0.45s cubic-bezier(0.25, 1, 0.5, 1) !important;
            will-change: transform !important;
        }
        .wp-core-ui .button-primary:hover,
        .wp-core-ui .button-primary:focus {
            transform: translateY(-3px) !important; /* poga "paceļas", uzbraucot ar peli */
            background-color: #34315d !important;
            color: #ffffff !important;
        }

        /* Privātuma politikas saites krāsa */
        .privacy-policy-page-link a {
            color: #c8b3d0 !important;
        }

        /* Valodas pārslēdzēja poga */
        .language-switcher input[type="submit"] {
            color: #c8b3d0 !important;
            border-color: #997ca2 !important;
            background-color: transparent !important;
        }
        .language-switcher input[type="submit"]:hover,
        .language-switcher input[type="submit"]:focus {
            color: #997ca2 !important;
            border-color: #c8b3d0 !important;
        }
    </style>
    <?php
});

Šeit parādās !important pie katras rindas - tas parasti ir "pēdējais līdzeklis" un labas prakses ziņā jāizvairās, bet šeit tas bieži nepieciešams, jo citi spraudņi (piem., sociālās pieteikšanās spraudņi) vai tēma paši ielādē savu CSS ar lielāku specifiskumu (specificity) pieteikšanās lapā. Ja bez !important stils netiek pielietots, tas nozīmē - kaut kas cits to jau pārraksta.

Redaktoram (Editor lomai) - Customizer piekļuve, bet ierobežota

Pēc noklusējuma tikai administratori var atvērt Izskats → Pielāgot (Customizer). Ja vēlies, lai arī Redaktora lomas lietotāji var mainīt logo, krāsas u.tml., bet nevar piekļūt tehniskākām sadaļām (izvēlnes, sīkrīki, pielāgots CSS) - vajadzīgas divas daļas: tiesību piešķiršana un pēc tam ierobežošana.

php// 1) Piešķir Redaktora lomai tiesības atvērt Customizer
add_action('admin_init', 'wpds_atlaut_redaktoram_customizer');
function wpds_atlaut_redaktoram_customizer() {
    $role = get_role('editor');
    if ($role && !$role->has_cap('edit_theme_options')) {
        $role->add_cap('edit_theme_options');
    }
}

// 2) Bet noņem tehniskākās sadaļas, ja lietotājs NAV administrators
add_action('customize_register', 'wpds_ierobezot_customizer_redaktoram', 999);
function wpds_ierobezot_customizer_redaktoram($wp_customize) {
    if (!current_user_can('administrator')) {
        $wp_customize->remove_section('custom_css');
        $wp_customize->remove_panel('nav_menus');
        $wp_customize->remove_panel('widgets');
        $wp_customize->remove_section('static_front_page');
    }
}

Prioritāte 999 otrajā funkcijā ir svarīga - tā izpildās pēc tam, kad WordPress un citi spraudņi jau ir reģistrējuši visas savas Customizer sadaļas, tāpēc ir kas noņemt. Ja izlaidīsi prioritāti, funkcija var izpildīties par agru un daļu sadaļu vēl nemaz nebūs, ko dzēst.

Kešatmiņas tīrīšanas poga admin joslā

Pievieno pogu WordPress augšējā admin joslā (redzama gan admin panelī, gan front-end pusē, ja lietotājs ielogojies), kas piespiedu kārtā pārlādē lapu, apejot pārlūka kešatmiņu - noder klientiem, kas bieži jautā "kāpēc neredzu savas izmaiņas".

phpadd_action('admin_bar_menu', function($wp_admin_bar) {
    $wp_admin_bar->add_node([
        'id'    => 'wpds_clear_cache',
        'title' => '⟳ Atjaunināt skatu',
        'href'  => '#',
        'meta'  => [
            'onclick' => 'wpdsClearCacheAndReload(); return false;',
            'title'   => 'Nospied, ja lapā neredzi jaunākās izmaiņas',
        ],
    ]);
}, 999);

add_action('admin_footer', 'wpds_cache_button_script'); // admin panelim
add_action('wp_footer', 'wpds_cache_button_script');    // front-end pusei (ja josla redzama)

function wpds_cache_button_script(): void {
    ?>
    <script>
    function wpdsClearCacheAndReload() {
        if (confirm('Vai pārlādēt lapu, apejot pārlūka kešatmiņu?')) {
            var url = window.location.href.split('?')[0];
            window.location.replace(url + '?nocache=' + Date.now());
        }
    }
    </script>
    <?php
}

Šī poga apiet tikai pārlūka kešatmiņu, pievienojot mainīgu parametru URL. Ja vietnē uzstādīts servera puses kešošanas spraudnis (WP Rocket, W3 Total Cache u.tml.) vai CDN (Cloudflare), tam var būt sava, atsevišķa kešatmiņa, kas jāiztīra atsevišķi - šī poga to neskar. Vajadzības gadījumā wpdsClearCacheAndReload() vietā var izsaukt attiecīgā spraudņa savu "purge cache" AJAX galapunktu.

Paslēpt admin paziņojumus konkrētā ekrānā

Admin panelī bieži uzkrājas atjaunināšanas, reklāmas un spraudņu paziņojumu josliņas, kas traucē klientiem koncentrēties uz reālo darbu. Šis piemērs paslēpj tās (izņemot veiksmes/kļūdas paziņojumus) tikai konkrētā admin ekrānā, nevis visur.

phpadd_action('admin_head', function() {
    if (!function_exists('get_current_screen')) return;

    $screen = get_current_screen();
    if (!$screen || $screen->post_type !== 'post') return; // maini uz vajadzīgo ekrānu

    echo '<style>
        .notice:not(.notice-success):not(.notice-error),
        .update-nag,
        #wp-admin-bar-updates {
            display: none !important;
        }
    </style>';
});

Jebkura teksta/frāzes aizstāšana (gettext)

gettext filtrs ļauj pārrakstīt jebkuru tekstu, ko WordPress vai kāds spraudnis izvada caur tulkošanas funkcijām (__(), _e() u.tml.) - pat ja tev nav piekļuves attiecīgā spraudņa kodam. Noder, ja gribi mainīt kāda spraudņa tekstu, nerediģējot pašu spraudni (kas citādi pazustu nākamajā atjauninājumā).

php// Vienkāršs, precīzs viena teksta aizstāšanas gadījums
add_filter('gettext', 'wpds_aizvietot_vienu_frazi', 20, 3);
function wpds_aizvietot_vienu_frazi($tulkotais, $original, $domain) {
    if ($tulkotais === 'E-pasta paroles atiestatīšanas saite') {
        return 'Atiestatīt paroli';
    }
    return $tulkotais;
}

// Vairāku vārdu/frāžu masveida aizstāšana konkrētam spraudnim (piem., WooCommerce)
add_filter('gettext', function($tulkotais, $original, $domain) {
    if ($domain !== 'woocommerce') return $tulkotais; // tikai šī spraudņa teksti

    $aizvietojumi = [
        'Pasūtījums' => 'Pirkums',
        'Pasūtījumi' => 'Pirkumi',
        'pasūtījums' => 'pirkums',
    ];

    return strtr($tulkotais, $aizvietojumi);
}, 20, 3);

Salīdzini pret $tulkotais (jau iztulkoto tekstu), nevis pret $original (angļu oriģinālu) - tā piemērs strādās neatkarīgi no tā, vai vietnei uzstādīta angļu vai latviešu valoda. $domain pārbaude (piem., === 'woocommerce') svarīga, lai netīšām neaizvietotu vienādu vārdu citur, kur tas nozīmē ko citu.

Iztīrīt transientus pēc prefiksa

WordPress nesniedz iebūvētu veidu, kā izdzēst "visus transientus, kuru nosaukums sākas ar X" - jāizmanto $wpdb tieši. Noder, kad kešots dati (skat. Transients) jāatjauno uzreiz pēc konkrētas darbības, nevis jāgaida, kamēr pats termiņš beidzas.

phpfunction wpds_iztirit_transientus(string $prefikss): void {
    global $wpdb;

    $wpdb->query($wpdb->prepare(
        "DELETE FROM {$wpdb->options} WHERE option_name LIKE %s OR option_name LIKE %s",
        $wpdb->esc_like('_transient_' . $prefikss) . '%',
        $wpdb->esc_like('_transient_timeout_' . $prefikss) . '%'
    ));
}

// Piemērs: dzēš visus 'produktu_saraksts_*' transientus, tiklīdz ieraksts tiek saglabāts
add_action('save_post', function() {
    wpds_iztirit_transientus('produktu_saraksts_');
});

Katram transientam datubāzē faktiski ir divi ieraksti - _transient_{atslēga} (pati vērtība) un _transient_timeout_{atslēga} (derīguma termiņš) - tāpēc dzēšanas vaicājumam jāaptver abi prefiksi, citādi paliks "bāreņu" ieraksti datubāzē. $wpdb->esc_like() ir obligāts, ja prefikss jebkad varētu saturēt lietotāja ievadi - tas izbēg %/_ simbolus, kam SQL LIKE ir īpaša nozīme.

Bootstrap saderīga izvēlne (Walker)

WordPress wp_nav_menu() pēc noklusējuma neizvada Bootstrap sagaidītās klases (nav-item, dropdown-menu u.tml.) - bez pielāgota Walker_Nav_Menu apakšklases nolaižamās apakšizvēlnes vizuāli nestrādās, pat ja Bootstrap CSS/JS ir pieslēgts. Šis Walker pārraksta izvades struktūru tā, lai sakristu ar Bootstrap 5 marķējumu.

phpclass Bootstrap5_Nav_Walker extends Walker_Nav_Menu {

    public function start_lvl(&$output, $depth = 0, $args = null) {
        $output .= '<ul class="dropdown-menu">';
    }

    public function end_lvl(&$output, $depth = 0, $args = null) {
        $output .= '</ul>';
    }

    public function start_el(&$output, $item, $depth = 0, $args = null, $id = 0) {
        $has_children = in_array('menu-item-has-children', $item->classes);
        $is_active    = in_array('current-menu-item', $item->classes)
                      || in_array('current-menu-ancestor', $item->classes);

        if ($depth === 0) {
            $li_class   = 'nav-item' . ($has_children ? ' dropdown' : '');
            $link_class = 'nav-link' . ($has_children ? ' dropdown-toggle' : '') . ($is_active ? ' active' : '');
            $toggle     = $has_children ? ' data-bs-toggle="dropdown" aria-expanded="false" role="button"' : '';
        } else {
            $li_class   = 'dropdown-item-wrap' . ($has_children ? ' dropend' : '');
            $link_class = 'dropdown-item' . ($is_active ? ' active' : '');
            $toggle     = $has_children ? ' data-bs-toggle="dropdown" aria-expanded="false"' : '';
        }

        $active_attr = $is_active ? ' aria-current="page"' : '';

        $output .= '<li class="' . $li_class . '">';
        $output .= '<a class="' . $link_class . '" href="' . esc_url($item->url) . '"' . $toggle . $active_attr . '>';
        $output .= esc_html($item->title);
        $output .= '</a>';
    }

    public function end_el(&$output, $item, $depth = 0, $args = null) {
        $output .= '</li>';
    }
}

Lietošana veidnē (skat. arī Izvēlnes pamatiem) - vienkārši pievieno 'walker' parametru:

phpwp_nav_menu([
    'theme_location' => 'galvena',
    'container'      => 'nav',
    'menu_class'     => 'navbar-nav',
    'walker'         => new Bootstrap5_Nav_Walker(),
]);

Ja izmanto citu CSS ietvaru (Tailwind, Bulma), maini tikai klašu nosaukumus (nav-item, dropdown-menu utt.) uz sava ietvara ekvivalentiem - pati Walker struktūra (kad izsaukt start_lvl/start_el) paliek nemainīga jebkuram CSS ietvaram.

Taksonomijas) - pati novirzīšanas loģika (wp_redirect() + exit) paliek identiska. Pielāgota metabox (avota lauks)

Papildina ieraksta rediģēšanas ekrānu ar savu, redzamu ievades lauku - atšķirībā no Pielāgotiem laukiem pamatlapā (kur dati tiek pievienoti programmatiski), šis piemērs rāda pilnu ceļu: administrators redz un aizpilda lauku admin panelī.

php// 1) Reģistrē metabox - parādās sānā, "post" ierakstu rediģēšanas ekrānā

    add_meta_box(
        'wpds_avots',
        'Avots',
        'wpds_avots_render',
        'post',
        'side',
        'default'
    );
});

// 2) Izvada lauku - nolasa esošo vērtību, ja tāda jau ir
function wpds_avots_render($post) {
    wp_nonce_field('wpds_avots_save', 'wpds_avots_nonce');
    $avots = get_post_meta($post->ID, 'avots', true);
    ?>
    <input type="text" name="avots"
           value="<?php echo esc_attr($avots); ?>"
           placeholder="piem. Delfi, https://avots.lv" style="width:100%;">
    <?php
}

// 3) Saglabā, kad ieraksts tiek publicēts/atjaunināts
add_action('save_post', function($post_id) {
    if (!isset($_POST['wpds_avots_nonce'])) return;
    if (!wp_verify_nonce($_POST['wpds_avots_nonce'], 'wpds_avots_save')) return;
    if (defined('DOING_AUTOSAVE') && DOING_AUTOSAVE) return;
    if (!current_user_can('edit_post', $post_id)) return;

    if (!empty($_POST['avots'])) {
        update_post_meta($post_id, 'avots', sanitize_text_field($_POST['avots']));
    } else {
        delete_post_meta($post_id, 'avots');
    }
});

Izvade veidnē - pilnīgi tāpat kā jebkurš cits get_post_meta() nolasījums:

php<?php $avots = get_post_meta(get_the_ID(), 'avots', true); ?>
<?php if ($avots): ?>
    <p>Avots: <?php echo esc_html($avots); ?></p>
<?php endif; ?>

DOING_AUTOSAVE pārbaude ir svarīga - WordPress ik pa brīdi automātiski saglabā melnrakstu fonā, kamēr rediģē; bez šīs pārbaudes save_post izpildītos arī tad, kad $_POST vēl nesatur tavu lauku, un varētu netīšām izdzēst jau saglabāto vērtību. Lai pievienotu vēl vienu ierakstu tipu (ne tikai post), atkārto add_meta_box() izsaukumu ar citu tipa nosaukumu.

Stripe apmaksas formas valoda

Ja izmanto WooCommerce Stripe Gateway spraudni, apmaksas forma (kartes numura lauks, kļūdu ziņojumi) pēc noklusējuma parādās apmeklētāja pārlūka valodā vai angliski - wc_stripe_params filtrs ļauj to piespiest uz konkrētu valodu.

Šis filtrs attiecas tikai uz oficiālo WooCommerce Stripe Gateway spraudņa integrāciju (kas pati ģenerē apmaksas formu tieši veikala lapā ar Stripe.js). TranslatePress: indeksēšana citai valodai - soli pa solim

Situācija: vietne izmanto TranslatePress vairāku valodu atbalstam, latviešu versija Google indeksā jau ir, bet otra valoda (šeit - piemēram, krievu, /ru/) vai nu vispār netiek indeksēta, vai Search Console rāda kļūdas ("Dublikāts", "Alternatīvā lapa ar pareizu canonical taga vērtību" u.tml.). Šī nav viena kļūda, bet virkne mazu trūkumu, kas jāsalabo secīgi - katrs solis balstās uz iepriekšējo.

1. solis - pareizs valodas atribūts un hreflang tagi

Vispirms pamats: WordPress pēc noklusējuma turpina izvadīt <html lang="lv"> pat krievu valodas lapās, un nemaz neizvada hreflang tagus. Bez tiem Google nezina, ka /ru/lapa/ ir tā paša satura krievu versija, nevis atsevišķa, dublēta lapa - tas ir pats biežākais indeksēšanas problēmu cēlonis daudzvalodu vietnēs, un pārējie soļi bez šī nestrādās pareizi.

phpadd_filter('language_attributes', function($output) {
    if (function_exists('trp_get_current_language')) {
        $valoda = trp_get_current_language(); // piem. 'lv', 'ru', 'en'
        $output = 'lang="' . esc_attr($valoda) . '"';
    }
    return $output;
});

add_action('wp_head', function() {
    if (!class_exists('TRP_Translate_Press')) {
        return;
    }

    $trp = TRP_Translate_Press::get_trp_instance();
    $url_converter = $trp->get_component('url_converter');
    $settings = $trp->get_component('settings')->get_settings();
    $pasreizeja_url = (is_ssl() ? 'https://' : 'http://') . $_SERVER['HTTP_HOST'] . $_SERVER['REQUEST_URI'];

    foreach ($settings['translation-languages'] as $valodas_kods) {
        $tulkotais_url = $url_converter->get_url_for_language($valodas_kods, $pasreizeja_url, '');
        echo '<link rel="alternate" hreflang="' . esc_attr($valodas_kods) . '" href="' . esc_url($tulkotais_url) . '" />' . "\n";
    }

    // x-default norāda meklētājam, kura versija jārāda, ja neviena valoda tieši neatbilst
    $noklusejuma_url = $url_converter->get_url_for_language($settings['default-language'], $pasreizeja_url, '');
    echo '<link rel="alternate" hreflang="x-default" href="' . esc_url($noklusejuma_url) . '" />' . "\n";
}, 5);

trp_get_current_language()

TranslatePress funkcija, kas atgriež pašreizējās lapas valodas kodu (piem. 'ru') - pieejama tikai tad, ja spraudnis ir aktīvs, tāpēc vienmēr jāpārbauda ar function_exists().

url_converter komponente

TranslatePress iekšējais rīks, kas no jebkura URL uzbūvē tā ekvivalentu citā valodā - tieši to pašu, ko izmanto valodu pārslēdzējs izvēlnē.

Prioritāte 5

Izvada hreflang tagus agri <head> sadaļā - pirms lielākās daļas SEO spraudņu izvades, kas ir ieteicamā prakse.

Pēc ieviešanas pārbaudi rezultātu ar skatīt lapas avotu (View Source) katrā valodas versijā - vajadzētu redzēt vienu <link rel="alternate" hreflang="..."> katrai valodai, ieskaitot pašu pašreizējo. Google Search Console (Lapas → Indeksēšana) parasti parāda hreflang kļūdas 1-2 nedēļu laikā pēc ieviešanas.

2. solis - SEO virsraksti & apraksti krievu valodai

Hreflang tagi pasaka Google, kuras lapas ir saistītas - bet TranslatePress pēc noklusējuma tulko tikai lapas redzamo saturu, ne Yoast SEO virsrakstu/aprakstu laukus (tie ir uzstādīti reizi, konkrētajai lapai, neatkarīgi no valodas). Rezultātā krievu valodas versija meklētājā joprojām parādītos ar latvisko virsrakstu - jāfiltrē wpseo_title un wpseo_metadesc pēc pašreizējās valodas ar uzmeklēšanas masīvu.

    return $apraksts;
}

Lapas ID uzzini, atverot to rediģēšanai admin panelī - tas redzams pārlūka adreses joslā (post.php?post=123&action=edit).

Ja lapu skaits ir liels, TranslatePress piedāvā arī maksas paplašinājumu SEO Pack, kas ļauj tulkot šos laukus tieši redaktora saskarnē (tāpat kā parasto saturu) - augstāk redzamais filtru risinājums ir bezmaksas alternatīva, kas ērta pie neliela, fiksēta lapu skaita (piem., līdz 10-15 lapām).

3. solis - dublētu URL un canonical labošana

Ar hreflang un savu SEO tekstu krievu versija jau ir pareizi marķēta un atšķirama - bet, ja saites uz to kaut kur ir "salauztas", Google to var indeksēt kā atsevišķu, bojātu lapu. Divi bieži sastopami cēloņi: (1) daži iekšējie saites ģenerē dubultu valodas prefiksu, piem. /ru/ru/lapa/; (2) strukturētie dati (JSON-LD, ko izvada Yoast SEO) reizēm satur nepareizu vai novecojušu url lauku, kas neatbilst pašreizējai lapas adresei.

php// 1) Novērš /ru/ru/ tipa dublētu valodas prefiksu izvadītajā HTML
add_action('template_redirect', function() {
    if (is_admin()) {
        return;
    }

    ob_start(function($html) {
        return preg_replace('#/(en|ru)/\1/#', '/$1/', $html);
    });
});

// 2) Labo canonical URL Yoast strukturētajos datos (JSON-LD)
add_filter('wpseo_schema_graph', function($data) {
    $pareiza_url = (is_ssl() ? 'https://' : 'http://') . $_SERVER['HTTP_HOST'] . $_SERVER['REQUEST_URI'];

    foreach ($data as &$vieniba) {
        if (isset($vieniba['url'])) {
            $vieniba['url'] = $pareiza_url;
        }
    }

    return $data;
}, 20);

// 3) Papildina robots.txt ar sitemap saiti (dažreiz nepieciešams manuāli daudzvalodu sitemapiem)
add_filter('robots_txt', function($output) {
    $output .= "Sitemap: " . home_url('/sitemap_index.xml') . "\n";
    return $output;
}, 20);

Vispirms diagnosticē, vai dubultā prefiksa problēma vispār pastāv (skaties lapas avotu vai Search Console → Lapas → "Dublikāts, Google izvēlējās citu kanonisko URL") - pievieno #1 tikai tad, ja tiešām redzi /ru/ru/ tipa saites. preg_replace ar output buffering katrā lapas ielādē nedaudz palielina servera slodzi, tāpēc tas ir labojums simptomam, nevis pamatcēlonim (parasti tas ir cietkodēta valodas prefiksa saite kādā veidnē vai page builderī).

4. solis - sitemap krievu valodas lapām

Ar iepriekšējiem trim soļiem esošās krievu lapas ir pareizi marķētas un pieejamas - bet, ja Yoast/RankMath automātiski ģenerētais sitemap_index.xml tās neietver (bieži gadās TranslatePress apakšmapju struktūrai, īpaši statiskām/pielāgotām lapām, kas nav parasti WordPress raksti), Google par tām var vienkārši nezināt. Risinājums - atsevišķs, manuāli uzturēts sitemap fails tieši šai valodai.

xml<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
<url><loc>https://tavavietne.lv/ru/</loc><lastmod>2026-08-14</lastmod></url>
<url><loc>https://tavavietne.lv/ru/kontakti/</loc><lastmod>2026-03-12</lastmod></url>
<url><loc>https://tavavietne.lv/ru/pakalpojums-a/</loc><lastmod>2026-03-18</lastmod></url>
</urlset>

1. Faila nosaukums

Piem. ru-sitemap.xml - jebkurš skaidrs nosaukums, nav WordPress rezervēts termins.

2. Kur likt

Tieši httpdocs saknes mapē (caur Plesk File Manager vai FTP) - tajā pašā vietā, kur atrodas galvenais sitemap_index.xml.

3. Sasaiste

Saite uz šo failu jau tiek pievienota robots.txt iepriekšējā koda 3. daļā - papildus iesniedz to arī atsevišķi Google Search Console → Sitemaps.

Šis fails ir statisks - atšķirībā no sitemap_index.xml, tas neatjaunojas pats, kad pievieno vai maina lapas. lastmod jāatjaunina manuāli. Tāpēc šī pieeja der tikai nelielam, retāk mainīgam lapu skaitam (dažiem desmitiem) - ja valodas versijai ir simtiem lapu vai tās mainās bieži, labāk atrisināt, kāpēc SEO spraudnis tās neietver automātiski, nevis uzturēt manuālu failu ilgtermiņā.

Automātiska aizpilde pieteikušamies lietotājiem

Contact Form 7 formas laukos var norādīt default:... parametru - tas automātiski aizpilda lauku ar pieteikušā lietotāja datiem, ja apmeklētājs jau ir ielogojies. Neielogotam apmeklētājam lauks vienkārši paliek tukšs - kļūdas nav, tas ir gaidītā uzvedība.

html<label>Vārds <span style="color: red;">*</span></label>
[text* name default:user_display_name placeholder "Jūsu vārds"]

<label>Tālrunis <span style="color: red;">*</span></label>
[tel* phone default:user_meta key='billing_phone' placeholder "+371..."]

<label>E-pasts <span style="color: red;">*</span></label>
[email* email default:user_email placeholder "piemers@epasts.lv"]

<label>Jūsu ziņa <span style="color: red;">*</span></label>
[textarea* message x4 minlength:10]

[submit "Nosūtīt ziņu"]

default:user_display_name

Aizpilda ar pieteikušā lietotāja publiski redzamo vārdu (WordPress profila "Displayed name" lauks).

default:user_email

Aizpilda ar lietotāja konta e-pasta adresi.

default:user_meta key='...'

Aizpilda ar jebkuru lietotāja meta lauku - piem., billing_phone ir WooCommerce saglabātais rēķina tālrunis.

user_meta key='billing_phone' strādā tikai tad, ja lietotājs jau iepriekš iegādājies kaut ko WooCommerce veikalā (vai administrators to ir manuāli aizpildījis) - billing_phone ir WooCommerce, nevis WordPress kodola meta lauks. Ja projektā WooCommerce nav uzstādīts, šis konkrētais lauks paliks tukšs arī pieteikušamies lietotājiem.

Aizpildītā vērtība ir tikai sākotnējais ieteikums - lauks joprojām ir parasts teksta lauks, ko lietotājs var brīvi rediģēt vai izdzēst pirms nosūtīšanas. Neuztver to kā drošu, neapšaubāmu datu avotu servera pusē - ja formas apstrādē kaut ko izmanto tālāk (piem., saglabā datubāzē), joprojām validē un attīri ievadi tāpat kā jebkuru citu formas lauku.

Kontaktforma divās valodās (pēc URL)

Ja vietnei ir viens koplietots veidnes fails (piem. footeris vai kontaktu lapas veidne), ko rāda visām TranslatePress valodu versijām, bet katrai valodai vajag atšķirīgu Contact Form 7 formu (citādi lauku nosaukumi, citāda apstiprinājuma e-pasta valoda) - shortcode, kas nosaka valodu pēc URL un izvada atbilstošo formu, ir vienkāršāk nekā dublēt visu veidni.

phpadd_shortcode('kontaktforma_valoda', function() {
    $celjs = isset($_SERVER['REQUEST_URI']) ? $_SERVER['REQUEST_URI'] : '';
    $ir_krievu = (strpos($celjs, '/ru/') !== false);

    $forma_id = $ir_krievu ? 456 : 123; // nomaini uz reālajiem CF7 formu ID
    $izvade = do_shortcode('[contact-form-7 id="' . (int) $forma_id . '"]');

    // data-no-translation liedz TranslatePress mēģināt "tulkot" formas HTML katrā ielādē
    return '<div data-no-translation="1">' . $izvade . '</div>';
});

Izmanto veidnē vai lapas saturā [kontaktforma_valoda] vietā, kur citādi liktu [contact-form-7 id="..."] tieši.

Kāpēc data-no-translation ir svarīgs: TranslatePress pēc noklusējuma mēģina tulkot jebkuru redzamo tekstu lapā, arī formas HTML - tas var sabojāt CF7 slēptos laukus (nonce, formas ID), kas noved pie formas, kas izskatās normāli, bet nekad neaizsūta e-pastu. Šis atribūts pasaka TranslatePress "šo bloku neaiztiec".

URL noteikšana pēc /ru/ ir vienkāršs, bet trausls risinājums - tas pieņem, ka TranslatePress lieto apakšmapju struktūru (nevis apakšdomēnu vai parametru). Ja projektam ir tikai dažas lapas ar formu (nevis viena koplietota veidne visām valodām), robustāks variants ir vienkārši ievietot [contact-form-7 id="123"] un [contact-form-7 id="456"] tieši attiecīgās lapas tulkotajā versijā - bez shortcode starpniekloģikas vispār.

Ielādēt CF7 skriptus tikai vajadzīgajā lapā

Contact Form 7 pēc noklusējuma ielādē savu CSS un JS katrā vietnes lapā, pat ja formas tur nemaz nav - nelietderīga slodze, kas nedaudz palēnina katru lapu. Ja forma parādās tikai konkrētā(s) lapā(s), abus filtrus var ierobežot.

phpadd_filter('wpcf7_load_js', function($load_js) {
    return is_page('kontakti');
});

add_filter('wpcf7_load_css', function($load_css) {
    return is_page('kontakti');
});

Ja forma parādās vairākās lapās (piem., kontaktu lapā un footerī visās lapās), is_page('kontakti') jāpaplašina attiecīgi - pretējā gadījumā forma pārējās lapās parādīsies bez stila vai bez validācijas JS. Ja forma ir footerī (redzama visur), šo optimizāciju vienkārši nevajag pielietot.
