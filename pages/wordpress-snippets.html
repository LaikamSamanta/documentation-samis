Ātrie risinājumi

Populāri, patstāvīgi functions.php trikizi — katru var iekopēt tieši tādu, kāds tas ir, tēmas functions.php failā (vai izceltā failā, ko no turienes ielādē ar require_once). Meklē pilnas dziļās sadaļas? Skaties pilnajā WordPress dokumentācijā.

SVG augšupielāžu atbalsts

WordPress pēc noklusējuma bloķē SVG augšupielādi — SVG faili ir teksta (XML) faili, kas var saturēt JavaScript kodu, tāpēc tie ir potenciāls XSS drošības risks. Šis kods atļauj SVG, bet tikai uzticamiem lietotājiem (administratoriem).

phpadd_filter('upload_mimes', function($mimes) {
    if (current_user_can('manage_options')) {
        $mimes['svg'] = 'image/svg+xml';
    }
    return $mimes;
});

Nekad neatļauj SVG augšupielādi visiem lietotājiem (piem., edit_posts vietā manage_options) — jebkurš, kas var augšupielādēt SVG, teorētiski var ievietot ļaunprātīgu JavaScript kodu. Ražošanas vietnēm, kur SVG jāaugšupielādē arī parastiem redaktoriem, apsver specializētu spraudni (piem., "Safe SVG"), kas SVG failu attīra pirms saglabāšanas.

Noņemt WordPress versijas numuru

WordPress pēc noklusējuma lapas HTML kodā atklāj savu versijas numuru — tas atvieglo uzbrucējiem atrast vietnes, kam vēl nav uzstādīts jaunākais drošības labojums.

phpremove_action('wp_head', 'wp_generator');

Izslēgt XML-RPC

XML-RPC ir vecāks WordPress interfeiss ārējiem savienojumiem (piem., senākām mobilajām lietotnēm) — tas ir arī izplatīts brute-force uzbrukumu mērķis. Ja to nelieto (lielākā daļa vietņu nelieto), droši izslēdz.

phpadd_filter('xmlrpc_enabled', '__return_false');

Izslēgt komentārus pilnībā

Aizver komentārus visos esošajos ierakstos, noņem komentāru atbalstu no ierakstu/lapu tipiem un paslēpj "Komentāri" izvēlni admin panelī — der vietnēm, kur komentāri nemaz nav vajadzīgi.

php// 1) Aizver komentārus/trackback visiem esošajiem ierakstiem un lapām
function wpds_disable_comments_status() {
    return false;
}
add_filter('comments_open', 'wpds_disable_comments_status', 20, 2);
add_filter('pings_open', 'wpds_disable_comments_status', 20, 2);

// 2) Noņem komentāru atbalstu no ierakstu/lapu tipiem
add_action('init', function() {
    remove_post_type_support('post', 'comments');
    remove_post_type_support('page', 'comments');
});

// 3) Paslēpj "Komentāri" admin izvēlnē
add_action('admin_menu', function() {
    remove_menu_page('edit-comments.php');
});

Paslēpt admin izvēlnes punktus

Vienkāršo admin paneli parastiem redaktoriem, paslēpjot izvēlnes punktus, kas viņiem nav vajadzīgi.

phpadd_action('admin_menu', function() {
    if (current_user_can('manage_options')) return; // administratori redz visu

    remove_menu_page('tools.php');       // Rīki
    remove_menu_page('edit-comments.php'); // Komentāri
    remove_menu_page('plugins.php');     // Spraudņi
}, 999); // liels skaitlis — izpildās PĒC visiem, kas izveido izvēlnes

Standarta izvēlnes punktu identifikatorus (kā tools.php, edit-comments.php) atrodi WordPress oficiālajā remove_menu_page() dokumentācijā. Pielāgota spraudņa izveidoto izvēlni (piem., no kāda uzstādīta spraudņa) paslēpj tāpat, izmantojot tā reģistrēto slug.

Pieteikšanās logo, saite & fons

Nomaina noklusējuma WordPress logo /wp-login.php lapā pret savas vietnes logo. Zemāk arī tas, kā tai pašā lapai ļaut pielāgot fona krāsu.

phpadd_action('login_enqueue_scripts', function() {
    $logo = get_template_directory_uri() . '/assets/logo.png';
    ?>
    <style>
        #login h1 a {
            background-image: url(<?= esc_url($logo) ?>);
            background-size: contain;
            width: 100%;
            height: 80px;
        }
    </style>
    <?php
});

// Neobligāti — logo klikšķis ved uz tavu vietni, ne wordpress.org
add_filter('login_headerurl', 'home_url');

Piemērs augstāk izmanto fiksētu failu no tēmas mapes — labi der, ja logo maina reti, pats izstrādātājs. Ja logo un logo saite jāļauj mainīt klientam pašam (bez koda rediģēšanas), izmanto WordPress Customizer — WP_Customize_Image_Control uzreiz dod gatavu attēla augšupielādes lauku ar priekšskatījumu no Media Library, bez papildu JS rakstīšanas:

php// 1) Reģistrē attēla LAUKU un URL LAUKU — abi Izskats → Pielāgot → Vietnes identitāte
add_action('customize_register', function($wp_customize) {
    $wp_customize->add_setting('wpds_login_logo', [
        'type'    => 'option', // saglabā wp_options tabulā, nevis theme mod
        'default' => '',
    ]);
    $wp_customize->add_control(new WP_Customize_Image_Control($wp_customize, 'wpds_login_logo_control', [
        'label'    => 'Pieteikšanās lapas logo',
        'section'  => 'title_tagline', // jau esoša "Vietnes identitāte" sadaļa
        'settings' => 'wpds_login_logo',
    ]));

    // Otrs, pavisam atsevišķs lauks — kur ved klikšķis uz logo
    $wp_customize->add_setting('wpds_login_logo_url', [
        'type'              => 'option',
        'default'           => '',
        'sanitize_callback' => 'esc_url_raw', // obligāti — lauks ir brīvs teksts, ne attēla ID
    ]);
    $wp_customize->add_control('wpds_login_logo_url', [
        'label'       => 'Logo saite (atstāj tukšu, lai vestu uz sākumlapu)',
        'section'     => 'title_tagline',
        'type'        => 'url',
    ]);

    // Trešais lauks — fona krāsa. WP_Customize_Color_Control pats pievieno
    // krāsu izvēlētāju (color picker), bez papildu JS
    $wp_customize->add_setting('wpds_login_bg_color', [
        'type'              => 'option',
        'default'           => '',
        'sanitize_callback' => 'sanitize_hex_color', // pieņem tikai derīgu #rrggbb vai tukšu
    ]);
    $wp_customize->add_control(new WP_Customize_Color_Control($wp_customize, 'wpds_login_bg_color_control', [
        'label'    => 'Pieteikšanās lapas fona krāsa',
        'section'  => 'title_tagline',
        'settings' => 'wpds_login_bg_color',
    ]));
});

// 2) Nolasa saglabāto attēlu un fona krāsu, izmanto tos — WP_Customize_Image_Control
// jau pats saglabā GATAVU attēla URL (nevis tikai ID), tāpēc get_option() pietiek
add_action('login_enqueue_scripts', function() {
    $logo = get_option('wpds_login_logo');
    $bg_krasa = get_option('wpds_login_bg_color');
    if (!$logo && !$bg_krasa) return; // nekas nav iestatīts — paliek WordPress noklusējums
    ?>
    <style>
        <?php if ($logo): ?>
        #login h1 a {
            background-image: url(<?= esc_url($logo) ?>);
            background-size: contain;
            width: 100%;
            height: 80px;
        }
        <?php endif; ?>
        <?php if ($bg_krasa): ?>
        body.login {
            background: <?= esc_attr($bg_krasa) ?>;
        }
        <?php endif; ?>
    </style>
    <?php
});

// 3) Nolasa saglabāto URL — ja lauks tukšs, atgriežas pie WordPress noklusējuma (home_url)
add_filter('login_headerurl', function($noklusejuma_url) {
    $custom_url = get_option('wpds_login_logo_url');
    return $custom_url ? esc_url($custom_url) : $noklusejuma_url;
});

Šis piemērs ir pilnībā pašpietiekams — pēc iekopēšanas klients uzreiz redz jaunus "Pieteikšanās lapas logo", "Logo saite" un "Pieteikšanās lapas fona krāsa" laukus Izskats → Pielāgot → Vietnes identitāte, ar attēla augšupielādes pogu un krāsu izvēlētāju. Nekas papildus (admin lapa, JS) nav jāraksta — visi trīs ievades tipi to visu jau dara paši.

Novirzīšana pēc pieteikšanās (pēc lomas)

Pēc pieteikšanās administratorus nosūta uz admin paneli, bet parastos lietotājus (piem., abonentus) — uz konta lapu, nevis noklusējuma admin dashboard.

phpadd_filter('login_redirect', function($parasta_adrese, $pieprasita_adrese, $user) {
    if ($user instanceof WP_User && in_array('administrator', $user->roles, true)) {
        return admin_url();
    }
    return home_url('/mans-konts/');
}, 10, 3);

Piespiedu admin valoda (latviski)

Uzspiež WordPress administrācijas paneli vienmēr rādīt latviešu valodā, neatkarīgi no katra lietotāja profilā izvēlētās personīgās valodas (Lietotāji → Tavs profils → Valoda) — noder, ja vēlies, lai visi komandas locekļi redz vienu un to pašu admin saskarni. Vietnes publiskā daļa (front-end) šo filtru neskar, jo is_admin() pārbauda tikai admin paneli.

phpadd_filter('locale', 'wpds_uzspiest_admin_valodu');
add_filter('user_locale', 'wpds_uzspiest_admin_valodu'); // obligāti — bez šī katra lietotāja profila valoda (Lietotāji → Tavs profils) uzvarētu virs šī iestatījuma

function wpds_uzspiest_admin_valodu($valoda) {
    if (is_admin()) {
        return 'lv_LV';
    }
    return $valoda;
}

Šis filtrs tikai norāda, kuru valodu WordPress mēģina lietot — tas nedarbosies, ja latviešu valodas pakotne serverī nav uzstādīta. Ja pēc šī koda admin panelis joprojām rādās angliski, dodies uz Iestatījumi → Vispārīgi → Vietnes valoda un izvēlies "Latviešu", lai WordPress lejupielādētu lv_LV tulkojuma failus (vai uzstādi ar WP-CLI: wp language core install lv_LV). Pēc tam šis filtrs turpinās strādāt automātiski visiem lietotājiem, arī tiem, kam profilā izvēlēta cita valoda.

Admin paneļa & pieteikšanās lapas krāsas

Šeit bieži iesācējs sajauc divas pavisam atšķirīgas lapas: wp-admin panelis (dashboard, redzams pēc pieteikšanās) un wp-login.php (pati pieteikšanās forma, pirms pieteikšanās). Katrai ir sava CSS un savs hooks — piemērs, kas maina vienu, otru vispār neietekmē.

1) Admin paneļa (dashboard) pamata krāsa

Kopš WordPress 5.7 admin panelis linkiem, fokusa iezīmējumiem un primārajām pogām izmanto CSS mainīgos — tos pārrakstot, maina krāsu visur uzreiz, neatkarīgi no lietotāja izvēlētās "Admin Color Scheme".

phpadd_action('admin_head', function() {
    ?>
    <style>
        :root {
            --wp-admin-theme-color: #d94f70;
            --wp-admin-theme-color-darker-10: #c23f5e;
            --wp-admin-theme-color-darker-20: #a8324e;
        }
    </style>
    <?php
});

2) Pieteikšanās lapas (wp-login.php) krāsa

wp-login.php šos CSS mainīgos nemaz nelasa — tai jāizmanto cits hooks (login_enqueue_scripts) un jāmērķē tieši uz lapā esošos selektorus (#nav — "Reģistrēties" / "Aizmirsāt paroli?", #backtoblog — "Atpakaļ uz vietni").

phpadd_action('login_enqueue_scripts', function() {
    ?>
    <style>
        #login #nav a,
        #login #backtoblog a {
            color: #d94f70;
        }
        #login #nav a:hover,
        #login #backtoblog a:hover {
            color: #a8324e;
        }

        /* Neobligāti — arī "Pieteikties" pogas krāsa */
        .wp-core-ui .button-primary {
            background: #d94f70;
            border-color: #a8324e;
        }
        .wp-core-ui .button-primary:hover,
        .wp-core-ui .button-primary:focus {
            background: #c23f5e;
            border-color: #8f2b45;
        }
    </style>
    <?php
});

admin_head neizsaucas vispār wp-login.php lapā — tā ir sava, atsevišķa lapa ārpus admin paneļa, ne tā daļa. Ja liec pirmo piemēru un gaidi, ka mainīsies pieteikšanās lapas krāsa, kods vienkārši nekad neizpildīsies tur, kur skaties — bieži izskatās, it kā "nekas nemainās", lai gan kods faktiski strādā pareizi (dashboard krāsa gan mainījusies).

3) Sekundārās (necaurspīdīgi apvilktās) pogas

WordPress atšķir divus pogu veidus: .button-primary — pilnībā iekrāsota "galvenā" darbība (piem., "Pieteikties"), un parasta .button — bez fona, tikai ar apmali (piem., "Mainīt", "Atcelt"). Tās ir divi atšķirīgi selektori — otrās pogas krāsu --wp-admin-theme-color mainīgais neietekmē, tāpēc tai jāpieraksta sava CSS, neatkarīgi no tā, vai poga atrodas admin panelī vai pieteikšanās lapā.

php// Der gan admin_head (dashboard), gan login_enqueue_scripts (wp-login.php) —
// izvēlies hooku atkarībā no tā, kurā lapā poga atrodas
add_action('admin_head', function() {
    ?>
    <style>
        .wp-core-ui .button:not(.button-primary) {
            color: #d94f70;
            border-color: #d94f70;
        }
        .wp-core-ui .button:not(.button-primary):hover,
        .wp-core-ui .button:not(.button-primary):focus {
            color: #a8324e;
            border-color: #a8324e;
        }
    </style>
    <?php
});

:not(.button-primary) pasargā no tā, lai šis noteikums netīšām nepārrakstītu pirmās apakšsadaļas primāro pogu stilu — abi noteikumi var droši dzīvot vienā un tajā pašā <style> blokā.

4) Pilnāks piemērs — vairāk elementu & pacēluma efekts pogai

Reālā projektā pieteikšanās lapā parasti jāstilizē vairāk nekā tikai divi-trīs elementi — arī privātuma politikas saite (redzama, ja iestatīta Privātuma politikas lapa) un valodas pārslēdzēja poga lapas apakšā (redzama, ja uzstādītas vairākas valodas). Šis piemērs apvieno visu iepriekšējo un pievieno arī nelielu "pacēluma" animāciju pogai, uzbraucot ar peli:

phpadd_action('login_enqueue_scripts', function() {
    ?>
    <style>
        #login #nav a,
        #login #backtoblog a {
            color: #c8b3d0; /* saišu krāsa */
        }
        #login #nav a:hover,
        #login #backtoblog a:hover {
            color: #997ca2; /* saišu krāsa, uzbraucot ar peli */
        }

        /* "Pieteikties" pogas krāsa, forma un pacēluma efekts */
        .wp-core-ui .button-primary {
            background: #1e1b4b !important;
            border-radius: 6px !important;
            border-color: transparent !important;
            color: #ffffff !important;
            transition: transform 0.45s cubic-bezier(0.25, 1, 0.5, 1) !important;
            will-change: transform !important;
        }
        .wp-core-ui .button-primary:hover,
        .wp-core-ui .button-primary:focus {
            transform: translateY(-3px) !important; /* poga "paceļas", uzbraucot ar peli */
            background-color: #34315d !important;
            color: #ffffff !important;
        }

        /* Privātuma politikas saites krāsa */
        .privacy-policy-page-link a {
            color: #c8b3d0 !important;
        }

        /* Valodas pārslēdzēja poga */
        .language-switcher input[type="submit"] {
            color: #c8b3d0 !important;
            border-color: #997ca2 !important;
            background-color: transparent !important;
        }
        .language-switcher input[type="submit"]:hover,
        .language-switcher input[type="submit"]:focus {
            color: #997ca2 !important;
            border-color: #c8b3d0 !important;
        }
    </style>
    <?php
});

Šeit parādās !important pie katras rindas — tas parasti ir "pēdējais līdzeklis" un labas prakses ziņā jāizvairās, bet šeit tas bieži nepieciešams, jo citi spraudņi (piem., sociālās pieteikšanās spraudņi) vai tēma paši ielādē savu CSS ar lielāku specifiskumu (specificity) pieteikšanās lapā. Ja bez !important stils netiek pielietots, tas nozīmē — kaut kas cits to jau pārraksta.

Redaktoram (Editor lomai) — Customizer piekļuve, bet ierobežota

Pēc noklusējuma tikai administratori var atvērt Izskats → Pielāgot (Customizer). Ja vēlies, lai arī Redaktora lomas lietotāji var mainīt logo, krāsas u.tml., bet nevar piekļūt tehniskākām sadaļām (izvēlnes, sīkrīki, pielāgots CSS) — vajadzīgas divas daļas: tiesību piešķiršana un pēc tam ierobežošana.

php// 1) Piešķir Redaktora lomai tiesības atvērt Customizer
add_action('admin_init', 'wpds_atlaut_redaktoram_customizer');
function wpds_atlaut_redaktoram_customizer() {
    $role = get_role('editor');
    if ($role && !$role->has_cap('edit_theme_options')) {
        $role->add_cap('edit_theme_options');
    }
}

// 2) Bet noņem tehniskākās sadaļas, ja lietotājs NAV administrators
add_action('customize_register', 'wpds_ierobezot_customizer_redaktoram', 999);
function wpds_ierobezot_customizer_redaktoram($wp_customize) {
    if (!current_user_can('administrator')) {
        $wp_customize->remove_section('custom_css');
        $wp_customize->remove_panel('nav_menus');
        $wp_customize->remove_panel('widgets');
        $wp_customize->remove_section('static_front_page');
    }
}

Prioritāte 999 otrajā funkcijā ir svarīga — tā izpildās pēc tam, kad WordPress un citi spraudņi jau ir reģistrējuši visas savas Customizer sadaļas, tāpēc ir kas noņemt. Ja izlaidīsi prioritāti, funkcija var izpildīties par agru un daļu sadaļu vēl nemaz nebūs, ko dzēst.

Izraksta (excerpt) garums

Noklusējuma izraksta garums ir 55 vārdi — šis filtrs to pielāgo pēc vajadzības.

phpadd_filter('excerpt_length', function($garums) {
    return 20; // vārdu skaits
});

// Neobligāti — nomaina noklusējuma "[...]" beigās uz kaut ko citu
add_filter('excerpt_more', function() {
    return '…';
});

Pielāgots attēla izmērs

WordPress automātiski ģenerē vairākus attēla izmērus katrai augšupielādei (thumbnail, medium, large) — šis pievieno vēl vienu, savu, izmēru tam pašam mehānismam.

phpadd_action('after_setup_theme', function() {
    // nosaukums, platums, augstums, vai apgriezt (true = precīzi izmēri)
    add_image_size('kartes-attels', 400, 300, true);
});

Lietošana veidnē:

php<?php if (has_post_thumbnail()): ?>
    <?= get_the_post_thumbnail(get_the_ID(), 'kartes-attels') ?>
<?php endif; ?>

Jauns izmērs attiecas tikai uz jaunām augšupielādēm — jau esošajiem attēliem šī izmēra versijas nav. Lai ģenerētu trūkstošos izmērus arī vecajiem attēliem, izmanto spraudni "Regenerate Thumbnails" vai WP-CLI komandu wp media regenerate.

Izslēgt emoji skriptus (veiktspēja)

WordPress pēc noklusējuma katrā lapā ielādē papildu skriptu emoji attēlošanai vecākos pārlūkos — lielākajai daļai vietņu tas nav vajadzīgs un nedaudz palēnina lapu.

phpadd_action('init', function() {
    remove_action('wp_head', 'print_emoji_detection_script', 7);
    remove_action('wp_print_styles', 'print_emoji_styles');
    remove_action('admin_print_scripts', 'print_emoji_detection_script');
    remove_action('admin_print_styles', 'print_emoji_styles');
});

Piespiedu klasiskais redaktors (izslēgt Gutenbergu)

Ja tēma vai spraudņi ir veidoti ar veco, klasisko redaktoru prātā (vai vienkārši negribi blociņu redaktoru), viena rindiņa pilnībā izslēdz Gutenbergu — visiem ierakstu tipiem, visiem lietotājiem.

phpadd_filter('use_block_editor_for_post', '__return_false');

Šis filtrs ietekmē tikai to, vai redaktors atveras kā Gutenbergs vai klasiskais TinyMCE — pati "Classic Editor" spraudņa uzstādīšana nav nepieciešama. Ja vajag izslēgt tikai konkrētam ierakstu tipam, pievieno pārbaudi: if ($post_type === 'produkts') return false; pirms atgriešanas.

Jebkura teksta/frāzes aizstāšana (gettext)

gettext filtrs ļauj pārrakstīt jebkuru tekstu, ko WordPress vai kāds spraudnis izvada caur tulkošanas funkcijām (__(), _e() u.tml.) — pat ja tev nav piekļuves attiecīgā spraudņa kodam. Noder, ja gribi mainīt kāda spraudņa tekstu, nerediģējot pašu spraudni (kas citādi pazustu nākamajā atjauninājumā).

php// Vienkāršs, precīzs viena teksta aizstāšanas gadījums
add_filter('gettext', 'wpds_aizvietot_vienu_frazi', 20, 3);
function wpds_aizvietot_vienu_frazi($tulkotais, $original, $domain) {
    if ($tulkotais === 'E-pasta paroles atiestatīšanas saite') {
        return 'Atiestatīt paroli';
    }
    return $tulkotais;
}

// Vairāku vārdu/frāžu masveida aizstāšana konkrētam spraudnim (piem., WooCommerce)
add_filter('gettext', function($tulkotais, $original, $domain) {
    if ($domain !== 'woocommerce') return $tulkotais; // tikai šī spraudņa teksti

    $aizvietojumi = [
        'Pasūtījums' => 'Pirkums',
        'Pasūtījumi' => 'Pirkumi',
        'pasūtījums' => 'pirkums',
    ];

    return strtr($tulkotais, $aizvietojumi);
}, 20, 3);

Salīdzini pret $tulkotais (jau iztulkoto tekstu), nevis pret $original (angļu oriģinālu) — tā piemērs strādās neatkarīgi no tā, vai vietnei uzstādīta angļu vai latviešu valoda. $domain pārbaude (piem., === 'woocommerce') svarīga, lai netīšām neaizvietotu vienādu vārdu citur, kur tas nozīmē ko citu.

Stripe apmaksas formas valoda

Ja izmanto WooCommerce Stripe Gateway spraudni, apmaksas forma (kartes numura lauks, kļūdu ziņojumi) pēc noklusējuma parādās apmeklētāja pārlūka valodā vai angliski — wc_stripe_params filtrs ļauj to piespiest uz konkrētu valodu.

phpadd_filter('wc_stripe_params', function($params) {
    $params['stripe_locale'] = 'lv';
    return $params;
});

Šis filtrs attiecas tikai uz oficiālo WooCommerce Stripe Gateway spraudņa integrāciju (kas pati ģenerē apmaksas formu tieši veikala lapā ar Stripe.js). Ja projektā izmantots pašrocīgi būvēts Stripe Checkout Session process, kā aprakstīts Integrācijas → Stripe maksājumi, šis filtrs tur neko neietekmē — tur valodu nosaka tieši parametros, ko servera puse nosūta, veidojot sesiju.

Pārbaudi, vai 'lv' ir Stripe atbalstīto lokalizāciju sarakstā (docs.stripe.com/js/appendix/supported_locales) — Stripe periodiski paplašina atbalstīto valodu klāstu. Ja konkrētā valoda vēl netiek atbalstīta, drošāka alternatīva ir 'auto', kas ļauj Stripe pašam noteikt valodu pēc apmeklētāja pārlūka iestatījumiem.
