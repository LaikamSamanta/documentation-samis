Web serveris: kas ir nginx, Apache un PHP-FPM

Kad atver lapu, tev atbild nevis "viens serveris", bet vairākas programmas, kas strādā pa kārtām. Katrai ir sava darba daļa.

Atbilde iet atpakaļ pa to pašu ceļu. Ja viena posma nav vai tas nokrīt, saņem 502/504.

ProgrammaVienkārši sakotKo tā dara
nginxĀtrs "durvju sargs" priekšā.Pieņem visus pieprasījumus, apkalpo  (attēli, CSS, JS) pats, apstrādā , un visu pārējo (PHP)  (reverse proxy).
ApacheVecāks, ļoti elastīgs web serveris.Lasa .htaccess failus (WordPress permalinks, redirekti), apstrādā rewrite noteikumus un nodod PHP pieprasījumus PHP-FPM.
PHP-FPMPHP "strādnieku fabrika".Atsevišķi procesi (workeri), kas . Web serveris tikai nodod tam pieprasījumu un saņem gatavu HTML atpakaļ. FPM = FastCGI Process Manager.

Web serveris (nginx/Apache) pats PHP nesaprot. Tas tikai pieņem pieprasījumu un atdod failu vai nodod PHP-FPM, kas ir tas, kas tiešām "palaiž" .php failu.

PHP-FPM - kā tas strādā

PHP-FPM tur gatavus workerus (procesus). Katrs worker vienā brīdī apkalpo vienu pieprasījumu. Kad visi ir aizņemti, nākamie pieprasījumi gaida rindā.

IestatījumsKo nozīmēPiezīme
pm.max_childrenMaksimālais workeru skaits (= vienlaicīgi apkalpotie PHP pieprasījumi)Cenšas ierobežot ar RAM: pieejamā atmiņa ÷ viena worker atmiņa
pm (static / dynamic / ondemand)Kā tiek veidoti workeri: vienmēr fiksēts skaits / pēc vajadzības līdz maksimumam / tikai kad pienāk pieprasījumsdynamic ir izplatītākais
request_terminate_timeoutPēc cik sekundēm FPM piespiedu kārtā pārtrauc workeriNostrādā arī tad, ja max_execution_time nav
memory_limit (php.ini)Cik RAM drīkst izmantot viens skriptsWordPress parasti 256M

Detalizēti par aprēķinu un iestatīšanu Plesk: PHP lapa → PHP-FPM tuning.
