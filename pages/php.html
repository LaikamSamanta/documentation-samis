memory_limit, execution time, max workeri - kā izvēlēties vērtības pēc RAM

Šie trīs iestatījumi ir savstarpēji saistīti - visi kopā nedrīkst pārsniegt serverim faktiski pieejamo RAM, citādi risks ir OOM (out-of-memory), kas var nogalināt arī MySQL vai citus procesus, ne tikai PHP.

IestatījumsKo daraKā izvēlēties
memory_limitMax RAM, ko drīkst izmantot viens PHP process/skripts.WordPress min. 64M, ar spraudņiem/WooCommerce parasti 256M; smagiem importiem īslaicīgi 512M.
max_execution_timeCik sekundes skripts drīkst darboties, pirms PHP to pārtrauc.30-60s parastām lapām. Neceļ globāli augstu "drošībai" - iestrēdzis skripts tik ilgi tur aizņemtu worker'i.
pm.max_childrenCik PHP-FPM worker procesu drīkst darboties vienlaicīgi (max vienlaicīgi apstrādāto pieprasījumu skaits).Formula: pieejamā RAM priekš PHP-FPM (MB) ÷ vidējais RAM patēriņš uz vienu worker'i (MB) - sk. zemāk, kā izmērīt abus.

pm.max_children × memory_limit ir teorētiskais maksimums, ko PHP-FPM var izēst no RAM, ja visi worker'i vienlaicīgi strādā pie smagiem skriptiem. Ja šis reizinājums pārsniedz serverim faktiski atlikušo RAM (pēc MySQL, Plesk, Nginx/Apache u.c.) - serveris var sākt swapot vai OOM killer sāk nogalināt procesus, ieskaitot, iespējams, datubāzi.

Kā fiziski izmērīt - SSH

bash# cik RAM serverim kopā un cik brīvs
free -h

# cik CPU kodolu (arī ierobežo, cik worker'us jēga likt)
nproc

# kādi php-fpm procesi vispār strādā (nosaukums atkarīgs no PHP versijas)
ps aux | grep php-fpm

# vidējais reālais RAM patēriņš uz vienu php-fpm worker'i (MB)
ps --no-headers -o rss,cmd -C php-fpm8.1 | awk '{sum+=$1; n++} END {print sum/n/1024" MB videji, "n" workeri"}'

# pašreizējais memory_limit (CLI php var atšķirties no web/FPM!)
php -i | grep -i memory_limit

# kurš php.ini/pool fails faktiski ielādēts
php --ini

Kalkulators - ieliec nomērītās vērtības

pm-max-children-calc

Kuri faili konkrēti (Plesk)

FailsKo satur
/var/www/vhosts/system/<domēns>/etc/php.iniKonkrētā domēna memory_limit, max_execution_time u.c. - šo failu Plesk ģenerē, kad maini PHP Settings UI.
/opt/plesk/php/<versija>/etc/php.iniGlobālais/noklusējuma php.ini konkrētai PHP versijai (piem. 8.1) - izmanto tikai tad, ja domēnam nav sava override.
FPM pool fails (pm.max_children)Ceļš atšķiras pēc Plesk/PHP versijas - neuzmini, atrodi to dinamiski (sk. komandas zemāk).
 
bash# atrod konkrētā domēna FPM pool failu (nomaini domēnu)
grep -rl "tavsdomens.lv" /opt/plesk/php/*/etc/php-fpm.d/ 2>/dev/null

# ja neatrod - meklē plašāk visā sistēmā
find / -iname "*.conf" -path "*fpm*" 2>/dev/null | xargs grep -l "tavsdomens.lv" 2>/dev/null

# redzi, kuru konfigurāciju php-fpm serviss faktiski palaiž (servisa nosaukums no iepriekšējās komandas)
systemctl status 'plesk-php*-fpm' 2>/dev/null | grep -i conf

Plesk katram domēnam/PHP versijai parasti taisa savu FPM pool'u - pm.max_children maini caur Websites & Domains → domēns → PHP Settings (ja tur nav lauka - "Additional configuration directives"), nevis rediģē pool failus tieši, jo Plesk tos var pārrakstīt. Ja tomēr rediģē failu pašrocīgi, pēc izmaiņām jārestartē attiecīgais php-fpm serviss (systemctl restart ar to servisa nosaukumu, kas redzams systemctl list-units | grep php-fpm).

Ja hostē vairākus domēnus uz viena servera - katram var būt savs FPM pool ar savu pm.max_children, tāpēc formulai jāskatās uz visu domēnu kopējo maksimālo patēriņu, ne tikai viena.
