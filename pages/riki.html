Rīki

Reāli, strādājoši rīki tieši pārlūkā - bez instalēšanas, bez servera, dati nekur netiek augšupielādēti. Kur vien tas tehniski iespējams (attēlu apstrāde, teksta pārveide u.tml.), tas šeit ir izdarīts kā vizuāls rīks, nevis tikai koda piemērs. Uzdevumiem, kas prasa piekļuvi failu sistēmai vai fona darbību (masveida lejupielāde, mapju sakārtošana, uzraudzība) - skaties Python rīki, jo tos pārlūks tehniski nevar izdarīt.

Attēlu izmērs, formāts & saspiešana

Nomet vienu vai vairākus attēlus zemāk - katram uzreiz redzi rezultāta izmēru, un vari lejupielādēt pa vienam vai visus reizē. Formāta izvēlē pieejams arī WebP (mazāks fails nekā JPEG pie tādas pašas kvalitātes). Viss notiek Tavā pārlūkā (Canvas API) - nekas nekur netiek augšupielādēts.

Nomet vienu vai vairākus attēlus šeit vai izvēlies failus

Ievadi platumu vai augstumu (px) - kamēr ķēdes ikona ir "saslēgta", otrs lauks aprēķinās automātiski pēc pirmā augšupielādētā attēla proporcijām, tāpat kā parastos web rīkos. Nospiežot ikonu, var atslēgt un ievadīt abus laukus neatkarīgi (tad attēls tiek izstiepts/saspiests tieši uz šo izmēru, nevis apgriezts). Ja abi lauki tukši, izmantots "Maks. platums" iestatījums augstāk.

Velc rāmja stūrus, lai mainītu izmēru, vai velc pašu rāmi, lai to pārvietotu.

Vairāki faili

Katrs pievienotais attēls tiek apstrādāts neatkarīgi, ar tiem pašiem platuma/kvalitātes/formāta iestatījumiem - maini iestatījumus vienreiz, tie pielietojas visiem uzreiz.

Apgriešana ar fiksētu proporciju

Katram failam ir poga "Apgriezt" - atver rāmi, ko var vilkt un mainīt izmēru. Izvēlies 1:1 / 4:3 / 16:9 / 9:16, lai rāmja proporcija paliktu fiksēta, vai "Brīvi" jebkurai formai. Apgrieztais attēls aizstāj oriģinālu un tālāk iet cauri parastajai izmēra/formāta apstrādei.

No kāda uz kādu formātu

Katram failam pie nosaukuma redzams, piemēram, "PNG → JPEG" - tas parāda, kādā formātā attēls tika augšupielādēts un kādā formātā tas tiks lejupielādēts pēc apstrādes (atbilstoši izvēlētajam "Formāts" laukam).

Precīzs izmērs (bez apgriešanas)

Papildus "Maks. platums" slīdnim var ievadīt konkrētu platumu un/vai augstumu pikseļos, piemēram, 500×500 - attēls tiek izstiepts/saspiests tieši uz šo izšķirtspēju (ctx.drawImage(img, 0, 0, platums, augstums)), nevis apgriezts. Ja aizpilda tikai vienu lauku, otrs tiek aprēķināts automātiski pēc oriģinālā attēla proporcijām; ja aizpilda abus, izmērs ir tieši tāds, kāds ievadīts (var izstiept, ja proporcijas nesakrīt ar oriģinālu). Tukši lauki nozīmē, ka tiek izmantots "Maks. platums" iestatījums.

WebP formāts

canvas.toBlob(callback, "image/webp", kvalitāte) - atbalstīts visos modernajos pārlūkos. Parasti dod mazāku faila izmēru par JPEG pie vizuāli identiskas kvalitātes.

Kāpēc PNG bez kvalitātes slīdņa

PNG ir bezzudumu formāts - kvalitātes parametru tas neatbalsta, tāpēc slīdnis pazūd, izvēloties PNG. Der attēliem ar caurspīdīgumu vai tekstu/ikonām, kur JPEG/WebP saspiešanas artefakti būtu redzami.

Vienkrāsaina fona noņemšana

Noklikšķini uz fona krāsas attēlā - visi līdzīgas krāsas pikseļi kļūst caurspīdīgi. Godīgi par ierobežojumu: šis nav AI (kā remove.bg) - tas ir krāsu salīdzinājums, tāpēc der produktu foto/logotipiem ar vienmērīgu (piem. baltu vai vienkrāsainu) fonu, bet nestrādā sarežģītiem foniem ar daudz krāsu variāciju.

Nomet attēlu šeit vai izvēlies failu

Noklikšķini uz attēla, lai izvēlētos fona krāsu.

Izvēlētā krāsa:

Kā strādā

Klikšķa vietā nolasa pikseļa RGB krāsu, tad katram attēla pikselim rēķina krāsu attālumu līdz tai (Math.sqrt no R/G/B starpību kvadrātiem) - ja attālums mazāks par toleranci, pikseļa alfa kanālu iestata uz 0 (caurspīdīgs).

Tolerance slīdnis

Zema tolerance - noņem tikai gandrīz identisku krāsu (precīzi, bet var atstāt maliņas). Augsta tolerance - noņem plašāku krāsu diapazonu (var sākt "ēst" arī paša objekta malas, ja tās tuvu fona krāsai).

Kāpēc lejupielāde tikai PNG

Caurspīdīgumam (alfa kanālam) nepieciešams formāts, kas to atbalsta - PNG ir drošākā, universālākā izvēle (JPEG caurspīdīgumu neatbalsta vispār).

Krāsu rīks (HEX / RGB / RGBA)

Ievadi krāsu jebkurā formātā - HEX, atsevišķie R/G/B/A kanāli vai vizuālais izvēlētājs - visi pārējie lauki pārrēķinās uzreiz. Zemāk arī redzi, kāds ir tuvākais zināmais CSS krāsas nosaukums šai HEX vērtībai (piem., ievadot #ff6347, redzēsi "tomato").

Tuvākā zināmā krāsa: -

rgb(109, 40, 217)
rgba(109, 40, 217, 1)

Divvirziena sinhronizācija

Maini jebkuru lauku - HEX tekstu, R/G/B/A skaitļus vai krāsu izvēlētāju - un visi pārējie atjaunojas uzreiz. HEX atbalsta gan 3, gan 6, gan 8 ciparu formu (#f00, #ff0000, #ff0000ff ar alfa kanālu).

Kā atrasta tuvākā krāsa

Katram no ~148 standarta CSS krāsu nosaukumiem (tomato, cornflowerblue u.c.) pārlūks pats atrisina precīzo RGB vērtību (uzstādot canvas.fillStyle = nosaukums un nolasot rezultātu atpakaļ) - tas garantē pareizību bez manuāli ierakstītas tabulas. Tad starp visām meklē mazāko RGB attālumu (Math.sqrt no R/G/B starpību kvadrātu summas), tāpat kā fona noņemšanas rīkā augstāk.

Kāpēc RGBA atsevišķi no RGB

rgb() CSS ierakstā nozīmē pilnībā necaurspīdīgu krāsu. rgba() pievieno ceturto - alfa (0 = pilnībā caurspīdīgs, 1 = necaurspīdīgs) - noderīgs, piemēram, pusgruntu overlay slāņiem vai hover efektiem.

"Paņemt no ekrāna" (Eyedropper)

Izmanto pārlūka iebūvēto EyeDropper API - noklikšķinot uz pogas, var izvēlēties jebkuru pikseli EKRĀNĀ (arī ārpus šīs lapas, citā logā), un tā krāsa tiek ielasīta rīkā. Godīgi par ierobežojumu: šo API pašlaik atbalsta tikai Chrome/Edge (un citi Chromium pārlūki) - Firefox un Safari to neatbalsta, tāpēc poga parādās tikai pārlūkos, kur tā tiešām strādā.

JSON formatētājs

Ielīmē JSON zemāk - "Formatēt" sakārto to lasāmā veidā ar atkāpēm, "Saspiest" izņem visas liekās atstarpes. Ja JSON ir bojāts, uzreiz redzēsi, kurā rindā un kolonnā ir kļūda.

Rezultāts

Kā strādā formatēšana

JSON.parse() pārbauda un pārveido tekstu par JS objektu, tad JSON.stringify(objekts, null, 2) to atkal pārvērš tekstā ar 2 atstarpju atkāpēm katrā līmenī.

Kļūdas vietas atrašana

Daudzos gadījumos pārlūka JSON.parse kļūdas ziņojumā ir simbola pozīcija tekstā (piem., "position 45") - rīks to pārvērš rindas/kolonnas numurā, saskaitot rindu pārtraukumus līdz tai pozīcijai. Dažām kļūdām (piem., nederīgai vērtībai) pārlūks pozīciju nenorāda vispār - tad redzēsi tikai paša pārlūka ziņojumu.

Kāpēc saspiešana noder

Formatēts JSON ir lasāmāks izstrādei, bet saspiests (bez atstarpēm) ir mazāks pārraidei - tāpēc API atbildes parasti nāk saspiestas, bet dev rīkos tās formatē lasīšanai.

Base64 / URL kodēšana

Kodēšana pārveido tekstu drošam pārsūtīšanas/glabāšanas formātam - tā nav šifrēšana (jebkurš var to atkodēt atpakaļ, nav vajadzīga parole). Base64 bieži izmanto, iegulstot mazus datus tekstā; URL kodēšana - liekot speciālus simbolus (piem., atstarpes, &) URL adresē.

Rezultāts

UTF-8 atbalsts

Pārlūka btoa()/atob() pa vecam strādā tikai ar Latin1 simboliem un salūzt uz garumzīmēm (ā, š, ē). Rīks vispirms pārveido tekstu par UTF-8 baitiem ar TextEncoder, tad kodē tos - tāpēc latviešu teksts strādā pareizi.

Base64 vs URL kodēšana

Base64 pārveido JEBKURUS baitus par burtu/ciparu/+/= virkni (der binārajiem datiem). URL kodēšana (encodeURIComponent) aizvieto tikai īpašos simbolus ar %XX secēm, atstājot pārējo tekstu lasāmu.

Kāpēc tas nav drošs paroļu glabāšanai

Base64 kodējumu var atkodēt jebkurš, kam ir teksts - tā nav šifrēšana vai hash. Paroles glabā ar hash (skat. rīku zemāk vai Drošības kategoriju), ne Base64.

UUID ģenerators

Ģenerē nejaušus UUID v4 identifikatorus - noder datubāzu rindu ID, sesiju tokeniem, failu nosaukumiem u.c., kur vajag garantēti unikālu vērtību bez centrālas skaitīšanas.

crypto.randomUUID()

Modernie pārlūki UUID v4 ģenerē tieši - crypto.randomUUID() - kriptogrāfiski droši nejaušs, bez papildu bibliotēkām.

Kāpēc "v4"

UUID versijas nosaka, kā tas veidots - v4 nozīmē "gandrīz pilnībā nejaušs" (122 nejauši biti no 128). Sadursmes iespējamība ir tik zema, ka praksē to var uzskatīt par garantēti unikālu.

Unix laika konvertētājs

Sekundes vai milisekundes?

JavaScript Date iekšēji strādā ar MILISEKUNDĒM (Date.now()), bet lielākā daļa API/datubāžu izmanto SEKUNDES. Rīks pats nosaka, kuru vienību esi ievadījis, pēc skaitļa garuma.

Laika josla

<input type="datetime-local"> rāda/pieņem laiku TAVĀ pārlūka laika joslā, bet Unix timestamp vienmēr ir absolūts (UTC) - konvertācija to ņem vērā automātiski.

Regex testeris

Ievadi regulāro izteiksmi un testa tekstu - sakritības tiek iekrāsotas tieši tekstā, un zemāk redzi katras sakritības detaļas (arī uztvertās grupas, ja tādas ir).

/ /

Ievadi regulāro izteiksmi, lai sāktu.

Karodziņi (flags)

g - visas sakritības (nevis tikai pirmā). i - neievēro reģistru. m - ^/$ strādā katrā rindā atsevišķi. s - . sakrīt arī ar jaunrindu.

Uztvertās grupas

Iekavas (...) regex izteiksmē izveido "uztverto grupu" - katras sakritības daļu var izmantot atsevišķi (piem., datumā (\d{4})-(\d{2})-(\d{2}) uztver gadu, mēnesi, dienu atsevišķi).

Kāpēc reizēm regex "nesakrīt"

Bieža kļūda - aizmirsts g karodziņš (tad atrod tikai pirmo sakritību), vai speciālie simboli (. * + ? ( ) [ ] { } ^ $ |) nav pareizi "escapoti" ar \, ja tos grib meklēt burtiski.

JWT dekodētājs

Ielīmē JWT (JSON Web Token) - rīks izkodē un parāda header un payload daļas lasāmā JSON formātā. Godīgi par ierobežojumu: šis TIKAI dekodē (base64url dekodēšana, ne šifrēšana) - tas NEVERIFICĒ parakstu, tāpēc jebkurš var izlasīt saturu, bet tas neapstiprina, ka tokens ir īsts/neizmainīts. Parakstu var pārbaudīt tikai ar servera slepeno atslēgu.

Header
Payload

Kā veidots JWT

Trīs base64url daļas, atdalītas ar punktu: header.payload.signature. Header un payload ir vienkārši JSON, kodēts base64url (nevis šifrēts!) - tos var izlasīt jebkurš bez atslēgas.

Kāpēc paraksts nav pārbaudīts

Paraksta pārbaudei vajadzīga servera slepenā atslēga (HMAC) vai publiskā atslēga (RSA/ECDSA) - tā NEKAD nedrīkst nonākt pārlūkā/klienta pusē, tāpēc šis rīks var tikai parādīt SATURU, ne apstiprināt tā īstumu.

exp / iat / nbf

Standarta laika lauki payload: iat - izdošanas laiks, exp - derīguma beigas, nbf - derīgs no. Visi ir Unix timestamp (sekundēs) - rīks tos parāda arī cilvēkam lasāmā formātā.

Hash ģenerators

Aprēķina teksta kriptogrāfisko hash (kontrolsummu) ar pārlūka iebūvēto Web Crypto API. Hash ir vienvirziena - no rezultāta nevar atgūt oriģinālo tekstu.

Kāpēc nav MD5

Pārlūka iebūvētais crypto.subtle.digest MD5 neatbalsta vispār (tas jau sen uzskatīts par kriptogrāfiski salauztu) - tikai SHA-1 (arī novecojis, bet vēl sastopams) un SHA-2 saime (256/384/512, šobrīd drošs standarts).

Kā strādā

crypto.subtle.digest("SHA-256", baiti) atgriež hash kā ArrayBuffer - to pārvērš par hex virkni, katru baitu formatējot kā 2 hex ciparus.

Hash vs šifrēšana

Hash NAV atgriezenisks (nevar "atšifrēt" atpakaļ) - der paroļu glabāšanai un datu integritātes pārbaudei. Šifrēšana IR atgriezeniska ar pareizo atslēgu - der datu slēpšanai. Vairāk par to skaties Drošības kategorijā.

Gradient ģenerators

Vizuāli pielāgo krāsu pāreju un uzreiz dabū gatavu CSS kodu kopēšanai.

CSS

Gradient krāsu pieturas

Katra krāsu "pietura" (stop) sastāv no krāsas un procentuālas pozīcijas (0-100%) - starp pieturām pārlūks pats izrēķina gludu pāreju.

Lineārs vs radiāls

Lineārs iet taisnā līnijā konkrētā leņķī (0° = no apakšas uz augšu, 90° = no kreisās uz labo). Radiāls izplešas no centra uz āru riņķa veidā - leņķis tam neattiecas.

Box-shadow ģenerators

Vizuāli pielāgo ēnu un uzreiz dabū gatavu CSS kodu kopēšanai.

CSS

Box-shadow parametri

box-shadow: X Y izplūdums izplešanās krāsa; - X/Y nobīda ēnu no elementa, izplūdums to izpludina, izplešanās palielina/samazina ēnas izmēru pirms izplūduma.

inset

Parasti box-shadow "izceļas" ārpus elementa malas. inset pārvērš to par IEKŠĒJU ēnu - noder, piemēram, iespiestas (pressed) pogas vai iedobuma efektam.
