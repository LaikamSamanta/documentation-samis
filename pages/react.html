Sākums React

React

Pilns iesācēja ceļvedis React bibliotēkai - komponenti, hooks, formas, maršrutēšana, testēšana un veiktspēja. Visi piemēri pārbaudīti reālā Vite + React 19 projektā, pārlūkā, ar reālu API izsaukumu.

Kas ir React?

React ir JavaScript bibliotēka lietotāja saskarnes (UI) veidošanai no atkārtoti lietojamiem komponentiem. Ja jau redzēji īsu ievadu JavaScript kategorijā - šeit turpinām krietni dziļāk: hooks, maršrutēšana, formas, testēšana un veiktspēja.

Deklaratīvs stils

Apraksti, KĀ UI izskatās PIE KONKRĒTA stāvokļa - React pats izlemj, kā efektīvi atjaunināt reālo DOM, nevis manuāli katru soli (appendChild, classList.add...).

Komponenti kā funkcijas

Katrs komponents ir parasta JavaScript funkcija, kas atgriež JSX - var to izsaukt, padot tam parametrus (props), veidot no tā jaunus komponentus.

Kad izvēlēties React

Lietotnēm ar daudz mainīga, savstarpēji saistīta stāvokļa (dashboard, formas ar validāciju, reāllaika atjauninājumi) - vienkāršai statiskai lapai bieži pietiek ar tīru JavaScript.

Šī dokumentācija balstās uz React 19 un funkciju komponentiem ar hooks - vecāki tutoriāli (pirms 2019) bieži rāda klases un this.setState. Klases komponenti joprojām strādā, bet jaunam kodam gandrīz vienmēr izmanto funkciju komponentus.

Projekta uzstādīšana (Vite)

Vite ir šobrīd ātrākais un vienkāršākais veids, kā sākt jaunu React projektu - ātrs dev serveris ar tūlītēju atjaunināšanos (HMR), skat. arī Vite JavaScript kategorijā.

bashnpm create vite@latest mans-projekts -- --template react
cd mans-projekts

npm run dev
# → http://localhost:5173

Svarīgākās mapes/faili jaunā projektā:

Komponenti & JSX

JSX ir HTML izskatoša sintakse tieši JavaScript kodā - pārlūks to neizprot tieši, tāpēc Vite/build process to pārvērš parastā React.createElement() izsaukumā.

jsxfunction Sveiciens() {
    return (
        <div>
            <h1>Sveiki, pasaule!</h1>
            <p>Šis ir mans pirmais komponents.</p>
        </div>
    );
}

export default Sveiciens;

Viena saknes elements

JSX jāatgriež TIKAI viens elements - vairākus "ietin" <div> vai tukšā <>...</> (Fragment), kas neveido papildu DOM mezglu.

{ } iekavas

Jebkurš JavaScript izteiksme JSX iekšā jāliek figūriekavās - {1 + 1} izvadīs "2".

className, ne class

class ir rezervēts JavaScript vārds - JSX izmanto className tam pašam CSS klases atribūtam.

Props

Props ir dati, ko vecāka komponents padod bērna komponentam - kā funkcijas argumenti, bet HTML atribūtu sintaksē. Komponents props NEDRĪKST mainīt pats - tie ir "read-only" no bērna puses.

jsxfunction Lietotajs({ vards, vecums }) {
    return <p>{vards} ({vecums} gadi)</p>;
}

// Lietošana:
<Lietotajs vards="Anna" vecums={28} />

{ '{ vards, vecums }' } parametros ir "destructuring" - īsceļš, kas izņem konkrētus laukus tieši no props objekta. Bez tā rakstītu function Lietotajs(props) { return <p>{props.vards}</p>; } - abi varianti strādā identiski.

State (useState)

State ir dati, kas komponentam "pieder" un var mainīties laika gaitā - atšķirībā no props, komponents PATS kontrolē savu state.

jsximport { useState } from 'react';

function Counter() {
    const [skaits, setSkaits] = useState(0); // [vērtība, funkcija to mainīt]

    return (
        <div>
            <p>Skaits: {skaits}</p>
            <button onClick={() => setSkaits(skaits + 1)}>Pieskaitīt</button>
        </div>
    );
}

Komponents ir tikai funkcija, kas atgriež "kā UI izskatās TAGAD" - setSkaits neizmaina mainīgo klasiskā nozīmē, tā liek React ATKĀRTOTI izsaukt visu funkciju ar jauno vērtību.

Nekad nemaini state tieši (skaits++ vai masīva .push() uz state masīvu) - React nepamana šādas izmaiņas un komponents NEpārrenderējas. Vienmēr izmanto set funkciju ar JAUNU vērtību/objektu/masīvu.

useEffect

useEffect palaiž kodu PĒC renderēšanas - der "blakusparādībām" (side effects), kas nav pati renderēšana: API izsaukumi, event listeneri, taimeri, manuāla DOM piekļuve.

jsximport { useEffect, useState } from 'react';

function LogaPlatums() {
    const [platums, setPlatums] = useState(window.innerWidth);

    useEffect(() => {
        function handleResize() {
            setPlatums(window.innerWidth);
        }
        window.addEventListener('resize', handleResize);

        // "Cleanup" funkcija - izpildās PIRMS nākamā efekta UN komponenta izņemšanas
        return () => window.removeEventListener('resize', handleResize);
    }, []); // tukšs masīvs = izpildās TIKAI vienreiz, pēc pirmās renderēšanas

    return <p>Loga platums: {platums}px</p>;
}

Atkarību masīvs []

Tukšs = izpildās vienreiz. Ar mainīgajiem [id] = izpildās katru reizi, kad id mainās. Bez masīva vispār = izpildās PĒC KATRAS renderēšanas.

Cleanup funkcija

Atgrieztā funkcija no useEffect - noņem event listenerus/taimerus PIRMS efekts palaižas no jauna, lai neuzkrātos vairāki vienlaicīgi listeneri.

Biežākā kļūda

Aizmirsts atkarību masīvs izraisa BEZGALĪGU ciklu, ja efekts pats maina savu atkarību - useEffect(() => setSkaits(skaits + 1)) bez [] renderē bezgalīgi.

useRef

useRef saglabā vērtību starp renderēšanām, BEZ atkārtotas renderēšanas, kad tā mainās - der DOM elementu tiešai piekļuvei vai vērtībām, kam nav jāietekmē UI.

jsximport { useRef } from 'react';

function FokussInput() {
    const inputRef = useRef(null);

    function focusInput() {
        inputRef.current.focus(); // tiešs piekļuve reālajam DOM <input> elementam
    }

    return (
        <>
            <input ref={inputRef} type="text" />
            <button onClick={focusInput}>Fokusēt lauku</button>
        </>
    );
}

useState vs useRef: mainot useState vērtību, komponents PĀRRENDERĒJAS. Mainot useRef.current, NEKAS neatjauninās ekrānā automātiski - tas ir tieši šī hook mērķis (skaitītāji, taimeru ID, iepriekšējā vērtība), nevis dati, kas jārāda UI.

useMemo & useCallback

Abi der veiktspējas optimizācijai - izvairās no dārgu aprēķinu/funkciju pārveidošanas KATRĀ renderēšanā, ja tam nav iemesla.

jsximport { useCallback, useMemo, useState } from 'react';

function AugluSaraksts() {
    const [query, setQuery] = useState('');
    const [count, setCount] = useState(0); // nesaistīts stāvoklis
    const items = ['Ābols', 'Banāns', 'Ķirsis'];

    // Pārrēķina TIKAI, kad query mainās - NEVIS pie katras count izmaiņas
    const filtered = useMemo(
        () => items.filter(i => i.toLowerCase().includes(query.toLowerCase())),
        [query]
    );

    // Tā pati funkcijas REFERENCE saglabājas starp renderēšanām - der, ja padod bērna komponentam ar React.memo
    const handleChange = useCallback(e => setQuery(e.target.value), []);

    return (
        <>
            <input value={query} onChange={handleChange} />
            <button onClick={() => setCount(c => c + 1)}>Nesaistīts: {count}</button>
            <ul>{filtered.map(i => <li key={i}>{i}</li>)}</ul>
        </>
    );
}

Pārbaudīts reāli - klikšķinot "Nesaistīts" pogu (maina count, ne query), filtrēšanas funkcija NETIEK izsaukta atkārtoti. useMemo/useCallback nav vajadzīgi VISUR - der tikai, kad aprēķins tiešām dārgs vai funkcija iet uz bērna komponentu, kas pats optimizēts ar React.memo. Pārmērīga lietošana pievieno sarežģītību bez reālas priekšrocības.

Pielāgoti hooks

Pielāgots hook ir parasta funkcija, kuras nosaukums sākas ar use un kura iekšā izmanto citus hooks - ļauj atkārtoti lietot loģiku (nevis UI) starp komponentiem.

jsx// hooks/useLocalStorage.js
import { useEffect, useState } from 'react';

function useLocalStorage(key, defaultValue) {
    const [value, setValue] = useState(() => {
        const saved = localStorage.getItem(key);
        return saved !== null ? JSON.parse(saved) : defaultValue;
    });

    useEffect(() => {
        localStorage.setItem(key, JSON.stringify(value));
    }, [key, value]);

    return [value, setValue]; // tieši tāda pati "forma" kā useState
}

export default useLocalStorage;
jsx// Lietošana - identiski kā useState, bet ar automātisku saglabāšanu
const [vards, setVards] = useLocalStorage('lietotaja-vards', '');

Pārbaudīts reāli - vērtība saglabājas localStorage UN paliek pēc pilnas lapas pārlādes, jo useState sākotnējā vērtība nolasa to atpakaļ no localStorage. "use" prefikss nav tikai konvencija - React ar to atpazīst, ka funkcija DRĪKST izsaukt citus hooks iekšā.

useContext

Context ļauj padot datus TIEŠI jebkuram pēcnācēja komponentam, neejot cauri katrai starpposma komponentei ar props ("prop drilling").

jsximport { createContext, useContext, useState } from 'react';

const ThemeContext = createContext(null);

export function ThemeProvider({ children }) {
    const [theme, setTheme] = useState('light');
    const toggle = () => setTheme(t => (t === 'light' ? 'dark' : 'light'));

    return (
        <ThemeContext.Provider value={{ theme, toggle }}>
            {children}
        </ThemeContext.Provider>
    );
}

export function useTheme() {
    return useContext(ThemeContext);
}
jsx// Jebkurā, patvaļīgi dziļā bērna komponentā - BEZ props cauri visai ķēdei:
function ThemedButton() {
    const { theme, toggle } = useTheme();
    return <button onClick={toggle}>Tēma: {theme}</button>;
}

ThemedButton STRĀDĀ TIKAI, ja tas atrodas kaut kur iekš <ThemeProvider> - ārpus tā useContext atgriež null. Reālā kodā useTheme parasti pārbauda šo un izmet skaidru kļūdu, nevis klusi salūzt vēlāk.

Nosacīta renderēšana

JSX nav speciālas @if direktīvas (atšķirībā no Blade) - lieto tīru JavaScript loģiku tieši figūriekavu iekšā.

jsx// Ternārais operators - der, kad ir DIVAS alternatīvas
{items.length > 0 ? <p>Ir {items.length} preces</p> : <p>Saraksts tukšs</p>}

// && - der, kad rāda TIKAI, ja nosacījums patiess (nav "citādi" gadījuma)
{errors.length > 0 && <div className="error">Ir kļūdas!</div>}

// Agrīna atgriešanās - der, kad viens stāvoklis aizstāj VISU komponentu
if (loading) return <p>Ielādē...</p>;

{count && <p>...</p>} ar count = 0 izvada uz ekrāna burtisko "0", nevis neko - && atgriež pirmo "falsy" vērtību, un 0 ir derīgs JSX bērns. Drošāk: {count > 0 && <p>...</p>}.

Saraksti & keys

Masīvu renderē ar .map() - katram elementam OBLIGĀTI jāpiešķir unikāls key, lai React zinātu, kurš elements ir kurš starp renderēšanām.

jsxconst preces = ['Piens', 'Maize', 'Olas'];

<ul>
    {preces.map(prece => <li key={prece}>{prece}</li>)}
</ul>

// Ar objektiem - key parasti unikāls ID no datubāzes, NE indekss
{lietotaji.map(l => <LietotajaKarte key={l.id} lietotajs={l} />)}

key={index} (masīva pozīcija) šķiet vienkāršākais risinājums, bet salūzt, ja saraksts var mainīt secību/izdzēst vidū - React tad var sajaukt, kurš state pieder kuram elementam. Lieto masīva indeksu kā key TIKAI, ja saraksts nekad nemainās (statisks, tikai pievieno beigās).

Formas & controlled inputs

"Controlled" input nozīmē - lauka vērtība VIENMĒR nāk no React state, ne no paša DOM elementa - React ir "vienīgais patiesības avots".

jsxfunction PieteiksanasForma() {
    const [epasts, setEpasts] = useState('');

    function handleSubmit(e) {
        e.preventDefault(); // aptur pārlūka noklusējuma pilnu lapas pārlādi
        console.log('Nosūtīts:', epasts);
    }

    return (
        <form onSubmit={handleSubmit}>
            <input
                type="email"
                value={epasts}
                onChange={e => setEpasts(e.target.value)}
                required
            />
            <button type="submit">Pieteikties</button>
        </form>
    );
}

Ja value={epasts} ir norādīts BEZ onChange, lauks kļūst "read-only" un lietotājs vispār nevar rakstīt - pārlūks pat parāda brīdinājumu konsolē. Vienmēr abi kopā: value (kas rādāms) UN onChange (kā tas mainās).

Notikumu apstrāde

React notikumu nosaukumi ir camelCase (onClick, ne onclick) un pieņem FUNKCIJU, nevis string, kā parastā HTML atribūtā.

jsx// Pareizi - padod funkcijas REFERENCI, izpildīsies TIKAI pie klikšķa
<button onClick={handleClick}>Klikšķini</button>

// Pareizi - inline arrow funkcija, der, ja jāpadod parametrs
<button onClick={() => dzestPreci(prece.id)}>Dzēst</button>

// NEPAREIZI - izpildās UZREIZ renderēšanas laikā, ne pie klikšķa!
<button onClick={handleClick()}>Klikšķini</button>

onClick={handleClick()} (ar iekavām) izsauc funkciju UZREIZ, kad JSX renderējas, un padod TĀS REZULTĀTU kā onClick vērtību - gandrīz vienmēr tas nav gribētais. Iekavas pievieno tikai, ja apzināti veido jaunu funkciju (() => ...), kas izsauks oriģinālo VĒLĀK.

Komponentu kompozīcija

children ir īpašs prop - viss, kas ierakstīts starp komponenta atverošo un aizverošo tagu, nonāk tur automātiski.

jsxfunction Card({ title, children }) {
    return (
        <div className="card">
            <h3>{title}</h3>
            <div>{children}</div>
        </div>
    );
}

// Lietošana - Card pats nezina, KAS tieši būs iekšā:
<Card title="Piemēra karte">
    <p>Šis ir children saturs.</p>
    <button>Poga arī der</button>
</Card>

Kompozīcija (mazi, apvienojami komponenti caur children) parasti der labāk nekā milzīgs komponents ar desmit props, kas kontrolē katru iespējamo variantu - Card šeit nav "jāzin" par pogām, tekstiem vai attēliem, kas tajā var parādīties.

Fetch/API izsaukumi

Datu ielāde no API notiek useEffect iekšā - ar trim stāvokļiem, kas jāapstrādā: ielādē, kļūda, veiksmīgi dati.

jsxfunction PostList() {
    const [posts, setPosts] = useState([]);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
        let cancelled = false;

        fetch('https://api.example.com/posts')
            .then(res => {
                if (!res.ok) throw new Error('Servera kļūda');
                return res.json();
            })
            .then(data => { if (!cancelled) setPosts(data); })
            .catch(err => { if (!cancelled) setError(err.message); })
            .finally(() => { if (!cancelled) setLoading(false); });

        return () => { cancelled = true; }; // pasargā no state maiņas UZ JAU IZŅEMTA komponenta
    }, []);

    if (loading) return <p>Ielādē...</p>;
    if (error) return <p>Kļūda: {error}</p>;

    return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}

Pārbaudīts reāli ar īstu API izsaukumu (jsonplaceholder.typicode.com) - cancelled mainīgais pasargā no biežas kļūdas: ja komponents tiek izņemts no ekrāna PIRMS fetch paspēj atbildēt, setPosts izsaukums uz jau neeksistējošu komponentu izmestu React brīdinājumu par "memory leak".

React Router

React pats nesatur maršrutēšanu - react-router-dom ir oficiālā, visbiežāk lietotā bibliotēka vairāku "lapu" SPA lietotnēm.

bashnpm install react-router-dom

function PostPage() {

Error Boundaries

Error Boundary noķer JavaScript kļūdas jebkur bērnu komponentu kokā un rāda rezerves UI, nevis sabojā VISU lietotni baltā ekrānā.

jsximport { Component } from 'react';

class ErrorBoundary extends Component {
    state = { hasError: false };

    static getDerivedStateFromError() {
        return { hasError: true };
    }

    componentDidCatch(error, info) {
        console.error('Noķerta kļūda:', error, info);
    }

    render() {
        if (this.state.hasError) {
            return <p>Kaut kas nogāja greizi šajā daļā.</p>;
        }
        return this.props.children;
    }
}

// Lietošana - ietin RISKANTO daļu, ne visu lietotni uzreiz:
<ErrorBoundary>
    <RiskantaisKomponents />
</ErrorBoundary>

Error Boundary DRĪKST rakstīt tikai kā klases komponentu - hooks (funkciju komponenti) šobrīd nesatur ekvivalentu componentDidCatch/getDerivedStateFromError. Tas arī NEnoķer kļūdas event handleros (piem., onClick iekšā) - tur joprojām vajag parastu try/catch.

Lazy loading & code splitting

React.lazy ielādē komponenta kodu TIKAI TAD, kad tas tiešām vajadzīgs - samazina sākotnējo JS pakotnes izmēru lielām lietotnēm ar retāk lietotām lapām/paneļiem.

jsximport { lazy, Suspense, useState } from 'react';

// Šis import() NENOTIEK uzreiz - tikai tad, kad komponents tiešām renderēsies
const AdminPanelis = lazy(() => import('./AdminPanelis'));

function App() {
    const [rada, setRada] = useState(false);

    return (
        <>
            <button onClick={() => setRada(true)}>Atvērt admin paneli</button>
            {rada && (
                <Suspense fallback={<p>Ielādē...</p>}>
                    <AdminPanelis />
                </Suspense>
            )}
        </>
    );
}

Pārbaudīts reāli (dev servera tīkla pieprasījumos) - komponenta fails tiek pieprasīts TIEŠI tajā brīdī, kad poga tiek nospiesta, nevis lapas ielādes laikā. Produkcijas build (npm run build) šo automātiski pārvērš par atsevišķu, mazāku JS failu (chunk), ko pārlūks lejupielādē pēc pieprasījuma.

TypeScript ar React

TypeScript pievieno tipu pārbaudi React komponentiem - īpaši noderīgi props definēšanai, lai kļūda ("aizmirsu obligātu prop") parādās uzreiz IDE, nevis tikai izpildot kodu (skat. arī TypeScript JS kategorijā vispārīgam pamatam).

State pārvaldība lielām lietotnēm

Iebūvētais useState/useContext pietiek lielākajai daļai projektu - specializētas bibliotēkas der TIKAI, kad state kļūst tiešām sarežģīts un koplietots daudzviet.

useState + useContext

Noklusējuma izvēle. Der lielākajai daļai lietotņu - papildu bibliotēka bieži nozīmē sarežģītību bez reālas priekšrocības.

Zustand

Minimālistiska, populāra alternatīva - state veikals bez konteksta providera "iesaiņošanas", maz koda.

Redux Toolkit

Struktūrētāks, ar stingrākiem noteikumiem (immutable updates, actions) - der lielām komandām/lietotnēm, kur paredzamība svarīgāka par mazu koda apjomu.

Bieža pazīme, ka useContext vairs nepietiek: Provider komponents pats kļūst par simtiem rindu garu "dievu objektu", vai katra maza state izmaiņa pārrenderē pusi lietotnes. Tad der apsvērt Zustand/Redux - nevis sākt ar tiem "gadījumā, ja vajadzēs".

Būvēšana & izvietošana

React SPA lietotne pēc būvēšanas kļūst par statiskiem failiem (HTML/CSS/JS) - der jebkuram statisko failu hostingam, bez PHP/Node servera vajadzības (atšķirībā no Laravel deploy).

bashnpm run build
# → izveido dist/ mapi ar gataviem, optimizētiem failiem
npm run preview
# → lokāli pārbauda produkcijas build, pirms izvieto

Ja lietotne izmanto React Router, servera konfigurācijai jānorāda "fallback" uz index.html VISIEM ceļiem, kas nav reāls fails - pretējā gadījumā tiešā URL atvēršana (nevis klikšķis lietotnē) dod servera 404, kaut arī tas pats ceļš klikšķinot strādā.
