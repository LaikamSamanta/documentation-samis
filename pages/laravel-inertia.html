Inertia.js - kā tas strādā

Laravel + React bez API un bez frontend router: kontrolieris atgriež komponenti + datus, Inertia klikšķus dara ar XHR.

Atbilde vienmēr ir viens "page objekts". Ja pēc deploy mainās assetu version, GET pieprasījumam serveris atbild 409 + X-Inertia-Location un notiek vienreizēja pilna pārlāde.

json{ "component": "Product",            // kuru lapu rādīt
  "props": { "product": {...}, "auth": {...}, "errors": {} },
  "url": "/product/5", "version": "c32b8e..." }

Recepte: pievienot kolonnu esošai tabulai

Piemērs: tabulai products vajag jaunu lauku color. Nedrīkst rediģēt veco create_products_table migrāciju - tā jau ir izpildīta. Vienmēr jauna migrācija.

Jaunā kolonna uz frontendu nonāk pati (Product::get() atgriež visas kolonnas) - jāpieliek tikai validācija, saglabāšana un UI.

1. Migrācija

bashphp artisan make:migration add_color_to_products_table --table=products
php artisan migrate
phppublic function up(): void
{
    Schema::table('products', function (Blueprint $table) {
        // nullable/default OBLIGĀTI - tabulā jau ir ieraksti
        $table->string('color')->nullable()->after('title');
    });
}

public function down(): void
{
    Schema::table('products', function (Blueprint $table) {
        $table->dropColumn('color');   // nedrīkst palikt tukšs - citādi rollback neko nedara
    });
}
VajagMigrācijā
Skaitlis ar noklusējumu (kā status)$table->integer('status')->default(1);
Unikāls (kā sku)$table->unique('sku'); · down: $table->dropUnique(['sku']);
Ārējā atslēga$table->foreignId('brand_id')->nullable()->constrained();
Pārsaukt / mainīt tipu$table->renameColumn('a','b'); · $table->string('x', 100)->change();
Atcelt pēdējo migrācijuphp artisan migrate:rollback --step=1

2. Kontrolieris - validācija un saglabāšana (store un update)

    'title' => 'required',

    // unikālam laukam update gadījumā jāizlaiž pašam ierakstam:

Ja saglabā ar Product::create($request->all()) vai ->update([...]), kolonna jāpieraksta modelī: protected $fillable = ['title', 'color', ...];. Ja saglabā ar $product->color = ...; save() - nevajag.

Aizsargāt /admin/* ar savu middleware

Projektā login pārbauda $user->role == 'admin', bet pašus maršrutus servera pusē nekas neaizsargā - pārbaude notiek tikai frontendā (/admin/me). Pareizi: bloķēt jau serverī.

1) Izveido

bashphp artisan make:middleware EnsureAdmin
phppublic function handle(Request $request, Closure $next)
{
    $user = $request->user();

    if (! $user || $user->role !== 'admin') {
        return $request->expectsJson()
            ? response()->json(['status' => 401], 401)
            : redirect('/admin/login');
    }

    return $next($request);
}

2) Reģistrē - bootstrap/app.php

php$middleware->alias([
    'admin' => EnsureAdmin::class,
]);

3) Pieliek maršrutiem - routes/web.php

phpRoute::middleware('admin')->group(function () {
    Route::get('/admin/categories', ...);
    Route::resource('admin/categories', ...);
    // visi admin maršruti šeit iekšā
});
// /admin/login paliek ārpus grupas!

Vienkāršākais variants bez sava middleware: Route::middleware('auth') + $middleware->redirectGuestsTo('/admin/login') - bet tas pārbauda tikai "ielogojies", nevis "esi admin". Tāpēc admin paneļiem vajag savu.

Recepte: grozs (React Context + localStorage)

Vienkārši sakot: grozs šajā projektā nav datubāzē - tas glabājas lietotāja pārlūkā. Serveris par grozu neko nezina, kamēr lietotājs nenospiež "Pasūtīt". Tāpēc te nevajag ne kontrolieri, ne props - grozam pietiek ar React.

Provider "ietin" visu lietotni (app.jsx → setup()), tāpēc jebkura komponente var nolasīt vai mainīt grozu ar useContext.

1. Kā tas jau ir uzbūvēts

jsx// context/Cart.jsx
export const CartContext = createContext();

export const CartProvider = ({ children }) => {
  // sākuma vērtība: ko pārlūks atceras, vai tukšs saraksts
  const [cartData, setCartData] =
    useState(JSON.parse(localStorage.getItem('cart')) || []);

  const addToCart = (product, size = null) => {
    const updatedCart = [...cartData, { product_id: product.id, size, qty: 1, ... }];
    setCartData(updatedCart);                                    // atjauno ekrānu
    localStorage.setItem('cart', JSON.stringify(updatedCart));  // atceras pārlūkā
  };

  return <CartContext.Provider value={{ cartData, addToCart }}>{children}</CartContext.Provider>;
};
KodsKo tas dara
JSON.stringify(x)Pārvērš masīvu/objektu par tekstu (localStorage glabā tikai tekstu)
JSON.parse(text)Pārvērš tekstu atpakaļ par masīvu/objektu
localStorage.setItem('cart', text)Ieraksta pārlūka atmiņā (pārraksta, ja jau ir)
localStorage.getItem('cart')Nolasa no pārlūka atmiņas (ja nav - null)
localStorage.removeItem('cart')Izdzēš šo ierakstu no pārlūka atmiņas (grozs atkal tukšs)
setCartData(..)Nomaina state → React pārzīmē visu, kas grozu lieto
value={{ cartData, addToCart }}Kas būs pieejams visiem, kas lieto šo kontekstu

  useContext(CartContext);

router.post('/checkout', { items: cartData }, {
  onSuccess: () => clearCart(),  // tikai ja serveris pieņēma
});

Ar removeItem vien nepietiek: ja neizsauc setCartData([]), grozs ekrānā paliek, līdz pārlādē lapu. Un tīri grozu tikai pēc onSuccess - ja serveris atbild ar kļūdu (piem. validācija), lietotājs nezaudē grozu.

5. Kad grozs jāsūta uz serveri (Checkout)

Tikai tagad iesaistās Laravel: sūti grozu kā items un serverī izveido pasūtījumu. Cenas vienmēr pārrēķini serverī pēc product_id - pārlūka datiem (arī cenai) nedrīkst uzticēties.

React

jsxrouter.post('/checkout', {
  name, email,
  items: cartData,
});

Laravel

php$request->validate([
  'items' => 'required|array|min:1',
  'items.*.product_id' => 'exists:products,id',
]);
// cenu ņem no DB, ne no $request

Uzlabojums: šobrīd addToCart katru reizi pievieno jaunu rindu, arī tam pašam produktam ar to pašu izmēru. Labāk atrast esošo rindu (product_id + size) un palielināt qty.

Recepte: paziņojums pēc saglabāšanas (flash) un Form Request

Vienkārši sakot: lietotājs nospiež "Saglabāt" → serveris saglabā → parādās zaļš "Saglabāts!" un pazūd pats. Šo īso ziņu sauc par flash.

Laravel - nosūta ziņu

phpuse Inertia\Inertia;

public function update(ProfileUpdateRequest $request)
{
    $request->user()->fill($request->validated());
    $request->user()->save();

    Inertia::flash('toast', [
        'type' => 'success',
        'message' => 'Saglabāts!',
    ]);

    return to_route('profile.edit');
}

React - parāda ziņu (vienreiz, Layout.jsx)

jsximport { usePage } from '@inertiajs/react';
import { toast } from 'react-toastify';

const { flash } = usePage();

useEffect(() => {
  if (flash.toast) {
    toast[flash.toast.type](flash.toast.message);
  }
}, [flash]);

Ieliec useEffect vienreiz Layout.jsx (tas jau satur <ToastContainer />) - tad katra lapa automātiski rādīs paziņojumus, un kontrolierī pietiek ar vienu rindu Inertia::flash(..).

Ja validācijas noteikumi kontrolierī aug garāki, tos var iznest atsevišķā klasē. Kontrolieris kļūst īss, un validācija notiek pati, pirms metode vispār sāk darboties.

1) Izveido

Ja dati neder, Laravel pats atgriež lietotāju atpakaļ ar kļūdām (errors props) - tev nekas nav jāraksta.

Šis projekts izmanto Form Request Settings kontrolieros (profils, parole, 2FA) - tur tas ir gatavs paraugs (app/Http/Requests/Settings/). Pārējie kontrolieri validē ar Validator::make(..); abi veidi ir pareizi.
