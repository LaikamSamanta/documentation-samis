Sanctum vs sesiju autentifikācija (Inertia)

Inertia + Fortify

  • Viens projekts, viens deploy, sesiju auth.
  • Vienkāršāk, mazāk kustīgu daļu.
  • Filament strādā arī šeit - bet tikai kā cits route (piem. /admin) tajā pašā vienā appā/portā, ne atsevišķi.

Trūkums: mobile app vai atsevišķa izvietošana = pārtaisīt no nulles.

Sanctum + React Router

  • API (service-platform) + frontend (service-platform-public), katrs savs deploy.
  • API gatavs jauniem klientiem (mobile, trešā puse).
  • Filament dzīvo service-platform (API) pusē - tas jau ir atsevišķs deploy/ports no service-platform-public, kur klienti ielogojas.

Trūkums: CORS, tokeni, divi deploy procesi - attaisnojas tikai izmantojot elastīgumu.

Kāpēc tieši tokens, nevis sesijas cookie

Vienā domēnā pārlūks pievieno cookie pats; atsevišķos domēnos backend to nesaņem, tāpēc frontend katram pieprasījumam manuāli pievieno tokenu.

Kods: Inertia (cookie) vs Sanctum (tokens)

Inertia - sesijas cookie (automātiski)

js// POST - cookie pārlūks pievieno pats, papildu koda nav
const res = await fetch("/api/orders", {
  method: "POST",
  headers: { "Content-type": "application/json" },
  body: JSON.stringify({ product_id: 5 }),
});
const order = await res.json();

// PUT - tas pats, tikai body mainās
await fetch(`/api/orders/${order.id}`, {
  method: "PUT",
  headers: { "Content-type": "application/json" },
  body: JSON.stringify({ qty: 2 }),
});

// DELETE - body nav vajadzīgs, cookie vienalga automātisks
await fetch(`/api/orders/${order.id}`, { method: "DELETE" });

Sanctum - Bearer tokens (manuāli)

js// 1) POST /login - ATBILDES (response) body satur tokenu
const res = await fetch(`${apiUrl}/login`, {
  method: "POST",
  headers: { "Content-type": "application/json" },
  body: JSON.stringify({ email, password }),
});
const { token } = await res.json();
localStorage.setItem("token", token);

// 2) GET /user - PIEPRASĪJUMA (request) header nes tokenu, ne body
const res2 = await fetch(`${apiUrl}/user`, {
  method: "GET",
  headers: { Authorization: `Bearer ${token}` },
});
const user = await res2.json();

// 3) PUT - header paliek tas pats, papildus nāk body
await fetch(`${apiUrl}/user/${user.id}`, {
  method: "PUT",
  headers: { "Content-type": "application/json", Authorization: `Bearer ${token}` },
  body: JSON.stringify({ name: "Jauns vārds" }),
});

// 4) DELETE - header vienmēr jāpievieno, body nevajag
await fetch(`${apiUrl}/user/${user.id}`, {
  method: "DELETE",
  headers: { Authorization: `Bearer ${token}` },
});

Sanctum vajag, ja: (1) vairāk kā viens klients (web + mobile, trešā puse), VAI (2) frontend ir atsevišķs projekts uz cita domēna.

Postman + CSRF: 419 kļūda

web maršrutiem ir CSRF aizsardzība - POST bez derīga tokena dod 419. Risinājums:

  • GET lapu → dabū XSRF-TOKEN cookie → pievieno kā X-XSRF-TOKEN galveni POST, vai
  • Postman: ieslēdz cookie pārvaldību, tad GET → POST.

Factory vs Seeder

factory definē veidni - kā izskatās viens fake ieraksts. seeder izpilda to veidni - izsauc to un faktiski ieraksta datus datubāzē, kad palaid php artisan db:seed.

Standarta secība, veidojot jaunu funkciju

Jaunai admin sadaļai (piem. "Products") - vienmēr šī secība, jo kontrolieris izmanto modeli (Product::all()), un modelim jāzina sava tabula/kolonnas:

1. Migrācija - tabulas struktūra

bashphp artisan make:migration create_products_table
# rediģē database/migrations/..._create_products_table.php
php artisan migrate

2. Modelis - PHP klase, kas savieno ar tabulu

bashphp artisan make:model Product

3. Kontrolieris - loģika, kas apstrādā pieprasījumus

bashphp artisan make:controller Admin/ProductController --resource

--resource uzreiz uzģenerē visas CRUD metodes: index, create, store, edit, update, destroy.

4. Maršruti

phpRoute::resource('admin/products', Admin\ProductController::class);

Atkarīgs no auth veida (sk. augstāk). Sanctum/API: publiskie maršruti web.php, token API maršruti api.php (bez sesijām). Sesiju/Inertia (tavs gadījums): viss paliek web.php - api.php pēc noklusējuma nesniedz sesijas/CSRF.

5. Frontend (Inertia lapa)

resources/js/components/admin/Products.jsx (+ pages/admin/Products.jsx re-export). Kontroliera index() metode atgriež inertia('admin/Products', ['products' => Product::all()]).

Paātrinājums - Migrāciju + Modeli + Kontrolieri var izveidot vienā komandā: php artisan make:model Product -mcr (-m = migration, -c = controller, -r = resource metodes).

fetch() - GET vs POST

fetch() pēc noklusējuma vienmēr izmanto GET metodi, ja method nav norādīts.

fetch.js

fetch(url) // nav method → GET

fetch(url, { method: "POST", ... }) // jānorāda skaidri

GET (noklusējums - method nav norādīts)

jsconst res = await fetch(`${apiUrl}/categories/list`);
const result = await res.json();

if (result.status == 200) {
  setCategories(result.data);
}

POST (method jānorāda skaidri)

jsconst res = await fetch(`${apiUrl}/categories`, {
  method: "POST",
  headers: { "Content-type": "application/json" },
  body: JSON.stringify(data),
});
const result = await res.json();

Kas vēl jāzina par fetch()

  • GET pieprasījumam nedrīkst sūtīt body - dati jāliek URL/query parametros, ne pieprasījuma ķermenī.
  • Atbilde jāparsē ar .json() - arī tas ir Promise, tāpēc parasti ir divi await: viens fetch(), otrs .json().
  • POST/PUT/PATCH ar JSON datiem vienmēr vajag headers: {"Content-type": "application/json"} un body: JSON.stringify(...) - bez tā serveris datus pareizi nesapratīs.

fetch() nemet kļūdu HTTP kļūdas gadījumā (piem. 404, 500) - Promise noraidās tikai tad, ja pieprasījums vispār neaizsniedz serveri (tīkla kļūda). Lai noķertu HTTP kļūdas, pirms .json() pašam jāpārbauda res.ok vai res.status.

Inertia.js - kā tas strādā

Laravel + React bez API un bez frontend router: kontrolieris atgriež komponenti + datus, Inertia klikšķus dara ar XHR.

Atbilde vienmēr ir viens "page objekts". Ja pēc deploy mainās assetu version, GET pieprasījumam serveris atbild 409 + X-Inertia-Location un notiek vienreizēja pilna pārlāde.

json{ "component": "Product",            // kuru lapu rādīt
  "props": { "product": {...}, "auth": {...}, "errors": {} },
  "url": "/product/5", "version": "c32b8e..." }

Inertia middleware - atrašana, mapošana, share()

Reģistrācija - bootstrap/app.php

php->withMiddleware(function (Middleware $m) {
    $m->trustProxies(at: '*');       // globāli
    $m->web(append: [                // web grupa
        HandleInertiaRequests::class,
    ]);
})

Datu dalīšana - share()

phpprotected $rootView = 'app';

public function share(Request $r): array
{
    return [...parent::share($r),
        'auth' => ['user' => $r->user()],
        'categories' => fn () => Category::all(),
    ];
}
