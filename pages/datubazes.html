Sākums Datubāzes / SQL

Datubāzes / SQL

SQL valodas pamati neatkarīgi no WordPress vai konkrēta CMS - kā rakstīt vaicājumus, saprast tabulu attiecības un izvairīties no biežākajām veiktspējas kļūdām.

SELECT & WHERE

SELECT nosaka, kuras kolonnas iegūt, WHERE - kuras rindas atlasīt. Šie divi vārdi ir 90% no ikdienas SQL lietošanas.

sqlSELECT vards, epasts FROM lietotaji WHERE vecums >= 18;

SELECT * FROM produkti WHERE cena BETWEEN 10 AND 50;

SELECT * FROM lietotaji WHERE vards LIKE 'A%'; -- sākas ar burtu "A"

SELECT * FROM lietotaji WHERE pilseta IN ('Rīga', 'Liepāja', 'Daugavpils');

SELECT * (visas kolonnas) ir ērts izpētei, bet ražošanas kodā vienmēr norādi konkrētas kolonnas (SELECT vards, epasts) - tas ir ātrāk (mazāk dati jāpārsūta) un pasargā kodu, ja kāds vēlāk tabulai pievieno jaunu kolonnu.

Sakārtošana & limitēšana

ORDER BY nosaka secību, LIMIT ierobežo rezultātu skaitu - kopā tie ir pamats jebkurai lapošanai (pagination).

sqlSELECT * FROM produkti ORDER BY cena DESC LIMIT 10; -- 10 dārgākie

-- Lapošana: 3. lapa, ja katrā lapā 10 ieraksti
SELECT * FROM produkti ORDER BY cena ASC LIMIT 10 OFFSET 20;

Bez ORDER BY datubāze negarantē nekādu konkrētu secību - dažreiz tā var sagadīties tāda pati katru reizi, bet paļauties uz to nedrīkst. Ja secība ir svarīga (piem., lapošanai), vienmēr norādi ORDER BY tieši.

Datu tipi

Katrai kolonnai jānorāda tips, kas nosaka, kādus datus tā var glabāt un cik vietas tas aizņem.

INT

Vesels skaitlis - ID, skaitīšana, vecums. AUTO_INCREMENT to bieži izmanto primārajai atslēgai.

VARCHAR(n)

Mainīga garuma teksts, maksimums n rakstzīmes - vārdi, e-pasti, nosaukumi.

TEXT

Garš teksts bez fiksēta limita - raksti, apraksti, komentāri.

DECIMAL(p,s)

Precīzs decimālskaitlis - vienmēr naudas summām, nekad FLOAT (noapaļošanas kļūdas).

DATETIME

Datums + laiks - izveides datumi, notikumu laiki.

BOOLEAN / TINYINT(1)

Patiess/aplams karogi - aktivs, publicets. MySQL to iekšēji glabā kā mazu skaitli.

INSERT / UPDATE / DELETE

Trīs darbības, kas maina datus (pretstatā SELECT, kas tikai lasa).

sqlINSERT INTO lietotaji (vards, epasts) VALUES ('Anna', 'anna@example.com');

UPDATE lietotaji SET epasts = 'jauns@example.com' WHERE id = 5;

DELETE FROM lietotaji WHERE id = 5;

UPDATE vai DELETE bez WHERE ietekmē VISAS rindas tabulā - tas ir viens no biežākajiem, sāpīgākajiem iesācēju negadījumiem. Pirms izpildes vienmēr vispirms palaid to pašu nosacījumu kā SELECT, lai redzētu, kuras rindas tieši tiks ietekmētas.

Primārās & ārējās atslēgas

Primārā atslēga (primary key) unikāli identificē katru rindu tabulā. Ārējā atslēga (foreign key) savieno rindu ar rindu citā tabulā - tā veido attiecības starp tabulām.

sqlCREATE TABLE lietotaji (
    id INT AUTO_INCREMENT PRIMARY KEY,
    vards VARCHAR(100)
);

CREATE TABLE pasutijumi (
    id INT AUTO_INCREMENT PRIMARY KEY,
    lietotajs_id INT,
    summa DECIMAL(10,2),
    FOREIGN KEY (lietotajs_id) REFERENCES lietotaji(id)
);

FOREIGN KEY ne tikai dokumentē attiecību - datubāze to arī uzspiež: nevar izveidot pasūtījumu ar lietotajs_id, kas neeksistē lietotaji tabulā, un pēc noklusējuma nevar dzēst lietotāju, kuram vēl ir pasūtījumi.

JOIN veidi

JOIN apvieno rindas no divām (vai vairāk) tabulām vienā rezultātā, pamatojoties uz kopīgu atslēgu.

sql-- INNER JOIN - tikai rindas, kur ir sakritība ABĀS tabulās
SELECT p.id, l.vards
FROM pasutijumi p
INNER JOIN lietotaji l ON p.lietotajs_id = l.id;

-- LEFT JOIN - VISAS rindas no kreisās (lietotaji) tabulas,
-- arī tad, ja lietotājam vēl nav neviena pasūtījuma (p.id būs NULL)
SELECT l.vards, p.id
FROM lietotaji l
LEFT JOIN pasutijumi p ON l.id = p.lietotajs_id;

INNER JOIN

Der, ja interesē tikai pilnas attiecības - piem., pasūtījumi, kuriem noteikti ir lietotājs.

LEFT JOIN

Der, ja jāredz visi ieraksti no galvenās tabulas, pat ja saistītajā tabulā nav neviena atbilstoša ieraksta - piem., "visi lietotāji, arī tie bez pasūtījumiem".

Normalizācija (vienkārši)

Process, kā datus sadalīt vairākās saistītās tabulās, lai izvairītos no dublēšanās un pretrunīgiem datiem.

textSLIKTI (nenormalizēts) - lietotāja vārds atkārtojas katrā pasūtījuma rindā:
| pasutijuma_id | lietotaja_vards | lietotaja_epasts     | produkts |
| 1              | Anna             | anna@example.com     | Krekls   |
| 2              | Anna             | anna@example.com     | Bikses   |

LABI (normalizēts) - lietotāja dati VIENĀ vietā, pasūtījumi atsaucas uz to:
lietotaji: | id | vards | epasts            |
pasutijumi: | id | lietotajs_id | produkts |

Ja e-pasts glabāts katrā pasūtījuma rindā atsevišķi, mainot lietotāja e-pastu, jāatjaunina katra rinda - aizmirsti kaut vienu, un dati kļūst pretrunīgi. Normalizācija to novērš, glabājot katru faktu tikai vienā vietā.

GROUP BY & agregātfunkcijas

GROUP BY sagrupē rindas pēc kopīgas vērtības, ļaujot rēķināt summas, vidējos, skaitus u.c. par katru grupu atsevišķi.

sqlSELECT lietotajs_id, COUNT(*) AS pasutijumu_skaits, SUM(summa) AS kopa
FROM pasutijumi
GROUP BY lietotajs_id
HAVING COUNT(*) > 3; -- tikai lietotāji ar VAIRĀK nekā 3 pasūtījumiem

WHERE filtrē rindas pirms grupēšanas, HAVING filtrē grupas pēc grupēšanas - tāpēc HAVING COUNT(*) > 3 strādā, bet WHERE COUNT(*) > 3 izmestu kļūdu (COUNT vēl neeksistē WHERE izpildes brīdī).

Apakšvaicājumi (subqueries)

Vaicājums vaicājuma iekšā - iekšējais izpildās vispirms, un ārējais izmanto tā rezultātu.

sqlSELECT * FROM produkti
WHERE id IN (
    SELECT produkts_id FROM pasutijuma_rindas WHERE daudzums > 5
);

Daudzus apakšvaicājumus var pārrakstīt kā JOIN - parasti JOIN ir ātrāks, jo datubāze to var labāk optimizēt. Apakšvaicājumi der, ja loģika tā ir daudz skaidrāk lasāma, vai konkrētajam gadījumam nav dabiska JOIN varianta.

Indeksi & veiktspēja

Indekss ir papildu datu struktūra, kas paātrina meklēšanu pēc konkrētas kolonnas - līdzīgi kā grāmatas satura rādītājs, nevis lapu šķirstīšana pēc kārtas.

sqlCREATE INDEX idx_epasts ON lietotaji(epasts);

-- Parāda, VAI vaicājums izmanto indeksu, vai skenē visu tabulu
EXPLAIN SELECT * FROM lietotaji WHERE epasts = 'anna@example.com';

Indeksi paātrina lasīšanu, bet nedaudz palēnina rakstīšanu (katrai INSERT/UPDATE jāatjaunina arī indekss) - nelieto indeksu katrai kolonnai "gadījumam ja". Pievieno indeksu kolonnām, kuras bieži izmantoto WHERE, JOIN vai ORDER BY nosacījumos. Primārā atslēga jau automātiski ir indeksēta.

Transakcijas

Vairākas darbības, kas jāizpilda kopā, "visu vai neko" - ja kāda no tām neizdodas, visas pārējās tiek atceltas.

sqlBEGIN;

UPDATE konti SET atlikums = atlikums - 100 WHERE id = 1; -- noņem naudu
UPDATE konti SET atlikums = atlikums + 100 WHERE id = 2; -- pievieno naudu

COMMIT; -- apstiprina abas izmaiņas kopā
-- Ja kaut kas neizdodas pa vidu: ROLLBACK; (atceļ visu)

Bez transakcijas, ja serveris avarē tieši starp abiem UPDATE vaicājumiem augstāk, nauda "pazūd" - noņemta no viena konta, bet nekad nepievienota otram. Transakcija garantē, ka tas nekad nenotiek: vai nu izpildās abas darbības, vai neviena.

Prepared statements

Nekad neveido SQL vaicājumus, saliekot lietotāja ievadi tieši teksta virknē - tas atver SQL injection ievainojamību.

php// NEDROŠI - lietotāja ievade tieši SQL tekstā
$pdo->query("SELECT * FROM lietotaji WHERE epasts = '" . $_POST['epasts'] . "'");

// DROŠI - parametri saistīti atsevišķi no vaicājuma teksta
$stmt = $pdo->prepare("SELECT * FROM lietotaji WHERE epasts = :epasts");
$stmt->execute(['epasts' => $_POST['epasts']]);

Pilnu skaidrojumu, kāpēc tas strādā, un vairāk piemēru skati Drošība → SQL Injection. WordPress kontekstā tas pats princips ar $wpdb->prepare().

N+1 problēma

Bieža veiktspējas kļūda - cilpā izpilda pa vienam vaicājumam katrai rindai, tā vietā, lai iegūtu visus datus vienā vaicājumā.

php// SLIKTI - 1 vaicājums lietotājiem + PA VIENAM vaicājumam KATRAM lietotājam (N+1)
$lietotaji = $pdo->query("SELECT * FROM lietotaji")->fetchAll();
foreach ($lietotaji as $l) {
    $pasutijumi = $pdo->query("SELECT * FROM pasutijumi WHERE lietotajs_id = {$l['id']}")->fetchAll();
}
// 100 lietotāju = 101 vaicājums

// LABI - VIENS JOIN vaicājums iegūst visu uzreiz
$rezultats = $pdo->query("
    SELECT l.*, p.id AS pasutijuma_id
    FROM lietotaji l
    LEFT JOIN pasutijumi p ON l.id = p.lietotajs_id
")->fetchAll();
// 100 lietotāju = joprojām TIKAI 1 vaicājums

N+1 ir mānīgs, jo lokāli (ar 10 testa ierakstiem) tas šķiet ātrs - problēma parādās tikai ražošanā, kad tabulā ir tūkstošiem rindu, un lapa pēkšņi ielādējas sekundēm ilgi vai timeoutē.

Dublējumkopijas (backup/restore)

Datubāzes dublējums ir teksta fails ar visām komandām, kas nepieciešamas, lai to pilnībā atjaunotu no jauna.

bash# Izveido dublējumu
mysqldump -u lietotajs -p datubaze > dublejums.sql

# Atjauno no dublējuma
mysql -u lietotajs -p datubaze < dublejums.sql

WordPress projektos ērtāk lietot wp db export/wp db import (WP-CLI) - skati SSH → MySQL & dublējumi. Vienmēr uzglabā dublējumus ārpus tā paša servera - ja serveris tiek uzlauzts vai sabojāts, dublējums tajā pašā vietā nepalīdzēs.
