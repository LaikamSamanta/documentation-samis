HTML & CSS Advanced

Šeit nav pamatu - tikai tas, ko iesācēju kursi parasti izlaiž: modernais CSS layout, jauni selektori, native HTML5 elementi, kas aizstāj rokām rakstītu JS. Katrai tēmai - kāpēc tā ir noderīga un pilnībā strādājošs piemērs.

CSS Grid padziļināti

grid-template-areas ļauj aprakstīt izkārtojumu vizuāli, kā "karti" - daudz lasāmāk nekā skaitīt kolonnu/rindu numurus.

css.layout {
    display: grid;
    grid-template-columns: 250px 1fr;
    grid-template-areas:
        "header header"
        "sidebar main"
        "footer footer";
}
.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }
.footer  { grid-area: footer; }

subgrid ļauj bērnelementam pārmantot vecāka grid līnijas - noder, lai kartītes rindā izlīdzinātu pēc vienādām kolonnām, pat ja katrai kartītei atšķirīgs saturs:

css.parent { display: grid; grid-template-columns: repeat(4, 1fr); }
.child  { display: grid; grid-template-columns: subgrid; grid-column: span 4; }

repeat(auto-fit, minmax(200px, 1fr)) ir viena no visnoderīgākajām Grid kombinācijām - automātiski izveido tik kolonnu, cik ietilpst (katra vismaz 200px plata), bez neviena media query.

Container Queries

Media queries reaģē uz pārlūka loga platumu. Container queries reaģē uz vecākelementa platumu - komponente pati pielāgojas atkarībā no tā, kur tā ievietota (sānjoslā vs galvenajā saturā), nevis no visas lapas izmēra.

css.card-wrap {
    container-type: inline-size;
    container-name: card;
}

@container card (min-width: 400px) {
    .card { display: flex; align-items: center; }
}
@container card (max-width: 399px) {
    .card { display: block; }
}

Tā pati .card komponente tagad var izskatīties atšķirīgi platā galvenajā laukumā un šaurā sānjoslā - bez divām atsevišķām CSS klasēm vai JavaScript. Der patiesi atkārtoti lietojamiem komponentiem.

Flexbox padziļināti

Ne tikai display: flex - order un saliktais flex saīsinājums ļauj precīzi kontrolēt izkārtojumu bez HTML pārkārtošanas.

css.flex-row {
    display: flex;
    gap: 16px; /* mūsdienās der arī flexboxam, ne tikai gridam */
}

.priority-item {
    order: -1; /* vizuāli pārvieto UZ PRIEKŠU, HTML secība paliek nemainīga */
}

.grow-item {
    flex: 1 1 200px; /* grow: 1, shrink: 1, bāzes izmērs: 200px */
}

order maina tikai vizuālo secību, ne DOM (dokumenta) secību - ekrāna lasītāji un tastatūras navigācija (Tab taustiņš) joprojām seko oriģinālajai HTML secībai. Nelieto order, lai "salabotu" nepareizu HTML struktūru - tas rada pieejamības problēmas.

Custom Properties padziļināti

CSS mainīgie (--mainigais) ne tikai glabā vērtības - tos var pārrakstīt lokāli (kaskadē) un lasīt/rakstīt tieši no JavaScript.

css:root {
    --spacing: 8px;
    --spacing-lg: calc(var(--spacing) * 3); /* mainīgie var izmantot citus mainīgos */
}

.theme-dark {
    --bg: #0a0a0a; /* pārraksta lokāli - VISI bērnelementi automātiski redz jauno vērtību */
}
js// Lasīt/rakstīt CSS mainīgos tieši no JS
const root = document.documentElement;
root.style.setProperty('--spacing', '12px');

const vertiba = getComputedStyle(root).getPropertyValue('--spacing');

Tieši šis mehānisms ir pamatā Documentation Samis pašas tumšā/gaišā režīma pārslēgšanai - --page-accent un līdzīgi mainīgie tiek pārrakstīti pēc kategorijas un tēmas, un visi elementi, kas tos izmanto, atjaunojas automātiski, bez atsevišķas CSS klases katrai kombinācijai.

clamp() & fluid typography

clamp(min, ideāls, max) ļauj vērtībai augt/samazināties plūstoši atkarībā no ekrāna izmēra, bet nekad nepārsniegt noteiktās robežas - bez desmitiem media query.

cssh1 {
    font-size: clamp(1.5rem, 4vw + 1rem, 3rem); /* nekad mazāk par 1.5rem, nekad vairāk par 3rem */
}

.container {
    width: min(90%, 1200px); /* elastīgs, bet nekad platāks par 1200px */
}

.sidebar {
    width: max(250px, 20%); /* nekad šaurāks par 250px */
}

4vw + 1rem vidējā vērtībā apvieno divus mērvienību tipus - vw (atkarīgs no loga platuma) ar rem (fiksēts) - tas nodrošina, ka teksts skalējas ar ekrānu, bet nekad nekļūst absurdi mazs uz šauriem ekrāniem, jo rem daļa vienmēr piešķir minimālu bāzi.

:has() / :is() / :where()

Trīs jauni selektori, kas atrisina gadu desmitiem vecas CSS ierobežojumus.

css/* :has() - izvēlas TĒVU pēc BĒRNA klātbūtnes (agrāk vajadzēja JS) */
.card:has(img) { padding-top: 0; }
.form-group:has(input:invalid) { border-color: red; }

/* :is() - saīsina atkārtotus selektorus */
:is(h1, h2, h3) { font-weight: 700; }
/* tas pats, kas: h1, h2, h3 { font-weight: 700; } - bet noderīgāks garākiem selektoriem */

/* :where() - TAS PATS kā :is(), bet specificity VIENMĒR ir 0 */
:where(h1, h2, h3) { margin: 0; } /* viegli pārrakstāms ar jebkuru citu noteikumu */

:has() ir vienīgais veids tīrā CSS, kā stilizēt elementu, pamatojoties uz to, KAS atrodas tā iekšā - pirms tam tas prasīja JavaScript, kas klausās izmaiņas un pievieno/noņem klasi manuāli.

@layer (CSS Layers)

Ļauj skaidri kontrolēt kaskādes secību - vēlāk deklarēts @layer vienmēr uzvar pār agrāko, neatkarīgi no specificity. Atrisina "CSS kara" problēmu ar trešo pušu bibliotēkām.

css@layer reset, base, components, utilities; /* nosaka secību VISAM failam */

@layer base {
    a { color: blue; }
}

@layer utilities {
    .text-red { color: red; } /* UZVAR pār base, jo utilities nāk vēlāk kārtā, kaut arī specificity zemāks */
}

Bez slāņiem, lai pārrakstītu trešās puses bibliotēkas stilu (piem., no WordPress spraudņa), bieži vajadzēja !important vai mākslīgi garākus selektorus. Ar @layer vienkārši ieliec savu CSS vēlākā slānī - tas uzvar automātiski, tīri un paredzami.

Animācijas padziļināti

Katram sarakstā esošam elementam cita aizture (animation-delay), aprēķināta no CSS mainīgā - klasisks "staggered" (pakāpenisks) animācijas efekts bez JS.

css@keyframes slideIn {
    from { opacity: 0; transform: translateY(20px); }
    to   { opacity: 1; transform: translateY(0); }
}

.list-item {
    animation: slideIn .5s ease-out backwards; /* backwards = pielieto 0% kadru PIRMS animācijas sākas */
    animation-delay: calc(var(--i) * 0.1s); /* katram elementam --i inline stilā: style="--i: 0" / "--i: 1" ... */
}

--i mainīgo katram elementam ieliek JS pusē (piem., item.style.setProperty('--i', index)) vai servera pusē veidnē - tas ļauj vienam CSS noteikumam radīt atšķirīgu aizturi katram sarakstā esošam elementam.

Scroll-driven animations

Animācija, kas progresē atkarībā no ritināšanas pozīcijas, nevis laika - elements pakāpeniski parādās, ritinot to redzamības zonā.

css@keyframes fade-in-on-scroll {
    from { opacity: 0; transform: translateY(30px); }
    to   { opacity: 1; transform: translateY(0); }
}

.reveal {
    animation: fade-in-on-scroll linear;
    animation-timeline: view(); /* sasaista animāciju ar ritināšanas progresu, ne ar laiku */
    animation-range: entry 0% cover 40%; /* animācija notiek, kamēr elements ienāk skatā */
}

Šis ir jauns CSS API (2024+) - pārbaudi atbalstu caniuse.com, pirms paļauties uz to kritiskam funkcionalitātei. Vecākiem pārlūkiem der pakāpeniska uzlabošana (progressive enhancement): elements bez atbalsta vienkārši paliek redzams uzreiz, bez animācijas.

View Transitions API

Pārlūks automātiski animē pāreju starp diviem DOM stāvokļiem - nofotografē "pirms" un "pēc" un radī plūstošu pāreju starp tiem, bez rokām rakstītas animācijas loģikas.

jsdocument.startViewTransition(() => {
    // DOM izmaiņas šeit - pārlūks AUTOMĀTISKI animē pāreju
    updateDOM();
});
css::view-transition-old(root),
::view-transition-new(root) {
    animation-duration: 0.3s;
}

Der lieliski lapas pārejām vienas-lapas lietotnēs (SPA) - piem., pārejot no produktu saraksta uz produkta detaļām, attēls var vizuāli "izaugt" no sīktēla uz pilnu izmēru. Ja pārlūks neatbalsta šo API, startViewTransition() vienkārši izpilda funkciju uzreiz, bez animācijas - droši lietot kā uzlabojumu, ne kā obligātu atkarību.

Web Components

Pašam definēts HTML tags ar iekapsulētu (encapsulated) stilu un uzvedību, izmantojot tikai pārlūkā iebūvētu, natīvu API - bez React/Vue vai jebkuras bibliotēkas.

jsclass ManaPoga extends HTMLElement {
    connectedCallback() {
        this.attachShadow({ mode: 'open' }).innerHTML = `
            <style>
                button { padding: 10px 20px; border-radius: 8px; background: #7c3aed; color: #fff; border: none; }
            </style>
            <button><slot></slot></button>
        `;
    }
}

customElements.define('mana-poga', ManaPoga);
html<mana-poga>Klikšķini šeit</mana-poga>

Shadow DOM (attachShadow) nozīmē, ka <style> šī komponenta iekšā neietekmē pārējo lapu, un otrādi - lapas globālais CSS neietekmē komponenta iekšpusi. <slot> ir vieta, kur ievietojas oriģinālais saturs starp atverošo un aizverošo tagu (šeit - "Klikšķini šeit").

<dialog> elements

Natīvs, iebūvēts modālā loga elements - fokusa slēdzene (focus trap), Esc aizvēršana un fons (backdrop) darbojas automātiski, bez pašrocīgi rakstīta JS.

html<dialog id="myDialog">
    <p>Šis ir natīvs modālais logs.</p>
    <button onclick="document.getElementById('myDialog').close()">Aizvērt</button>
</dialog>

<button onclick="document.getElementById('myDialog').showModal()">Atvērt</button>
cssdialog::backdrop {
    background: rgba(0, 0, 0, 0.5); /* stilizē fonu aiz dialoga */
}
dialog {
    border: none;
    border-radius: 16px;
    padding: 24px;
}

Salīdzini ar pašrocīgi rakstīto modālo logu Sagataves → Modālais logs - tur vajadzēja pašiem rakstīt Esc taustiņa, klikšķa-ārpusē un fokusa loģiku. <dialog> to visu dara pats, uz showModal() izsaukuma.

<details>/<summary>

Natīvs, iebūvēts akordeons - vienas rindiņas HTML, bez CSS vai JS.

html<details>
    <summary>Kas ir WordPress?</summary>
    <p>WordPress ir satura pārvaldības sistēma (CMS), kas darbina vairāk nekā 40% no visām interneta vietnēm.</p>
</details>

<details open>
    <summary>Šis sākas atvērts</summary>
    <p>"open" atribūts nosaka sākotnējo stāvokli.</p>
</details>

Salīdzini ar pašrocīgi rakstīto akordeonu Sagataves → Akordeons - tas dod pilnu kontroli pār animāciju un stilu (piem., tikai vienu atvērtu vienlaicīgi), bet <details> der ātriem, vienkāršiem gadījumiem, kur JS/CSS piepūle nav attaisnojama.

<template> elements

Saturs <template> iekšā ir inertens - netiek renderēts, attēli neielādējas, skripti neizpildās - kamēr to neklonē DOM ar JavaScript. Efektīvs veids, kā sagatavot atkārtojamu HTML struktūru.

html<template id="row-template">
    <tr><td class="name"></td><td class="email"></td></tr>
</template>

<table><tbody id="tabula"></tbody></table>
jsconst template = document.getElementById('row-template');
const clone = template.content.cloneNode(true);

clone.querySelector('.name').textContent = 'Anna';
clone.querySelector('.email').textContent = 'anna@example.com';

document.getElementById('tabula').appendChild(clone);

Alternatīva veidam, kā daudzi raksta HTML tieši JS virknēs (innerHTML = '<tr>...') - <template> ļauj HTML struktūru rakstīt kā īstu HTML, ar sintakses izcelšanu un bez virkņu salikšanas kļūdu riska.
