Sākums GDPR / Sīkdatnes

GDPR / Sīkdatnes

Praktiskā, tehniskā GDPR puse - ne juridiskais teksts, bet tas, kas programmētājam tiešām jāieliek kodā: piekrišanas baneris, kas patiešām bloķē sīkdatnes līdz piekrišanai, un WordPress iebūvētie rīki.

Kas ir GDPR un kam tas attiecas

GDPR (General Data Protection Regulation / Vispārīgā datu aizsardzības regula) ir ES regula, kas spēkā kopš 2018. gada - nosaka, kā drīkst vākt, glabāt un izmantot fizisku personu datus. Tā attiecas uz jebkuru vietni, kas apstrādā ES iedzīvotāju datus, neatkarīgi no tā, kur atrodas pati vietne vai uzņēmums.

Kas ir "personas dati"

Jebkura informācija, kas var identificēt konkrētu personu - vārds, e-pasts, IP adrese, sīkdatnes ID, pat lietotāja uzvedības dati (piem., Google Analytics dati).

Latvijā

GDPR ievērošanu uzrauga Datu valsts inspekcija - sūdzības par vietnēm, kas neievēro noteikumus, izskata viņi.

Sīkdatņu kategorijas

Ne visām sīkdatnēm vajadzīga piekrišana - atšķirība ir principiāli svarīga koda ziņā, jo nosaka, kuras drīkst ielādēt uzreiz un kuras jāgaida.

✅ Nepieciešamās

Bez tām vietne nedarbojas - sesijas ID, groza saturs. Piekrišana nav vajadzīga, drīkst ielādēt uzreiz.

⚙️ Funkcionālās

Atceras izvēles (valoda, tēma). Parasti pieder pie "vajadzīgo" kategorijas, bet dažkārt prasa piekrišanu atkarībā no interpretācijas.

📊 Analītiskās

Google Analytics u.tml. - VIENMĒR jāgaida piekrišana pirms ielādes.

📢 Mārketinga

Facebook Pixel, reklāmu izsekošana - VIENMĒR jāgaida piekrišana, un parasti tā vislielākais juridiskais risks, ja pārkāpts.

Piekrišanas baneris

Pilnībā strādājošs baneris - svarīgākais princips: analītikas skripts tiešām netiek ielādēts, kamēr lietotājs nav piekritis, nevis tikai vizuāli paslēpts baneris ar skriptu, kas jau darbojas fonā.

html<div id="cookie-banner" class="cookie-banner" style="display:none;">
    <p>Šī vietne izmanto sīkdatnes, lai uzlabotu jūsu pieredzi. <a href="/privatuma-politika">Uzzināt vairāk</a></p>
    <div class="cookie-banner-actions">
        <button id="cookie-accept-necessary">Tikai nepieciešamās</button>
        <button id="cookie-accept-all">Pieņemt visas</button>
    </div>
</div>
jsdocument.addEventListener('DOMContentLoaded', function () {
    const banner = document.getElementById('cookie-banner');
    const piekrisana = localStorage.getItem('cookie_consent');

    if (piekrisana) {
        if (piekrisana === 'all') ieladetAnalitiku();
        return; // lēmums jau pieņemts iepriekš - banneri nerāda vēlreiz
    }

    banner.style.display = 'block';

    document.getElementById('cookie-accept-all').addEventListener('click', function () {
        localStorage.setItem('cookie_consent', 'all');
        banner.style.display = 'none';
        ieladetAnalitiku();
    });

    document.getElementById('cookie-accept-necessary').addEventListener('click', function () {
        localStorage.setItem('cookie_consent', 'necessary');
        banner.style.display = 'none';
        // analītika NETIEK ielādēta
    });
});

function ieladetAnalitiku() {
    // Skripts tiek pievienots lapai TIKAI PĒC piekrišanas - ne agrāk
    const script = document.createElement('script');
    script.src = 'https://www.googletagmanager.com/gtag/js?id=G-XXXXXXX';
    document.head.appendChild(script);
}

Biežākā kļūda: Google Analytics skripts jau ir <head> HTML kodā, un baneris tikai vizuāli parādās virs lapas - tas nav atbilstoši GDPR, jo sīkdatne jau uzstādīta, pirms lietotājs vispār redzējis banneri. Analītikas skripts drīkst parādīties HTML kodā TIKAI pēc piekrišanas, tieši kā šajā piemērā ar document.createElement('script').

Google Analytics & Consent Mode

Google Analytics piedāvā iebūvētu "Consent Mode" - vietas, kur skripts jau ielādēts, bet informē Google, vai atļauts vākt datus, nevis pilnībā jāieslēdz/jāizslēdz visu skriptu.

js// Sākotnēji - VISS liegts, kamēr lietotājs nav izvēlējies
gtag('consent', 'default', {
    'analytics_storage': 'denied',
    'ad_storage': 'denied'
});

// Pēc lietotāja piekrišanas (banera "Pieņemt visas" klikšķa):
gtag('consent', 'update', {
    'analytics_storage': 'granted'
});

Consent Mode der lielākiem projektiem, kur analītikas skripts jau dziļi integrēts (piem., ar Google Tag Manager) - vienkāršākiem projektiem pilnībā aizkavēta skripta ielāde (kā iepriekšējā sadaļā) ir vieglāk saprotama un droši pareiza pieeja.

Sīkdatņu saraksta uzturēšana

Privātuma politikā solītais sīkdatņu saraksts bieži novecojas - jauns spraudnis vai skripts pievieno sīkdatni, ko neviens nepieraksta politikā.

text1. Atver DevTools (F12) → cilne "Application" (Chrome) vai "Storage" (Firefox)
2. Kreisajā pusē: Cookies → izvēlies savu domēnu
3. Redzi VISAS reāli uzstādītās sīkdatnes - nosaukumu, derīgumu, avotu
4. Salīdzini ar to, kas norādīts privātuma politikā
5. Atkārto ik pēc dažiem mēnešiem vai pēc katra jauna spraudņa/skripta pievienošanas

Šī pati DevTools "Application" cilne noder arī vispārīgai atkļūdošanai - tur redzi arī localStorage, sessionStorage un servera sūtītās Set-Cookie galvenes.

Datu subjekta tiesības

GDPR piešķir lietotājiem konkrētas, izpildāmas tiesības attiecībā uz saviem datiem - vietnei jāspēj tās praktiski nodrošināt, ne tikai pieminēt politikā.

Piekļuve

Lietotājs var pieprasīt kopiju visiem datiem, ko vietne par viņu glabā.

Labošana

Var pieprasīt labot nepareizus datus.

Dzēšana ("tiesības tikt aizmirstam")

Var pieprasīt savu datu pilnīgu dzēšanu, ja nav cita juridiska pamata tos paturēt.

Pārnesamība

Var pieprasīt savus datus strukturētā, mašīnlasāmā formātā (piem., JSON), lai pārnestu uz citu pakalpojumu.

Iebilšana

Var iebilst pret konkrētiem datu apstrādes veidiem, piem., tiešo mārketingu.

Privātuma politikas pamatelementi

Minimālais saturs, kam jābūt jebkuras vietnes privātuma politikā:

Pārzinis

Kas (uzņēmums/persona) ir atbildīgs par datu apstrādi un kā ar viņu sazināties.

Kādi dati un kāpēc

Konkrēts saraksts, kādus datus vāc (e-pasts, IP, uzvedība) un ar kādu mērķi katrs tiek izmantots.

Cik ilgi glabā

Konkrēts vai vismaz noteiktu principu balstīts glabāšanas termiņš katram datu veidam.

Ar ko dalās

Trešās puses, kas saņem datus - hostings, e-pasta serviss, analītika, maksājumu apstrādātāji.

Tiesības & kontakti

Kā lietotājs var izmantot savas tiesības (skat. augstāk) un kur sūdzēties, ja neapmierina atbilde.

WordPress iebūvētie GDPR rīki

Kopš WordPress 4.9.6 (2018) kodolā jau iebūvēti pamata GDPR rīki - Iestatījumi → Privātums ļauj izveidot privātuma politikas lapu un apstrādāt datu pieprasījumus tieši admin panelī, bez papildu spraudņa.

php// Pievieno savu spraudni/tēmas datu avotu personas datu eksportam
add_filter('wp_privacy_personal_data_exporters', function($eksportetaji) {
    $eksportetaji['mans-spraudnis'] = [
        'exporter_friendly_name' => 'Mana spraudņa dati',
        'callback' => 'mans_spraudnis_datu_eksports',
    ];
    return $eksportetaji;
});

Šis filtrs nepieciešams tikai tad, ja spraudnis/tēma glabā savus, pielāgotus lietotāja datus ārpus standarta WordPress lietotāju/komentāru sistēmas - parastiem WordPress datiem (lietotāji, komentāri) eksports jau strādā automātiski, bez papildu koda.

Kontaktformas piekrišana

Jebkurai formai, kas savāc personas datus (e-pastu, vārdu), jābūt skaidrai, aktīvai piekrišanas atzīmei - iepriekš atzīmēta rūtiņa nav derīga piekrišana pēc GDPR.

html<label>
    <input type="checkbox" name="piekritu_privatumam" required>
    Piekrītu <a href="/privatuma-politika" target="_blank">privātuma politikai</a>
</label>
phpif (empty($_POST['piekritu_privatumam'])) {
    die('Jāpiekrīt privātuma politikai, lai nosūtītu formu.');
}

Rūtiņai vienmēr jābūt pēc noklusējuma neatzīmētai - lietotājam pašam aktīvi jāatzīmē. Ja izmanto gatavu kontaktformu no Integrācijas → Kontaktforma, pievieno šo rūtiņu tai pašai formai un pārbaudi to serverī tāpat kā pārējos laukus.
