Sākums WordPress Integrācijas

Integrācijas

Pilnas, gatavas integrācijas jebkuram WordPress projektam - iekopē un uzreiz strādā. Katra integrācija ir sava, sakļaujama sadaļa sānjoslā - spied uz nosaukuma, lai atvērtu tās soļus.

Kur likt PHP kodu: ja vien nav norādīts citādi, visi šīs lapas PHP piemēri jāievieto aktīvās tēmas functions.php failā (Izskats → Tēmas redaktors, vai tieši failā serverī) un jāsaglabā - izmaiņas parasti redzamas uzreiz pēc lapas atsvaidzināšanas. WordPress pamatiem (tēmas, hooks, CPT) skaties WordPress sadaļu.

Valodu sistēma (multi-language) - pārskats

Šī ir pilna, patstāvīga daudzvalodu sistēma - tavs paša "mini WPML", bet vienkāršāks, bez maksas un pilnībā tavā kontrolē. To var iekopēt gandrīz jebkurā WordPress projektā un tā uzreiz strādā. Sistēma sastāv no deviņām daļām, kuras zemāk izskaidrotas pa vienai:

1️⃣ Valodu saraksts

JSON fails ar aktīvajām valodām (kods + nosaukums).

2️⃣ Valodas noteikšana

No URL, sīkdatnes vai noklusējuma - automātiski.

3️⃣ Pretty URL

/en/lapa/ vietā neglīta ?lang=en.

4️⃣ Statiskā teksta tulkojumi

Pogas, izvēlnes, virsraksti - visās valodās.

5️⃣ Lauku definīcijas & redaktors

Organizēts admin ekrāns lielu lapu tulkošanai, ar nosauktiem laukiem un valodu cilnēm.

6️⃣ Daudzvalodu lauki

Ieraksta lauki (piem., apakšvirsraksts) katrā valodā atsevišķi.

7️⃣ Admin lapa

Valodu pievienošana/dzēšana bez koda rediģēšanas.

8️⃣ Google Translate

Viena poga aizpilda tulkojumu automātiski.

9️⃣ Pārslēdzējs & SEO

Frontend valodu izvēlne + hreflang tagi.

Visas 9 daļas kopā veido vienu failu - inc/multilingual.php. Katra sadaļa zemāk paskaidro savu gabalu un rāda tā kodu; pēdējā sadaļā ("Kā ielikt citā projektā") ir precīzi soļi, kā tās salikt kopā jaunā WordPress projektā.

1. Pamata fails & valodu saraksts

Valodu saraksts netiek glabāts datubāzē, bet vienkāršā JSON failā wp-content/uploads/ml-lang/languages.json - tas ir ātrāk nekā datubāzes vaicājums un failu var apskatīt/rediģēt tieši, ja kādreiz vajag. Fails ar .htaccess tiek pasargāts, lai neviens to nevarētu atvērt tieši pārlūkā.

php/**
 * inc/multilingual.php
 * Daudzvalodu sistēma - daļa 1: pamata valodu saraksts
 */
defined('ABSPATH') || exit;

// Atgriež mapes ceļu, kur glabājam valodu datus (izveido, ja neeksistē)
function ml_lang_dir(): string {
    $dir = wp_upload_dir()['basedir'] . '/ml-lang';
    if (!file_exists($dir)) {
        wp_mkdir_p($dir);
        file_put_contents($dir . '/.htaccess', 'deny from all');
    }
    return $dir;
}

// Nolasa aktīvo valodu sarakstu - piem. [['code'=>'lv','label'=>'Latviešu'], ...]
function ml_get_languages(): array {
    $file = ml_lang_dir() . '/languages.json';

    if (!file_exists($file)) {
        return [['code' => 'lv', 'label' => 'Latviešu']];
    }

    $data = json_decode(file_get_contents($file), true);
    return (is_array($data) && !empty($data))
        ? $data
        : [['code' => 'lv', 'label' => 'Latviešu']];
}

// Saglabā valodu sarakstu atpakaļ JSON failā
function ml_save_languages(array $langs): bool {
    $file = ml_lang_dir() . '/languages.json';
    $json = wp_json_encode($langs, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE);
    return (bool) file_put_contents($file, $json);
}

// Pirmā valoda sarakstā vienmēr ir noklusējuma (galvenā) valoda
function ml_default_lang(): string {
    $langs = ml_get_languages();
    return $langs[0]['code'] ?? 'lv';
}

Ja fails vēl neeksistē, sistēma automātiski strādā ar vienu noklusējuma valodu (lv) - tā nekad "nesalūzt" pat pirms pirmās konfigurēšanas.

wp_upload_dir()

Atgriež masīvu ar WordPress augšupielāžu mapes info - ['basedir'] ir tās pilnais ceļš serverī (parasti wp-content/uploads).

wp_mkdir_p()

WordPress versija komandai mkdir -p - izveido mapi UN visas trūkstošās vecākmapes uzreiz, ja tādas vēl neeksistē.

JSON_PRETTY_PRINT

wp_json_encode() karogs (flag) - saglabā JSON ar atkāpēm/jaunām rindām, lai failu var lasīt/rediģēt ar roku, nevis viss vienā garā rindā.

2. Aktīvās valodas noteikšana

Katrā lapas ielādē sistēmai jāzina, kurā valodā rādīt saturu. Prioritāšu secība: vispirms skatās URL (/en/...), tad sīkdatni (atceras iepriekšējo izvēli), visbeidzot - noklusējumu.

php// Nosaka un atceras aktīvo valodu vienas lapas ielādes ietvaros (static - skaitļo tikai vienreiz)
function ml_detect_lang(): string {
    static $detected = null;
    if ($detected !== null) return $detected;

    $allowed = array_column(ml_get_languages(), 'code');
    $default = ml_default_lang();

    // 1) URL segments, piem. "/en/kontakti/" -> "en"
    $path  = parse_url($_SERVER['REQUEST_URI'] ?? '/', PHP_URL_PATH) ?? '/';
    $parts = explode('/', trim($path, '/'));

    if (!empty($parts[0]) && in_array($parts[0], $allowed, true)) {
        return $detected = $parts[0];
    }

    // 2) Sīkdatne no iepriekšējā apmeklējuma
    $cookie = sanitize_key($_COOKIE['ml_lang'] ?? '');
    if ($cookie && in_array($cookie, $allowed, true)) {
        return $detected = $cookie;
    }

    // 3) Noklusējums
    return $detected = $default;
}

// Īsāks, ērtāks alias - šo sauc visur pārējā kodā un veidnēs
function ml_current_lang(): string {
    return ml_detect_lang();
}

// Katru reizi, kad valoda mainās, atjaunojam sīkdatni uz gadu
add_action('init', function () {
    $lang = ml_detect_lang();
    if (($_COOKIE['ml_lang'] ?? '') !== $lang) {
        setcookie('ml_lang', $lang, time() + YEAR_IN_SECONDS, COOKIEPATH, COOKIE_DOMAIN, is_ssl(), true);
    }
});

static $detected

Statisks mainīgais atceras savu vērtību starp izsaukumiem vienas lapas ielādes ietvaros - funkcija skaitļo valodu tikai vienreiz, pat ja to izsauc 50 reizes tajā pašā pieprasījumā.

array_column()

No masīva ar apakšmasīviem izvelk tikai VIENU kolonnu - šeit no [['code'=>'lv',...], ['code'=>'en',...]] paņem tikai ['lv', 'en'].

parse_url(..., PHP_URL_PATH)

parse_url() sadala pilnu URL atsevišķās daļās (domēns, ceļš, query); PHP_URL_PATH pasaka - atgriez TIKAI ceļa daļu, piem. no /en/kontakti/?a=1 paņem /en/kontakti/.

sanitize_key()

WordPress funkcija, kas no teksta atstāj tikai mazos burtus, ciparus, - un _ - droši lietot identifikatoriem/atslēgām, kas nāk no lietotāja (šeit - sīkdatnes vērtība).

Cookie parametri

YEAR_IN_SECONDS - WordPress konstante (gada sekundes, ērtāk nekā rakstīt skaitli). COOKIEPATH/COOKIE_DOMAIN - WordPress konstantes ar pareizo ceļu/domēnu šai instalācijai. is_ssl() - pārbauda, vai savienojums ir HTTPS.

3. Pretty URL maršrutēšana

Bez šī soļa vienīgais veids, kā norādīt valodu, būtu neglīts ?lang=en parametrs. add_rewrite_rule() māca WordPress saprast, ka /en/kontakti/ ir tas pats, kas parastā "kontakti" lapa, tikai citā valodā.

php// Reģistrē URL noteikumus katrai valodai: /en/, /en/jebkas/, u.t.t.
add_action('init', function () {
    foreach (ml_get_languages() as $l) {
        $code = preg_quote($l['code'], '#');

        add_rewrite_rule('^' . $code . '/?$', 'index.php?ml_lang=' . $l['code'], 'top');
        add_rewrite_rule('^' . $code . '/(.+?)/?$', 'index.php?ml_lang=' . $l['code'] . '&ml_path=$matches[1]', 'top');
    }
});

// Māca WordPress atpazīt jaunos URL parametrus
add_filter('query_vars', function (array $vars): array {
    $vars[] = 'ml_lang';
    $vars[] = 'ml_path';
    return $vars;
});

// Pārvērš "ml_path" (piem. "kontakti") par īstu WordPress lapu
add_action('parse_request', function (WP $wp): void {
    if (empty($wp->query_vars['ml_lang'] ?? '')) return;

    $path = trim($wp->query_vars['ml_path'] ?? '', '/');
    unset($wp->query_vars['ml_path']);

    // Tukšs ceļš ("/en/") -> sākumlapa
    if ($path === '') {
        $front_id = (int) get_option('page_on_front');
        if ($front_id) $wp->query_vars['page_id'] = $front_id;
        return;
    }

    // Meklē lapu pēc slug, piem. "kontakti"
    $page = get_page_by_path($path);
    if ($page) {
        $wp->query_vars['page_id'] = $page->ID;
        return;
    }

    // Ja nekas neatrodas, ļauj WordPress mēģināt pašam (arī raksti/CPT)
    $wp->query_vars['pagename'] = $path;
});

// Ģenerē saiti uz pašreizējo lapu, bet citā valodā (izmanto pārslēdzējā)
function ml_url(string $target_lang): string {
    $home    = untrailingslashit(home_url());
    $default = ml_default_lang();
    $allowed = array_column(ml_get_languages(), 'code');

    if (!in_array($target_lang, $allowed, true)) return $home . '/';

    $path     = parse_url($_SERVER['REQUEST_URI'] ?? '/', PHP_URL_PATH) ?? '/';
    $relative = '/' . ltrim($path, '/');

    // Noņem esošo valodas prefiksu, ja tāds jau ir ceļā
    foreach ($allowed as $code) {
        $prefix = '/' . $code;
        if ($relative === $prefix || str_starts_with($relative, $prefix . '/')) {
            $relative = substr($relative, strlen($prefix));
            break;
        }
    }
    $relative = '/' . ltrim($relative ?: '/', '/');

    return $target_lang === $default
        ? $home . $relative
        : $home . '/' . $target_lang . $relative;
}

// Katru reizi, kad maini valodas vai atjauno tēmu, jāatsvaidzina URL noteikumi
add_action('after_switch_theme', 'flush_rewrite_rules');

preg_quote()

Attīra tekstu, lai to droši varētu ielikt regulārā izteiksmē (regex) - ja valodas kodā gadītos regex īpašzīme, tā netiktu interpretēta kā regex komanda.

Trīs āķi kopā

add_rewrite_rule() reģistrē jaunu URL "izskatu"; query_vars filtrs māca WordPress atpazīt jaunos parametrus tajā; parse_request darbība tad lemj, KURA īstā lapa jārāda. Visi trīs strādā kopā, katrs savā solī.

get_page_by_path()

Atrod WordPress lapu pēc tās slug/ceļa (piem., meklē lapu ar slug "kontakti"), atgriež pilnu lapas objektu vai null, ja neatrod.

str_starts_with()

PHP 8+ iebūvēta funkcija - pārbauda, vai teksts sākas ar norādīto apakštekstu. Šeit - vai ceļš sākas ar /en/.

Pēc šī koda pievienošanas dodies uz Iestatījumi → Pastāvīgās saites → Saglabāt - tas piespiedu kārtā atsvaidzina URL noteikumus. Bez šī soļa /en/... adreses rādīs 404.

4. Statiskā teksta tulkojumi

Šis nodrošina tulkojumus fiksētiem tekstiem, kas nav piesaistīti konkrētam ierakstam - pogas, izvēlnes vārdi, virsraksti. Tie tiek glabāti JSON failos, sagrupēti pa "grupām" (piem., menu.json, kontakti.json), lai katra lapa/sadaļa turētu savu nelielo tulkojumu failu.

php// Nolasa/raksta konkrētas grupas tulkojumu failu, piem. "menu" -> ml-lang/menu.json
function ml_dict_file(string $group): string {
    return ml_lang_dir() . '/' . sanitize_file_name($group) . '.json';
}

function ml_dict_read(string $group): array {
    $file = ml_dict_file($group);
    if (!file_exists($file)) return [];
    $data = json_decode(file_get_contents($file), true);
    return is_array($data) ? $data : [];
}

function ml_dict_write(string $group, array $data): bool {
    return (bool) file_put_contents(ml_dict_file($group), wp_json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE));
}

// ŠO IZSAUC VEIDNĒS: ml_t('menu', 'home') -> "Sākums" / "Home" / "Главная"
function ml_t(string $group, string $key, string $lang = ''): string {
    $lang = $lang ?: ml_current_lang();
    $data = ml_dict_read($group);

    return $data[$lang][$key]
        ?? $data[ml_default_lang()][$key]
        ?? '';
}

Lietošana veidnē (piem. header.php):

php<a href="/"><?= esc_html(ml_t('menu', 'home')) ?></a>

Atbilstošais menu.json fails izskatītos šādi (šo faila saturu vēlāk rediģēs caur admin tulkošanas redaktoru, skat. 5. soli, nevis ar roku):

json{
    "lv": { "home": "Sākums", "contact": "Kontakti" },
    "en": { "home": "Home",   "contact": "Contact" }
}

5. Lauku definīcijas & tulkošanas redaktors

4. solī tulkojumus rediģē tieši JSON failā ar roku - der dažiem laukiem (izvēlne), bet nesader visai lapai ar 30-50 tulkojamiem laukiem: viegli sajaukt atslēgas, nav pārskata, kas jau iztulkots. Risinājums - reģistrē lauku sarakstu katrai lapai/grupai, ko admin ekrāns pēc tam automātiski pārvērš organizētā formā ar nosauktiem laukiem, sadaļu virsrakstiem un valodu cilnēm.

Vispirms - reģistrs, kur glabājas visu lapu/grupu lauku definīcijas:

phpglobal $ml_page_field_registry;
$ml_page_field_registry = [];

// Reģistrē, kādi lauki pieder konkrētam "slug" (lapas vai grupas nosaukums)
function ml_register_page_fields(string $slug, string $label, array $fields): void {
    global $ml_page_field_registry;
    $ml_page_field_registry[$slug] = ['label' => $label, 'fields' => $fields];
}

function ml_get_page_fields(string $slug): array {
    global $ml_page_field_registry;
    return $ml_page_field_registry[$slug]['fields'] ?? [];
}

function ml_get_all_page_definitions(): array {
    global $ml_page_field_registry;
    return $ml_page_field_registry ?? [];
}

Tad katrai lapai/grupai - viens reģistrācijas izsaukums ar visiem tās laukiem:

phpml_register_page_fields('sakumlapa', 'Sākumlapa', [
    // "heading" tips NAV īsts lauks - tikai vizuāls dalītājs admin ekrānā,
    // pēc konvencijas ar "_" priekšā, lai nesajauktu ar īstiem laukiem
    '_hero' => ['label' => 'Hero sekcija', 'type' => 'heading'],
    'hero_virsraksts' => ['label' => 'Hero - Virsraksts', 'type' => 'text'],
    'hero_apraksts'   => ['label' => 'Hero - Apraksts',   'type' => 'textarea'],

    '_kursi' => ['label' => 'Kursu sekcija', 'type' => 'heading'],
    'kursi_virsraksts' => ['label' => 'Kursi - Virsraksts', 'type' => 'text'],
]);

Reģistrācijai izmantotais $slug ir tas pats, ko ml_t() (4. solis) izmanto kā grupas nosaukumu - reģistrs pats nesaglabā nekādus tulkojumus, tas tikai pasaka admin ekrānam, KĀDUS laukus rādīt un ar kādu ievades tipu (text, textarea vai heading).

Admin ekrāns, kas šo reģistru pārvērš rediģējamā formā ar valodu pārslēgšanu:

phpadd_action('admin_menu', function () {

});

    if (!current_user_can('manage_options')) return;

    $defs = ml_get_all_page_definitions();
    $active_slug = sanitize_key($_GET['section'] ?? array_key_first($defs));

        }
        ml_dict_write($active_slug, $existing);
        echo '<div class="notice notice-success"><p>Saglabāts!</p></div>';
    }

    $saved = ml_dict_read($active_slug);
    $lang  = sanitize_key($_GET['lang'] ?? ml_default_lang());

    <div class="wrap">
        <h1>🌍 Tulkojumi - <?= esc_html($defs[$active_slug]['label']) ?></h1>

               class="button <?= $l['code'] === $lang ? 'button-primary' : '' ?>">
                <?= esc_html($l['label']) ?>
            </a>
        <?php endforeach; ?>

            <?php wp_nonce_field('ml_save_' . $active_slug); ?>

            <?php foreach ($fields as $key => $def): ?>
                <?php if ($def['type'] === 'heading'): ?>
                    <h3><?= esc_html($def['label']) ?></h3>
                <?php elseif ($def['type'] === 'textarea'): ?>
                    <p><label><?= esc_html($def['label']) ?></label><br>
                    <textarea name="field[<?= esc_attr($key) ?>]" rows="3" style="width:100%;"><?= esc_textarea($saved[$lang][$key] ?? '') ?></textarea></p>
                <?php else: ?>
                    <p><label><?= esc_html($def['label']) ?></label><br>
                    <input type="text" name="field[<?= esc_attr($key) ?>]" style="width:100%;"
                           value="<?= esc_attr($saved[$lang][$key] ?? '') ?>"></p>
                <?php endif; ?>
            <?php endforeach; ?>

            <p><button type="submit" name="ml_save" class="button button-primary">Saglabāt</button></p>
        </form>

Un beidzot - ērtāks veidnes izsaukums, kas pats atrod pareizo tulkojumu failu pēc ieraksta ID (nav jāatceras/jāhardkodē "slug"):

php// Veidnēs izsauc ar ieraksta ID: ml_page_t(get_the_ID(), 'hero_virsraksts')
function ml_page_t(int $post_id, string $field, string $lang = ''): string {
    $post = get_post($post_id);
    $slug = $post ? $post->post_name : (string) $post_id; // izmanto lapas slug kā faila nosaukumu
    return ml_t($slug, $field, $lang); // atkārtoti izmanto 4. soļa ml_t()
}

Viss ir viena, konsekventa sistēma: ml_page_t() automātiski izmanto WordPress lapas slug (piem., "sakumlapa") kā tulkojumu faila nosaukumu, tāpēc reģistrētā lapa un tās tulkojumu fails vienmēr sakrīt bez papildu konfigurācijas. Patvaļīgas grupas (piem., "menu" no 4. soļa) tāpat turpina strādāt - reģistrē tās ar to pašu ml_register_page_fields('menu', ...), un arī tās parādīsies tajā pašā tulkošanas redaktorā.

6. Daudzvalodu pielāgotie lauki

Šī daļa atšķiras no 4. soļa - tā ir domāta laukiem, kas pieder konkrētam ierakstam (piem., raksta apakšvirsraksts), nevis fiksētiem UI tekstiem. Vērtība katrai valodai tiek saglabāta vienā post meta laukā kā JSON masīvs - piem. {"lv": "...", "en": "..."}.

php// ŠO IZSAUC VEIDNĒS: ml_field(get_the_ID(), 'ml_subtitle')
function ml_field(int $post_id, string $field, string $lang = ''): string {
    $raw = get_post_meta($post_id, $field, true);
    if (empty($raw)) return '';

    $data = is_array($raw) ? $raw : json_decode($raw, true);
    if (!is_array($data)) return '';

    $lang = $lang ?: ml_current_lang();

    return $data[$lang]
        ?? $data[ml_default_lang()]
        ?? reset($data)
        ?: '';
}

Šī poga jau strādā ar 6. solī izveidoto meta box piemēru (tur tai jau ir pareizie data-* atribūti) - ne pati funkcija, ne pogas HTML nekas papildus nav jāraksta.

Šis ir neoficiāls Google galapunkts (nav Google Cloud Translation API) - tas ir bez maksas un ideāls admin ērtībai, bet nav garantijas, ka Google to nemainīs nākotnē. Lieliem apjomiem vai kritiskiem projektiem ilgtermiņā apsver oficiālo, maksas Google Cloud Translation API.

Kontaktforma + Cloudflare Turnstile - pārskats

Šī ir pilna, darbojoša kontaktforma ar mūsdienīgu spam aizsardzību - bez kaitinošajām "izvēlies visus attēlus ar autobusiem" reCAPTCHA mīklām. Cloudflare Turnstile lielākajai daļai apmeklētāju ir pilnīgi neredzama (strādā fonā, analizējot pārlūka uzvedību) un ir bez maksas jebkuram apmeklējumu apjomam.

Sistēmai ir trīs slāņi aizsardzības pret spamu un trīs galvenās daļas:

🛡️ Turnstile

Cloudflare pārbauda, vai aiz formas stāv reāls cilvēks, nevis bots.

🍯 Honeypot

Slēpts lauks, ko cilvēks neredz un neaizpilda - boti gan bieži aizpilda visu.

🔐 WordPress nonce

Apliecina, ka pieprasījums nāk no tavas lapas, nevis no ārpuses.

📝 Forma (HTML)

Vārds, e-pasts, ziņojums + neredzams Turnstile logrīks.

⚡ Iesūtīšana (JS)

Nosūta datus bez lapas pārlādēšanas (AJAX/fetch).

📧 Apstrāde (PHP)

Pārbauda visu, tad nosūta divas e-pasta vēstules.

1. Cloudflare Turnstile uzstādīšana

Pirms koda raksti, jāiegūst divas atslēgas no Cloudflare - tas ir bez maksas un neprasa, lai tava vietne vispār būtu pieslēgta Cloudflare (Turnstile strādā neatkarīgi no tā, kur mitināta vietne).

✅ wp-config.php Ieteicams

    }

    // ── 3. Cloudflare Turnstile - pārbauda ar Cloudflare serveri ──
    $turnstile_token = $_POST['cf-turnstile-response'] ?? '';
    if (empty($turnstile_token)) {
        wp_send_json_error(['message' => 'Lūdzu, pabeidziet drošības pārbaudi.']);
    }

    $secret_key = defined('TURNSTILE_SECRET_KEY') ? TURNSTILE_SECRET_KEY : '';

    $verify = wp_remote_post('https://challenges.cloudflare.com/turnstile/v0/siteverify', [
        'body' => [
            'secret'   => $secret_key,
            'response' => $turnstile_token,
            'remoteip' => $_SERVER['HTTP_CF_CONNECTING_IP'] ?? $_SERVER['REMOTE_ADDR'],
        ],
    ]);

    $outcome = json_decode(wp_remote_retrieve_body($verify), true);

    if (empty($outcome['success'])) {
        wp_send_json_error(['message' => 'Drošības pārbaude neizdevās. Vai tu neesi bots?']);
    }

    // ── 4. Lauku validācija un attīrīšana ──
    if (empty($_POST['name']) || empty($_POST['email']) || empty($_POST['message'])) {
        wp_send_json_error(['message' => 'Lūdzu, aizpildi visus laukus.']);
    }

    $name    = sanitize_text_field(wp_unslash($_POST['name']));
    $email   = sanitize_email($_POST['email']);
    $message = sanitize_textarea_field($_POST['message']);

    if (!is_email($email)) {
        wp_send_json_error(['message' => 'Nederīga e-pasta adrese.']);
    }

    // ── 5. E-pastu sagatavošana un nosūtīšana ──
    $owner_email = defined('CONTACT_OWNER_EMAIL') ? CONTACT_OWNER_EMAIL : get_option('admin_email');
    $site_name   = get_bloginfo('name');

    // Vēstule vietnes īpašniekam
    $owner_body = "<p><strong>Vārds:</strong> {$name}</p>"
        . "<p><strong>E-pasts:</strong> {$email}</p>"
        . "<p><strong>Ziņojums:</strong><br>" . nl2br(esc_html($message)) . "</p>";

    $owner_sent = wp_mail(
        $owner_email,
        'Jauns ziņojums no vietnes ' . $site_name,
        $owner_body,
        ['Content-Type: text/html; charset=UTF-8', 'Reply-To: ' . $name . ' <' . $email . '>']
    );

    // Apstiprinājuma vēstule apmeklētājam
    $client_body = "<p>Sveiki, {$name}!</p>"
        . "<p>Esam saņēmuši Jūsu ziņojumu un atbildēsim pēc iespējas ātrāk.</p>"
        . "<p><em>" . nl2br(esc_html($message)) . "</em></p>"
        . "<p>Ar cieņu,<br>{$site_name}</p>";

    wp_mail(
        $email,
        'Paldies par ziņojumu - ' . $site_name,
        $client_body,
        ['Content-Type: text/html; charset=UTF-8', 'From: ' . $site_name . ' <' . $owner_email . '>']
    );

    if ($owner_sent) {
        wp_send_json_success(['message' => 'Ziņojums veiksmīgi nosūtīts!']);
    }

    wp_send_json_error(['message' => 'Sūtīšanas kļūda. Lūdzu, mēģiniet vēlreiz.']);
}

Kas ir API

Veids, kā divas programmas sazinās pēc noteiktiem noteikumiem. Stripe API ir HTTP adreses, uz kurām tava servera PHP kods sūta pieprasījumus (piem., "izveido maksājuma sesiju") un saņem atbildi JSON formātā.

API atslēgas (keys)

Secret key (sk_...) drīkst izmantot tikai serverī - ar to var izveidot maksājumus tavā vārdā. Publishable key (pk_...) ir droši publiskot pārlūkā, bet šai integrācijai (hostinga Checkout) tā pat nav vajadzīga.

Test vs Live režīms

Katram Stripe kontam ir divas atslēgu kopas: sk_test_... testēšanai (nauda nekad reāli nepāriet) un sk_live_... reāliem maksājumiem. Pārslēdz Stripe panelī augšējā labajā stūrī.

Checkout Session

Objekts, ko tavs serveris izveido pirms katra pirkuma - apraksta, ko pērk un par cik. Stripe atbildē atgriež URL, uz kuru pāradresē apmeklētāju.

Webhook

Stripe sūtīts HTTP pieprasījums uz tavu serveri, kad kaut kas notiek (piem., apmaksa izdevās). Nepieciešams, jo pāradresācija atpakaļ uz tavu vietni nav uzticama - apmeklētājs var aizvērt cilni pirms tam.

Webhook paraksts (signing secret)

Unikāla atslēga (whsec_...), ar kuru pārbauda, ka webhook pieprasījums tiešām nāk no Stripe, nevis no kāda, kas mēģina viltus nosūtīt "apmaksāts" ziņu tavam serverim.

Nekad nepiešķir piekļuvi/produktu tikai tāpēc, ka apmeklētājs atgriezās "success" lapā. Šo URL var apmeklēt jebkurš, arī bez maksāšanas. function stripe_create_checkout_session(WP_REST_Request $req): WP_REST_Response|WP_Error {
    $produkts = sanitize_key($req->get_param('produkts'));

    // Cenas nosaka SERVERĪ, nevis pieņem no pārlūka - pretējā gadījumā
    // jebkurš varētu nosūtīt savu cenu tieši ar izmainītu pieprasījumu
    $produkti = [
        'kurss-a' => ['nosaukums' => 'A kurss', 'cena_eur' => 49.00],
        'kurss-b' => ['nosaukums' => 'B kurss', 'cena_eur' => 99.00],
    ];

    if (!isset($produkti[$produkts])) {
        return new WP_Error('invalid_product', 'Nederīgs produkts', ['status' => 400]);
    }

    $izvele = $produkti[$produkts];

    $body = [
        'mode' => 'payment', // vienreizējs maksājums (nevis abonements)

        // Produkta apraksts - Stripe pats izveido "cenu" no šiem datiem
        'line_items[0][price_data][currency]'          => 'eur',
        'line_items[0][price_data][unit_amount]'       => $izvele['cena_eur'] * 100, // centos!
        'line_items[0][price_data][product_data][name]' => $izvele['nosaukums'],
        'line_items[0][quantity]'                       => 1,

        // Uz šejieni Stripe pāradresē pēc veiksmīgas/atceltas apmaksas.
        // {CHECKOUT_SESSION_ID} ir Stripe rezervēts vietturis - Stripe to
        // pats aizvieto ar reālo sesijas ID pirms pāradresācijas.
        'success_url' => home_url('/paldies/?session_id={CHECKOUT_SESSION_ID}'),
        'cancel_url'  => home_url('/cenas/'),

        // Pielāgoti dati, ko Stripe "atceras" un atdod atpakaļ webhook - šeit
        // liek visu, kas vajadzīgs, lai zinātu, KAM un KO piešķirt pēc apmaksas
        'metadata[produkts]' => $produkts,
        'metadata[user_id]'  => get_current_user_id(),
    ];

    $response = wp_remote_post('https://api.stripe.com/v1/checkout/sessions', [
        'headers' => [
            'Authorization' => 'Bearer ' . STRIPE_SECRET_KEY,
            'Content-Type'  => 'application/x-www-form-urlencoded',
        ],
        'body'    => $body,
        'timeout' => 15,
    ]);

    if (is_wp_error($response)) {
        return new WP_Error('stripe_error', $response->get_error_message(), ['status' => 500]);
    }

    $dati = json_decode(wp_remote_retrieve_body($response), true);

    if (empty($dati['url'])) {
        return new WP_Error('stripe_no_url', 'Stripe neatgrieza checkout adresi', ['status' => 500]);
    }

    return new WP_REST_Response(['checkout_url' => $dati['url']], 200);
}

Stripe API pieņem datus application/x-www-form-urlencoded formātā ar "kvadrātiekavu" sintaksi (line_items[0][price_data][currency]) - nevis JSON. Tas ir tāpēc, ka Stripe API ir vecāks par plašo JSON pieņemšanu, un šī sintakse joprojām ir oficiāli atbalstītais veids arī bez SDK.

function stripe_webhook_handler(WP_REST_Request $req): WP_REST_Response|WP_Error {
    $payload           = $req->get_body();
    $signature_header = $req->get_header('stripe-signature');

    if (!stripe_verify_signature($payload, $signature_header, STRIPE_WEBHOOK_SECRET)) {
        return new WP_Error('invalid_signature', 'Nepareizs paraksts', ['status' => 400]);
    }

    $event = json_decode($payload, true);

    if ($event['type'] === 'checkout.session.completed') {
        $session    = $event['data']['object'];
        $session_id = $session['id'] ?? '';

        // Aizsardzība pret dubultapstrādi - Stripe var nosūtīt to pašu
        // notikumu vairākas reizes (tīkla atkārtojumi, laika limiti u.c.)
        $apstrades_atzime = 'stripe_apstradats_' . md5($session_id);
        if (get_transient($apstrades_atzime)) {
            return new WP_REST_Response(['received' => true, 'duplicate' => true], 200);
        }
        set_transient($apstrades_atzime, true, MONTH_IN_SECONDS);

        // Reālo piekļuves piešķiršanu dara āķī - skat. 8. soli
        do_action('stripe_payment_completed', $session);
    }

    return new WP_REST_Response(['received' => true], 200);
}

function stripe_verify_signature(string $payload, ?string $signature_header, string $secret): bool {
    if (!$signature_header) {
        return false;
    }

    // Stripe galvene izskatās kā: "t=1712345678,v1=abc123...,v1=def456..."
    $dalas        = explode(',', $signature_header);
    $laika_zimogs = '';
    $paraksti     = [];

    foreach ($dalas as $dala) {
        [$atslega, $vertiba] = array_pad(explode('=', $dala, 2), 2, '');
        if ($atslega === 't')  $laika_zimogs = $vertiba;
        if ($atslega === 'v1') $paraksti[] = $vertiba;
    }

    if (!$laika_zimogs || empty($paraksti)) {
        return false;
    }

    // Noraida pārāk vecus pieprasījumus - aizsardzība pret "replay" uzbrukumu,
    // kur kāds noķer vecu, derīgu pieprasījumu un nosūta to atkārtoti vēlāk
    if (abs(time() - (int) $laika_zimogs) > 5 * MINUTE_IN_SECONDS) {
        return false;
    }

    $parakstamie_dati = $laika_zimogs . '.' . $payload;
    $sagaidamais      = hash_hmac('sha256', $parakstamie_dati, $secret);

    foreach ($paraksti as $paraksts) {
        if (hash_equals($sagaidamais, $paraksts)) {
            return true;
        }
    }

    return false;
}

array_pad($arr, 2, '')

Garantē, ka masīvam ir VISMAZ 2 elementi - ja explode('=', $dala, 2) atgrieztu tikai 1 (nav "=" zīmes), array_pad piepilda trūkstošo ar tukšu tekstu, lai nākamā rinda ([$atslega, $vertiba] = ...) nesalūztu.

hash_hmac('sha256', ...)

Aprēķina kriptogrāfisku "parakstu" no datiem + slepenās atslēgas - tikai tas, kam ir tā pati slepenā atslēga (šeit - gan Stripe, gan tavs serveris), var aprēķināt to pašu rezultātu. Tā pārbauda, ka pieprasījums tiešām nāk no Stripe.

hash_equals()

Salīdzina divus tekstus DROŠĀ veidā - parasts === salīdzinājums var (teorētiski) atklāt info uzbrucējam pēc tā, cik ātri salīdzinājums notiek. hash_equals() vienmēr aizņem vienādu laiku, neatkarīgi no rezultāta.

Šis piemērs pārbauda parakstu "manuāli" (bez papildu bibliotēkām), lai to varētu iekopēt bez Composer/vendor mapes uzstādīšanas. Ja projektā jau ir uzstādīts oficiālais stripe/stripe-php pakotne, var izmantot arī \Stripe\Webhook::constructEvent($payload, $signature_header, $secret), kas dara to pašu.

Autentifikācija & abonementi - pārskats

Šī integrācija aizstāj WordPress noklusējuma wp-login.php ar pilnībā pielāgotu, uz tavas vietnes stila balstītu pieteikšanās/reģistrācijas plūsmu, un pievieno laika-ierobežotu abonementa sistēmu - noderīgu jebkurai vietnei, kur piekļuve saturam (kursi, materiāli, rīki) jāpiešķir tikai uz noteiktu periodu pēc apmaksas.

🔑 Auth

Custom pieteikšanās, reģistrācija un paroles atjaunošana - ar rate limiting un Turnstile pret bruteforce/botiem.

⏳ Abonementi

Nevis īsta Stripe Subscriptions API, bet gudrāks paņēmiens - viena maksājuma "plāni" (1/6/12 mēn.), kas pagarina lietotāja piekļuves termiņu.

🚪 Piekļuves kontrole

📧 Atgādinājumi

Šī sistēma izmanto to pašu Stripe Checkout Session mehānismu, kas jau aprakstīts augstāk - tā nav īsta atkārtota rēķina (recurring billing) sistēma ar Stripe Subscriptions API. Tā vietā katrs "plāns" ir vienreizējs maksājums, kas servera pusē pagarina lietotāja piekļuves termiņu par attiecīgo mēnešu skaitu. Vienkāršāk uzstādīt un pietiek lielākajai daļai projektu, kur nav vajadzīga automātiska atkārtota norakstīšana.

    $user_id = $user_id ?: get_current_user_id();

// ja abonements vēl nebija beidzies (lietotājs atjauno PIRMS termiņa beigām)
function mem_activate_subscription(int $user_id, string $plan_key): void {
    if (!isset(MEM_PLANS[$plan_key])) return;
    $months = MEM_PLANS[$plan_key]['months'];

    $current_expires = (int) get_user_meta($user_id, 'mem_subscription_expires', true);
    $base    = ($current_expires > time()) ? $current_expires : time();

    update_user_meta($user_id, 'mem_subscription_plan',    $plan_key);
    update_user_meta($user_id, 'mem_subscription_expires', $expires);
    delete_user_meta($user_id, 'mem_reminder_sent_7d');      // skat. 8. sadaļu
    delete_user_meta($user_id, 'mem_reminder_sent_expired');
}

8. Atjaunošanas atgādinājumi (cron)

Automātisks e-pasts 7 dienas pirms abonementa beigām un tieši beigu brīdī - palaižas caur reālu servera cron (nevis WordPress pseido-cron), jo šai funkcijai jāizpildās katru dienu neatkarīgi no tā, vai kāds apmeklē vietni.

phpfunction mem_run_subscription_reminders(): array {
    $sent_7d = 0; $sent_expired = 0; $now = time();

    // Atrod VISUS lietotājus, kam ir abonementa beigu datuma lauks
    $users = get_users([
        'meta_key'     => 'mem_subscription_expires',
        'meta_compare' => 'EXISTS',
    ]);

    foreach ($users as $user) {
        $expires    = (int) get_user_meta($user->ID, 'mem_subscription_expires', true);
        $days_left  = (int) ceil(($expires - $now) / DAY_IN_SECONDS);

        if ($days_left === 7 && mem_send_reminder($user, $expires, '7d'))      $sent_7d++;
        if ($days_left === 0 && mem_send_reminder($user, $expires, 'expired')) $sent_expired++;
    }

    return ['parstrada' => count($users), 'nosutiti_7d' => $sent_7d, 'nosutiti_beigusies' => $sent_expired];

function mem_send_reminder(WP_User $user, int $expires, string $type): bool {

6. Konversiju veidi & notikumu kods

Kad notiek konversija, jānosūta signāls abām sistēmām - GA4/Google Ads ar gtag() un Meta ar fbq(). Bet ne visas konversijas ir vienādas: Lead tipa konversijām (forma, zvans, čats) parasti nav naudas summas, bet Sale tipa konversijām (pirkums) summa ir obligāta - bez tās Google Ads/Meta nevar rēķināt ROAS (Return on Ad Spend) un nevar optimizēt uz vērtīgākiem pirkumiem, tikai uz skaitu. Tāpēc katram tipam - sava pieeja.

Lead tipa konversijas (bez naudas summas)

Kontaktforma, telefona zvans, čats, rezervācija, lejupielāde - visas izmanto vienu vienkāršu palīgfunkciju:

js// js/konversijas.js - vienota funkcija Lead tipa notikumiem
function nosutitKonversiju(ga4Notikums, fbNotikums, dati = {}) {

    }
  }
  if (typeof fbq === 'function') {

  }
}

Sale tipa konversijas (pirkumi - vienmēr ar vērtību)

Pirkuma konversija atšķiras divos veidos: (1) jānosūta vērtība un valūta, ne tikai fakts, ka pirkums noticis; (2) jānodrošina, ka konversija tiek skaitīta tikai vienu reizi katram pasūtījumam - pretējā gadījumā klienta "paldies" lapas atsvaidzināšana radītu dublētu, mākslīgi paceltu ieņēmumu skaitli reklāmas atskaitēs.

js// js/pirkuma-konversija.js
function nosutitPirkumaKonversiju(pasutijumaId, summa, valuta = 'EUR') {
  // Dublēšanās aizsardzība - ja šis pasutijumaId jau nosūtīts šajā pārlūkā, otrreiz nesūta
  const atzime = 'pirkums_nosutits_' + pasutijumaId;
  if (sessionStorage.getItem(atzime)) return;

  if (typeof gtag === 'function') {
    // 'purchase' ir GA4 IEBŪVĒTS (nevis pašizdomāts) e-komercijas notikums -
    // GA4 to automātiski atpazīst un rāda ieņēmumu atskaitēs
    gtag('event', 'purchase', {
      transaction_id: pasutijumaId,
      value: summa,
      currency: valuta,
    });
    if (window.GOOGLE_ADS_CONVERSION) {
      gtag('event', 'conversion', {
        send_to: window.GOOGLE_ADS_CONVERSION,
        value: summa,
        currency: valuta,
        transaction_id: pasutijumaId,
      });
    }
  }
  if (typeof fbq === 'function') {
    fbq('track', 'Purchase', { value: summa, currency: valuta });
  }

10. UTM parametru saglabāšana

Meta/Google paneļi rāda konversiju skaitu, bet ne vienmēr ērti parāda, kurš tieši pieteikums nāca no kuras konkrētas reklāmas/kampaņas, ja tev CRM vai e-pastā jāstrādā ar konkrētiem pieteikumiem. Risinājums - nolasīt UTM parametrus no URL un ierakstīt tos slēptos formas laukos, lai tie parādās pašā pieteikuma e-pastā.

js// js/utm-capture.js - saglabā UTM parametrus un aizpilda slēptos CF7 laukus
(function () {
  const parametri = new URLSearchParams(window.location.search);
  const utmLauki = ['utm_source', 'utm_medium', 'utm_campaign', 'utm_content', 'utm_term'];

  utmLauki.forEach(lauks => {
    const vertiba = parametri.get(lauks);
    // saglabā sessionStorage, lai UTM "izdzīvotu" arī pāreju uz citu lapu vietnē
    if (vertiba) sessionStorage.setItem(lauks, vertiba);
  });

  document.addEventListener('DOMContentLoaded', () => {
    utmLauki.forEach(lauks => {
      const input = document.querySelector(`input[name="${lauks}"]`);
      const saglabats = sessionStorage.getItem(lauks);
      if (input && saglabats) input.value = saglabats;
    });
  });
})();

Contact Form 7 formā pievieno slēptos laukus (redzami tikai kodā, ne apmeklētājam):

text[hidden utm_source]
[hidden utm_medium]
[hidden utm_campaign]

Un CF7 "Mail" cilnē e-pasta veidnē pievieno pašus mainīgos, lai tie parādās katrā pieteikuma vēstulē:

textJauns pieteikums no: [utm_source] / [utm_campaign]

sessionStorage (nevis localStorage) apzināti - UTM vērtībām jāsaglabājas tikai vienas apmeklējuma sesijas laikā, nevis jāpaliek uz nedēļām, citādi vecs UTM var nepareizi "pielipt" nākamajam, nesaistītam apmeklējumam.

11. Servera puses izsekošana (CAPI)

Reklāmu bloķētāji, Safari ITP un iOS App Tracking Transparency var apslāpēt klienta puses Pixel/gtag notikumus - reāli var pazust 10-30% konversiju, kas patiešām notikušas. Risinājums: nosūtīt to pašu notikumu arī tieši no servera, kur bloķētāji neko nevar ietekmēt.

Meta Conversions API (CAPI) - vajadzīgs papildu tokens (Events Manager → Settings → Conversions API → Generate Access Token), ko glabā tāpat kā citas atslēgas:

php// wp-config.php papildus
define('META_CAPI_TOKEN', '...');
php// Izsauc kopā ar (vai vietā) klienta puses fbq() izsaukumu, piem., CF7 apstrādē
function nosutit_meta_serverside_konversiju(string $notikums, string $epasts): void {
    if (!defined('META_PIXEL_ID') || !defined('META_CAPI_TOKEN')) return;

    // Meta pieprasa lietotāja datus (e-pastu) HASHOTUS, nekad tekstā
    $hashots_epasts = hash('sha256', strtolower(trim($epasts)));

    $atbilde = wp_remote_post("https://graph.facebook.com/v19.0/" . META_PIXEL_ID . "/events", [
        'headers' => ['Content-Type' => 'application/json'],
        'body'    => wp_json_encode([
            'data' => [[
                'event_name'    => $notikums,
                'event_time'    => time(),
                'action_source' => 'website',
                'user_data'      => ['em' => [$hashots_epasts]],
            ]],
            'access_token' => META_CAPI_TOKEN,
        ]),
    ]);

    // Bez šī bloka neveiksmīgs pieprasījums pazustu klusi, bez jebkādas pēdas, kāpēc konversiju trūkst
    if (is_wp_error($atbilde)) {
        error_log('Meta CAPI kļūda: ' . $atbilde->get_error_message());
    }
}

Google Enhanced Conversions - vienkāršāk: nosūta hashojamos lietotāja datus caur gtag('set', ...), Google pats tos sahašo pirms nosūtīšanas:

js// Izsauc PIRMS konversijas notikuma, ar datiem no aizpildītās formas

Šī sadaļa ir papildinājums, ne aizstājējs - klienta puses izsekošana (5.-7. sadaļa) joprojām jāsaglabā. Servera puse tikai "aizpilda robus", ko klienta puse palaida garām. Sākot projektu, vispirms uztaisi un notestē visu klienta pusi (1.-10. sadaļa); servera pusi pievieno vēlāk, kad kampaņas budžets pieaug un katrs procents precizitātes sāk reāli ietekmēt rezultātu.

12. Testēšana (Pixel Helper, Tag Assistant, DebugView)

Pēc koda ievietošanas vienmēr pārbaudi visas trīs integrācijas, pirms sāc tērēt reklāmas budžetu - kļūda izsekošanā nozīmē, ka reklāmas sistēma neredz nevienu konversiju un automātiski optimizē uz sliktākiem rezultātiem.

Reklāmbloķētāji (uBlock, Brave, Safari) daļai apmeklētāju pilnībā bloķē Pixel/gtag kodu - tas ir normāli, ne kļūda tavā kodā. Tāpēc GA4/Meta skaitļi nekad nesakritīs 100% ar reālo apmeklētāju skaitu - tam arī domāta servera puses izsekošana (11. sadaļa).

text1. Uzstādi spraudni "Meta Pixel Helper" no Chrome Web Store

2. Ievadi savas mērķlapas adresi → "Start"
   (atvērsies tava lapa ar mazu logu "Connected")

4. Atgriezies Tag Assistant cilnē - kreisajā pusē redzamas
   visas notikušās darbības
