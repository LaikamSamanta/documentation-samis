Web pamati

API

"Sarunvaloda" starp divām programmām - noteikums, kā viena sistēma var pieprasīt datus vai darbību no citas.

CMS

Content Management System - programma satura (tekstu, attēlu, lapu) pārvaldīšanai bez koda rakstīšanas katru reizi. WordPress ir vispopulārākais.

Frontend

Viss, ko lietotājs redz un ar ko mijiedarbojas pārlūkā - HTML, CSS, JavaScript.

Backend

Serverī strādājošā daļa, ko lietotājs neredz tieši - apstrādā datus, pieslēdzas datubāzei, atgriež atbildes.

Fullstack

Izstrādātājs vai risinājums, kas aptver gan frontend, gan backend daļu.

Framework

Gatavs "skelets" ar noteikumiem un rīkiem, uz kura būvē lietotni, nevis raksti visu no nulles. Piemēri - React, Vue.

SPA

Single Page Application - lietotne, kas ielādē vienu HTML lapu un pēc tam pati apmaina saturu bez pilnas pārlādes.

Responsīvs dizains

Izkārtojums, kas pielāgojas dažāda izmēra ekrāniem - telefonam, planšetei, monitoram - ar vienu un to pašu kodu.

Tīkls & serveri

IP adrese

Unikāls skaitlisks "adreses" identifikators, pēc kura ierīces tīklā atrod cita citu.

Ports

Numurs, kas norāda, kuram konkrētam pakalpojumam uz servera adresēts pieprasījums (80 = HTTP, 443 = HTTPS, 22 = SSH).

DNS

Sistēma, kas domēna vārdu (piem., example.com) pārvērš IP adresē, ko dators saprot.

Domēns

Cilvēkam lasāms vietnes vārds (piem., example.com), kas reģistrēts un norāda uz serveri caur DNS.

Serveris

Dators, kas pastāvīgi strādā un atbild uz pieprasījumiem no interneta - tur "dzīvo" vietne vai lietotne.

Hosting

Pakalpojums, kas nodrošina serveri, uz kura izvietot vietni - tas var būt gan dalīts serveris, gan mākoņa risinājums.

CDN

Content Delivery Network - servera tīkls pasaulē, kas nogādā vietnes saturu no ģeogrāfiski tuvākā punkta lietotājam, tāpēc ātrāk.

SSL / TLS

Šifrēšanas protokols, kas padara savienojumu starp pārlūku un serveri drošu (HTTPS).

Izstrāde & darba plūsma

Git

Versiju kontroles sistēma - seko līdzi koda izmaiņām laika gaitā, ļauj atgriezties pie vecām versijām un strādāt vairākiem cilvēkiem vienlaikus.

Repozitorijs

Mape ar visu projekta kodu, ko Git izseko - vietējā kopija un/vai attālinātā (piem., GitHub).

Commit

"Saglabāts uzņēmums" no koda izmaiņām - ar ziņu, kas paskaidro, kas un kāpēc mainījās.

Branch (zars)

Paralēla koda versija, kurā droši var izstrādāt jaunu funkciju, neskarot galveno (main/master) kodu.

Pull Request

Pieprasījums apvienot viena zara izmaiņas galvenajā kodā - parasti ar koda pārskatīšanu pirms apstiprināšanas.

.gitignore

Fails, kas pasaka Git, kurus failus/mapes NEKAD nesekot (piem., node_modules, .env ar paroles).

SSH

Šifrēts protokols attālinātai pieslēgšanai serverim caur termināli - komandu izpildei bez fiziskas piekļuves.

CI/CD

Automātiska koda testēšana (Continuous Integration) un izvietošana (Continuous Deployment) pēc katras izmaiņas, bez manuālas iejaukšanās.

Terminālis / CLI

Teksta interfeiss komandu ievadīšanai tieši datoram vai serverim, bez peles un logiem.

Dati & backend

Datubāze

Strukturēta vieta, kur glabājas visi lietotnes dati - lietotāji, ieraksti, pasūtījumi.

SQL

Valoda datu pieprasīšanai un mainīšanai datubāzē (SELECT, INSERT, UPDATE, DELETE).

JOIN

SQL komanda, kas savieno datus no divām vai vairākām tabulām vienā rezultātā.

Primārā / ārējā atslēga

Unikāls ieraksta identifikators tabulā (primārā) un saite uz citas tabulas ierakstu (ārējā).

Indekss

Datubāzes iekšējā "satura rādītāja" struktūra, kas ļauj meklēt datus daudz ātrāk, bez pilnas tabulas caurskatīšanas.

Endpoint

Konkrēta API adrese, kurai var nosūtīt pieprasījumu (piem., /api/lietotaji).

JSON

Vienkāršs teksta formāts datu apmaiņai starp programmām - atslēga/vērtība pāri, ko lasa gan cilvēks, gan programma.

Cache (kešs)

Pagaidu saglabāta rezultāta kopija, lai nākamreiz to pašu neaprēķinātu/neielādētu no jauna - ātrāk, bet var rādīt novecojušus datus.

Vides mainīgie (.env)

Slepeni vai konfigurācijas dati (paroles, atslēgas), kas glabājas ārpus koda, atsevišķā .env failā, kas nekad netiek iekļauts Git.

Konteineri (Docker)

Ietvars, kas iesaiņo lietotni ar visu tās vidi (PHP versiju, atkarībām), lai tā strādātu identiski jebkurā datorā.

Drošība

Šifrēšana vs Hash

Šifrēšanu var atšifrēt atpakaļ ar atslēgu, hash - nevar, tas ir vienvirziena process (izmanto parolēm).

Autentifikācija vs Autorizācija

Autentifikācija pārbauda, KAS tu esi (pieslēgšanās), autorizācija - KO tev drīkst darīt (tiesības).

JWT / Token

Parakstīts "caurlaides" gabaliņš, ko lietotājs sūta ar katru pieprasījumu, lai pierādītu, ka ir pieslēdzies, bez servera puses sesijas.

XSS

Cross-Site Scripting - uzbrukums, kad ļaunprātīgs JavaScript tiek iemontēts lapā caur neattīrītu lietotāja ievadi.

SQL injekcija

Uzbrukums, kad ļaunprātīgs SQL tiek iemontēts pieprasījumā caur neattīrītu ievadi, lai piekļūtu vai bojātu datubāzi.

CSRF

Uzbrukums, kad lietotājs bez ziņas tiek piespiests veikt darbību citā vietnē, kurā jau ir pieslēdzies.

Rate limiting

Ierobežojums, cik pieprasījumus lietotājs/IP drīkst sūtīt noteiktā laikā - aizsardzība pret pārslodzi un brutālā spēka uzbrukumiem.

OWASP Top 10

Autoritatīvs, regulāri atjaunots saraksts ar 10 visbiežāk sastopamajām web lietotņu drošības problēmām.

WordPress & CMS

Spraudnis (Plugin)

Papildinājums, kas pievieno WordPress jaunas funkcijas, neskarot pamata kodu.

Tēma (Theme)

Nosaka vietnes izskatu un izkārtojumu - var nomainīt bez satura zaudēšanas.

Hook

"Āķis" kodā, kurā var iekabināt savu funkciju - izpildās noteiktā brīdī (action) vai maina datus pirms izvades (filter).

Shortcode

Īsa iekava kvadrātiekavās (piem., [galerija]), ko redaktorā ievieto, un WordPress to aizvieto ar dinamisku saturu.

Widžets

Neliels, pārvietojams satura bloks (piem., sānjoslā vai kājenē) - kalendārs, jaunākie raksti, meklēšana.

WP-CLI

Komandrindas rīks WordPress pārvaldībai bez admin paneļa - instalēšana, atjaunināšana, datubāzes darbības.

Integrācijas & maksājumi

Webhook

HTTP pieprasījums, ko cits serviss (piem., Stripe) nosūta uz tavu serveri, kad kaut kas notiek - pretējs virziens nekā parasts API izsaukums, kur pieprasījumu sāc tu pats.

Webhook paraksts (signing secret)

Unikāla atslēga, ar kuru pārbauda, ka ienākošais webhook tiešām nāk no īstā pakalpojuma, nevis no uzbrucēja, kas mēģina viltot ziņu (piem., "apmaksa izdevās").

Stripe

Populārs maksājumu apstrādes pakalpojums - apstrādā karšu datus un ar tiem saistītās drošības prasības, lai pašam tos nevajadzētu glabāt.

Checkout Session

Objekts, ko izveido pirms katra pirkuma - apraksta, ko pērk un par cik. Pakalpojums (piem., Stripe) atbildē atgriež URL, uz kuru pāradresēt pircēju.

API atslēga (API key)

Slepena virkne, ar kuru serviss identificē un autorizē tavu pieprasījumu - nekad nedrīkst nonākt frontend kodā vai Git repozitorijā.

OAuth

Standarts, kas ļauj lietotājam piešķirt lietotnei ierobežotu piekļuvi savam kontam citā servisā (piem., "Pieslēgties ar Google"), bez savas paroles nodošanas.

Idempotences atslēga

Unikāls identifikators, ko pievieno pieprasījumam, lai to atkārtoti nosūtot (piem., tīkla kļūdas dēļ), darbība (piem., maksājums) netiktu izpildīta divreiz.

REST

Visizplatītākais API veidošanas princips - resursi (lietotāji, raksti) tiek adresēti ar URL, darbības ar HTTP metodēm (GET, POST, PUT, DELETE).

GraphQL

Alternatīva REST - klients pats apraksta, tieši kādus laukus vēlas, un API atgriež tikai tos, nevis fiksētu, iepriekš noteiktu atbildes formu.

WebSocket

Pastāvīgi atvērts, divvirzienu savienojums starp klientu un serveri - noder reāllaika funkcijām (čats, paziņojumi), kur serveris pats var sūtīt datus bez pieprasījuma.

Paginācija (Pagination)

Liela rezultātu saraksta sadalīšana lapās/daļās, lai API neatgrieztu visus ierakstus uzreiz vienā smagā atbildē.

Cron job

Uzdevums, kas serverī izpildās automātiski pēc grafika (piem., katru nakti), bez cilvēka iejaukšanās katru reizi.
