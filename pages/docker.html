Docker

Konteinerizēta vietējā izstrāde - visa projekta vide (PHP versija, MySQL, spraudņi) aprakstīta failos, kas nonāk Git repozitorijā, tāpēc jebkurš komandas loceklis to var palaist identiski, neatkarīgi no sava datora.

Kas ir Docker?

Docker palaiž lietotni konteinerī - izolētā vidē, kurā jau iepakots viss nepieciešamais (PHP, MySQL, to versijas un konfigurācija), neatkarīgi no tā, kas instalēts pašā datorā. Rezultāts - "pie manis strādā" problēma pazūd, jo visi izstrādātāji (un ražošanas serveris) palaiž identisku vidi.

Konteiners vs virtuālā mašīna

Virtuālā mašīna emulē VISU datoru (savu operētājsistēmas kodolu) - smaga un lēna. Konteiners koplieto resursdatora kodolu un izolē tikai procesu/failus - startējas sekundēs, nevis minūtēs.

Image vs konteiners

Image ir "recepte" - nemainīgs veidnes fails ar visu nepieciešamo. Konteiners ir šīs receptes IZPILDĪTA kopija - vienu image var palaist vairākos konteineros vienlaicīgi.

Kāpēc WordPress/PHP izstrādei

Vietējā vidē var precīzi atkārtot servera PHP versiju, paplašinājumus un MySQL versiju - novērš pārsteigumus, kad kods strādā lokāli, bet salūzt uz reālā servera.

Instalācija

Windows/Mac lietotājiem vienkāršākais ceļš ir Docker Desktop - grafiska lietotne, kas iekļauj gan Docker Engine, gan docker-compose. Linux serveriem instalē Docker Engine tieši:

bash# Ubuntu/Debian - oficiālais uzstādīšanas skripts
curl -fsSL https://get.docker.com | sh

# Pārbauda, vai instalācija izdevās
docker --version
docker compose version

Jaunākās Docker versijās komanda ir docker compose (ar atstarpi, iebūvēta Docker daļā) - vecākos ceļvežos vēl sastopama docker-compose (ar defisi, atsevišķa programma). Funkcionāli tās ir vienādas, bet jaunajos projektos der izmantot docker compose.

Pamatjēdzieni

Dockerfile

Teksta fails ar soli-pa-solim instrukcijām, kā uzbūvēt savu image - sākot no bāzes image (piem., "php:8.2-apache") un pievienojot savu kodu/konfigurāciju.

docker-compose.yml

Apraksta VAIRĀKUS konteinerus, kas strādā kopā (piem., PHP + MySQL + phpMyAdmin), ar vienu komandu tos visus palaižot un savienojot vienā tīklā.

Volume

Mape, kas "izdzīvo" arī pēc konteinera dzēšanas - bez tā visi datubāzes dati pazustu ikreiz, kad konteineru pārstartē.

Port mapping

Savieno konteinera iekšējo portu (piem., 80) ar datora reālo portu (piem., 8080) - bez tā konteiners no ārpuses nav sasniedzams pārlūkā.

Dockerfile

Piemērs - pielāgots PHP + Apache image ar vajadzīgajiem PHP paplašinājumiem WordPress vajadzībām:

text# Dockerfile
FROM php:8.2-apache

# PHP paplašinājumi, kas WordPress nepieciešami MySQL savienojumam un attēlu apstrādei
RUN docker-php-ext-install mysqli pdo pdo_mysql
RUN apt-get update && apt-get install -y libpng-dev && docker-php-ext-install gd

# Ieslēdz Apache "mod_rewrite" - nepieciešams WordPress pastāvīgajām saitēm (permalinks)
RUN a2enmod rewrite

# Kopē pašreizējās mapes saturu konteinera web-servera mapē
COPY . /var/www/html/

Uzbūvē savu image no šī faila ar docker build -t mana-vietne . (punkts beigās nozīmē "izmanto Dockerfile pašreizējā mapē") - bet praksē WordPress projektiem parasti pietiek ar gatavu oficiālo wordpress image (skat. zemāk), un pašrocīgs Dockerfile vajadzīgs tikai tad, ja nepieciešami PAPILDU PHP paplašinājumi vai sistēmas pakotnes.

docker-compose.yml

Vairāku konteineru apraksts vienā failā - katra atslēga (wordpress, db) ir viens serviss (konteiners), kas startējas un tīklojas automātiski.

text# docker-compose.yml
services:
  wordpress:
    image: wordpress:latest
    ports:
      - "8080:80"          # dators:8080 -> konteiners:80
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_NAME: wordpress
      WORDPRESS_DB_USER: wp_lietotajs
      WORDPRESS_DB_PASSWORD: wp_parole
    volumes:
      - ./wp-content:/var/www/html/wp-content   # tēmas/spraudņi paliek pieejami arī ārpus konteinera
    depends_on:
      - db

  db:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wp_lietotajs
      MYSQL_PASSWORD: wp_parole
      MYSQL_ROOT_PASSWORD: sakne_parole
    volumes:
      - db_dati:/var/lib/mysql   # datubāzes dati saglabājas arī pēc konteinera dzēšanas

volumes:
  db_dati:

Servisi savā starpā sazinās pēc servisa nosaukuma (šeit - db), nevis localhost - tāpēc WORDPRESS_DB_HOST vērtība ir db, nevis 127.0.0.1. Docker Compose automātiski izveido iekšēju tīklu, kurā katrs serviss redz pārējos pēc nosaukuma.

WordPress + MySQL piemērs

Ar iepriekšējās sadaļas docker-compose.yml failu, pilna vietējā WordPress vide startējas ar VIENU komandu:

bash# Startē abus konteinerus fonā (-d = detached)
docker compose up -d

# Vietne pieejama: http://localhost:8080
# WordPress instalācijas vednis parādīsies automātiski pirmajā reizē

# Aptur un noņem konteinerus (bet volumes/dati paliek)
docker compose down

Lai pievienotu phpMyAdmin (grafisks datubāzes pārvaldnieks) tai pašai videi, pievieno vēl vienu servisu docker-compose.yml failā:

text  phpmyadmin:
    image: phpmyadmin:latest
    ports:
      - "8081:80"
    environment:
      PMA_HOST: db
    depends_on:
      - db

Pēc docker compose up -d phpMyAdmin būs pieejams http://localhost:8081, jau savienots ar db servisu.

Volumes (dati)

Konteineri pēc noklusējuma ir bez atmiņas - dzēšot konteineru, dzēšas arī viss tā iekšienē izveidotais (ieskaitot datubāzes datus). Volume ir mape, ko Docker pārvalda ĀRPUS konteinera dzīves cikla, tāpēc dati pārdzīvo docker compose down.

Named volume

db_dati:/var/lib/mysql - Docker pats pārvalda glabāšanas vietu. Vienkāršākais variants datubāzēm, kur precīzs faila ceļš datorā nav svarīgs.

Bind mount

./wp-content:/var/www/html/wp-content - piesaista KONKRĒTU mapi no paša datora. Der kodam (tēmas, spraudņi), ko rediģē tieši ar ierasto teksta redaktoru.

docker compose down -v (ar -v) papildus noņem arī VOLUMES, tātad izdzēš visus datus neatgriezeniski - parastais docker compose down (bez -v) volumes saglabā.

Noderīgas komandas

bash# Rāda visus PALAISTOS konteinerus
docker ps

# Rāda VISUS konteinerus, arī apturētos
docker ps -a

# Skatās konkrēta servisa žurnālu (log) tiešraidē
docker compose logs -f wordpress

# Atver komandrindu KONTEINERA iekšienē (der failu/datubāzes pārbaudei)
docker compose exec wordpress bash
docker compose exec db mysql -u root -p

# Pārstartē vienu konkrētu servisu, nepārstartējot pārējos
docker compose restart wordpress

# Noņem NEIZMANTOTUS images/konteinerus/tīklus - atbrīvo diska vietu
docker system prune

docker system prune pēc noklusējuma neaiztiek volumes (dati ir droši), bet gan noņem NEIZMANTOTUS images/konteinerus/build kešatmiņu - der pievienot -a tikai tad, ja tiešām jāatbrīvo maksimāli daudz vietas, jo tas izdzēsīs arī images, kas varētu vēl noderēt.
