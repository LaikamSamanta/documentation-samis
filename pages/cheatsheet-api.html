API Cheatsheet

HTTP metodes & statusi

GET

Iegūst datus, neko nemainot serverī - idempotenta, drīkst atkārtot bez riska.

GET /users/5

POST

Izveido jaunu resursu - NAV idempotenta, atkārtota izsaukšana rada divus ierakstus.

POST /users

PUT

Aizvieto resursu pilnībā - visi lauki, kas nav norādīti, tiek dzēsti/nomainīti uz noklusējumu.

PUT /users/5

PATCH

Maina tikai norādītos laukus, pārējie paliek nemainīti.

PATCH /users/5

DELETE

Izdzēš resursu - idempotenta, otrā izsaukšana parasti atgriež 404, ne kļūdu.

DELETE /users/5

Statusa kodi - pirmais cipars pasaka grupu, pat nezinot precīzo kodu.

KodsNozīme
200OK - izdevās
201Created - jauns resurss izveidots
204No Content - izdevās, nav ko atgriezt
400Bad Request - nepareizi formēts pieprasījums
401Unauthorized - trūkst/nepareiza autentifikācija
403Forbidden - autentificēts, bet nav tiesību
404Not Found - resurss neeksistē
422Unprocessable Entity - neiztur validāciju
429Too Many Requests - pārsniegts limits
500Internal Server Error - kļūda serverī
503Service Unavailable - serveris īslaicīgi nepieejams

JSON

JS: objekts → JSON

Pārvērš JS objektu par JSON tekstu, piem., nosūtīšanai API pieprasījumā.

JSON.stringify(objekts);

JS: JSON → objekts

Pārvērš saņemtu JSON tekstu atpakaļ par lietojamu JS objektu.

JSON.parse(teksts);

PHP: masīvs → JSON

Pārvērš PHP masīvu/objektu par JSON tekstu.

json_encode($arr);

PHP: JSON → masīvs

true otrais parametrs - atgriež asociatīvu masīvu, nevis stdClass objektu.

json_decode($json, true);

Content-Type galvene

Obligāta, sūtot JSON pieprasījuma ķermenī - bez tās serveris nezina, kā to parsēt.

Content-Type: application/json

REST principi

Resursi = lietvārdi

URL apraksta LIETU, ne darbību - darbību jau pasaka HTTP metode.

GET /users  (ne /getUsers)

Ligzdošana

Attēlo piederību starp resursiem tieši URL struktūrā.

GET /users/5/orders

Versionēšana

Ļauj vēlāk mainīt API, nesalaužot vecos klientus.

/api/v1/users

Filtrēšana ar query parametriem

Papildu izvēles nosacījumi ejai kā ?atslēga=vērtība, ne kā daļa no ceļa.

GET /users?status=active

API veidi

REST

Visizplatītākais - HTTP + JSON, resursu-orientēts. Noklusējuma izvēle.

GraphQL

Klients pats izvēlas, kādus laukus grib, vienā endpointā.

WebSocket

Pastāvīgs, divvirzienu savienojums reāllaika datiem.

Webhooks

"Apgrieztais API" - serveris pats zvana tavam endpointam.

Autentifikācija

API atslēga

Viena statiska virkne, sūta header vai query parametrā.

X-API-Key: abc123

Basic Auth

Lietotājvārds:parole, base64 kodēts.

Authorization: Basic dXNlcjpwYXNz

Bearer Token

Token, kas iegūts pēc pieteikšanās, sūta katrā pieprasījumā.

Authorization: Bearer eyJhbGc...

OAuth 2.0

Lietotājs piekrīt trešajai pusei piekļūt datiem bez paroles nodošanas.

"Pierakstīties ar Google"

JWT

Pašpietiekams token ar iekodētu info, pārbaudāms bez datubāzes.

Drošība

CORS atļauja

Serveris skaidri atļauj konkrētu domēnu - bez tās pārlūks bloķē pieprasījumu.

Access-Control-Allow-Origin: https://mavietne.lv

HTTPS obligāti

Jebkuram API ar autentifikāciju - bez tā dati ceļo atklātā tekstā.

Rate limit atbilde

429 statuss + Retry-After pasaka, cik ilgi jāgaida līdz nākamajam mēģinājumam.

429 Too Many Requests
Retry-After: 30

Idempotency-Key

Novērš dubultu izpildi, atkārtojot POST pēc tīkla kļūdas (maksājumiem u.c.).

Idempotency-Key: unikals-id

Nekad frontendā

Slepenas atslēgas glabā serverī (piem., wp-config.php), nekad JS kodā, kas nonāk pārlūkā.

JS fetch

GET ar async/await

Pamata pieprasījums, ar obligātu atbilde.ok pārbaudi (fetch neizmet kļūdu 404/500 gadījumā).

const r = await fetch(url);
if (!r.ok) throw new Error(r.status);
const dati = await r.json();

POST ar JSON ķermeni

Method, headers un body jānorāda visi trīs kopā.

await fetch(url, {
  method: 'POST',
  headers: {'Content-Type':'application/json'},
  body: JSON.stringify(dati),
});

try/catch

Noķer tīkla kļūdas (nav interneta) UN pašrocīgi izmestās kļūdas no atbilde.ok pārbaudes.

try { ... } catch (e) { console.error(e); }

AbortController (timeout)

fetch() pēc noklusējuma negaida bezgalīgi - bez šī karājas, ja serveris klusē.

const c = new AbortController();
setTimeout(() => c.abort(), 5000);
fetch(url, { signal: c.signal });

PHP / WordPress

wp_remote_get()

WordPress veids sūtīt GET pieprasījumu - ievēro proxy un filtrus.

$r = wp_remote_get($url);
$dati = json_decode(wp_remote_retrieve_body($r), true);

wp_remote_post()

Tas pats POST pieprasījumam, ar body/headers masīvu.

wp_remote_post($url, ['body' => json_encode($d)]);

is_wp_error()

Obligāta pārbaude - tīkla kļūdas gadījumā wp_remote_* atgriež WP_Error, ne izņēmumu.

if (is_wp_error($r)) { error_log($r->get_error_message()); }

Tīrs cURL

Alternatīva bez WordPress, jebkuram PHP projektam.

curl_setopt_array($ch, [
  CURLOPT_URL => $url,
  CURLOPT_RETURNTRANSFER => true,
]);

Sava API izveide

register_rest_route()

Reģistrē jaunu WordPress REST API endpointu ar tā ceļu un metodi.

register_rest_route('ns/v1', '/lietotajs/(?P<id>\d+)', [
  'methods' => 'GET',
  'callback' => 'mana_funkcija',
  'permission_callback' => '__return_true',
]);

WP_REST_Response

Atgriež datus ar skaidru statusa kodu WordPress REST endpointā.

return new WP_REST_Response($dati, 200);

permission_callback

Obligāts - nosaka, kam drīkst piekļūt. __return_true = publiski visiem.

$wpdb->prepare()

Obligāti jebkuram datubāzes vaicājumam ar no ārpuses nākošu vērtību - pasargā no SQL injection.

$wpdb->prepare("SELECT * FROM t WHERE id = %d", $id);

OpenAPI/Swagger

Standartizēts YAML/JSON API apraksts, no kura automātiski uzģenerē interaktīvu dokumentāciju.

Testēšana

cURL ar galveni

Ātrākais veids izmēģināt endpointu terminālī.

curl -H "Authorization: Bearer TOK" url

cURL POST

-v rāda pilnu apmaiņu - noderīgi atkļūdošanai.

curl -v -X POST url -d '{"a":1}'

Postman

Bezmaksas GUI rīks pieprasījumu sūtīšanai bez koda rakstīšanas.

DevTools Network

F12 → Network → filtrs "Fetch/XHR" - redz tavas vietnes reālos API izsaukumus.

Paginācija & kļūdas

page/per_page

Lietotājam draudzīgākais paginācijas veids - lapu numuri.

GET /users?page=3&per_page=10

Cursor-based

Ātrākais veids lieliem/mainīgiem datiem, piem., barotnēm.

GET /posts?after=eyJpZCI6NTB9

Konsekventa kļūdas struktūra

Vienmēr viens formāts visiem endpointiem - klients var uz to paļauties.

{"kluda":{"kods":"...","zinojums":"..."}}
